# Русский форк OpenChamber

Это личный форк [openchamber/openchamber](https://github.com/openchamber/openchamber)
с русской локализацией интерфейса и документации. Всё остальное — оригинальный проект,
и он продолжает развиваться независимо.

**Русский здесь — язык по умолчанию.** Свежая установка запускается на русском;
английский и остальные одиннадцать языков остаются в переключателе. Языки, которые
форк не распознал, тоже откатываются на русский.

Апстрим русскую локализацию не принял (см. «Статус pull request'ов» внизу), поэтому
форк — самостоятельный проект, а не заготовка для мержа: релизы собираются и
публикуются здесь же, из ветки `ru`.

Этот файл описывает, как устроен форк и как его сопровождать.

на английском.

## Ветки

| Ветка | Что в ней | Назначение |
|---|---|---|
| `main` | чистое зеркало `upstream/main` | синхронизация с оригиналом, ничего своего |
| `ru` | **всё вместе**: локализация интерфейса и доков + русский `README` + этот файл + релизный workflow | рабочая ветка, из неё собираются релизы |
| `feat/ru-locale` | только локализация интерфейса | историческое: ветка закрытого PR №1 |
| `feat/ru-docs` | только локализация сайта документации | историческое: ветка закрытого PR №2 |

`main` никогда не трогаем своими коммитами, иначе `git merge --ff-only` перестанет
работать и синхронизация превратится в ручное разрешение конфликтов.

`feat/*` больше не нужны — апстрим оба PR закрыл. Удалять их не обязательно, но
держать в «пригодном для мержа» виде смысла нет: всё живое живёт в `ru`.

### Remote

```
origin    https://github.com/perejaslav/openchamber.git      # ваш форк
upstream  https://github.com/openchamber/openchamber.git     # оригинал
```

## Обновление до новой версии апстрима

```bash
cd openchamber

# 1. Подтянуть оригинал
git fetch upstream

# 2. Обновить зеркало (только fast-forward)
git checkout main
git merge --ff-only upstream/main
git push origin main

# 3. Перенести рабочую ветку на новую основу
git checkout ru
git merge upstream/main
# разрешить конфликты (см. ниже)
git push origin ru
```

`feat/*` в этой схеме больше не участвуют: апстрим оба PR закрыл, поддерживать их
в пригодном для мержа виде незачем.

### Конфликты в документации

При обновлении `ru` конфликты возможны только в трёх файлах: `README.md`,
`docs/CUSTOM_THEMES.md`, `SECURITY.md` — потому что они переведены **на месте**.
Правильная сторона — ваша:

```bash
git checkout ru
git merge upstream/main
# при конфликте в перечисленных файлах:
git checkout --ours README.md docs/CUSTOM_THEMES.md SECURITY.md
git add README.md docs/CUSTOM_THEMES.md SECURITY.md
git commit
```

Если апстрим **добавил новый раздел** в README, `--ours` его потеряет. Поэтому после
такого мержа стоит заглянуть в диф:

```bash
git diff upstream/main -- README.md | head -50
```

и дописать перевод нового раздела руками.

### Конфликты в локали

В `packages/ui/src/lib/i18n/` конфликты будут почти наверняка: апстрим добавляет новые
ключи. Типичный случай — новый ключ есть в `en.ts`, но отсутствует в `ru.ts`, и тест
паритета падает с сообщением вида:

```
all locales stay in key parity with english
```

Что делать: найти новые ключи и доперевести.

```bash
# ключи, которые есть в en, но отсутствуют в ru
cd packages/ui/src/lib/i18n/messages
comm -23 <(grep -oE "^  '?[^']+'?:" en.ts | sed "s/[: ]//g;s/'//g" | sort -u) \
         <(grep -oE "^  '?[^']+'?:" ru.ts | sed "s/[: ]//g;s/'//g" | sort -u)
```

Правила перевода и глоссарий лежат в репозитории:

- `translation/UI-BRIEF.md` — интерфейс приложения;
- `translation/DOCS-BRIEF.md` — сайт документации.

Глоссарий общий и обязательный: интерфейс и документация должны использовать одни и те
же слова. Перед тем как допереводить что-то новое, прочитайте нужный бриф — там же
описано, что переводить нельзя.

## Релизы

Готовые русские сборки собираются в CI (`.github/workflows/fork-release.yml`) и
публикуются как GitHub Release прямо в этом форке. Скачать установщик можно со
страницы [Releases](https://github.com/perejaslav/openchamber/releases) — собирать
вручную ничего не нужно.

### Как выпустить релиз

Релиз запускается **тегом вида `ru-v*`**:

```bash
git checkout ru
git merge upstream/main                  # если подтянули новый апстрим
bun test packages/ui/src/lib/i18n        # локаль должна остаться целой
git tag ru-v2.0.3.1
git push origin ru-v2.0.3.1
```

Тег `ru-v*`, а **не** `v*`, выбран намеренно: на `v*` висят апстримные `release.yml` и
`vscode-extension.yml`, рассчитанные на платные раннеры Blacksmith и на секреты подписи
Apple — на форке они не отработают и просто зависнут в очереди.

Workflow делает три вещи: прогоняет тесты локали, собирает на раннерах GitHub
Windows x64 (NSIS-установщик) и Linux x64 (AppImage), и прикрепляет файлы к релизу.
macOS не собирается: без подписи Apple приложение там не запускается.

### Про версию

Версия приложения берётся из `packages/electron/package.json` и **остаётся равной
версии апстрима** (сейчас `2.0.3`); тег — только ярлык релиза. Это не случайность.
Встроенный автоапдейтер сравнивает версии по semver, и сборка с версией `2.0.3-ru.1`
считалась бы *старее* `2.0.3` (префикс-релиз младше релиза), то есть обновления бы
никогда не предлагались.

Практическое следствие: когда выйдет апстрим `2.0.4`, нужно собрать форк на новой
базе — версия станет `2.0.4`, и установленные русские сборки увидят обновление.

### Автообновление

`build.publish` в `packages/electron/package.json` указывает на **этот** форк
(`perejaslav/openchamber`), а не на апстрим. Иначе установленная русская сборка однажды
предложила бы «обновление» из официального релиза и молча вернулась бы к английскому
интерфейсу.

### Установщик не подписан

Сертификата подписи кода у форка нет, поэтому Windows покажет SmartScreen
(«Подробнее» → «Выполнить в любом случае»). `scripts/package.mjs` сам отключает подпись,
если сертификат не задан, — это ожидаемое поведение, а не сбой сборки.

### Workflow на форке

Апстримные workflow (19 штук) на форке **отключены**: они завязаны на Blacksmith и на
секреты апстрима и только копили бы зависшие прогоны. Отключение хранится в настройках
репозитория, а не в файлах, поэтому после синхронизации с апстримом стоит проверить,
не появились ли новые включённые workflow:

```bash
gh workflow list -R perejaslav/openchamber --all
```

Свой workflow (`Fork release (RU)`) отключать нельзя — именно он собирает релизы.

## Сборка и установка русской версии вручную

Основной путь — релизы выше. Этот раздел нужен, если хочется собрать ветку `ru` самому
или наложить её на уже установленное приложение.

Приложение для десктопа берёт интерфейс из папки `resources/web-dist` установленной
копии. Чтобы увидеть русскую версию, её нужно собрать из этой ветки и подменить.

```bash
cd openchamber
bun install
bun run --cwd packages/electron build:web-assets     # ~1.5 минуты
```

Готовый интерфейс окажется в `packages/electron/resources/web-dist`.

Дальше — скрипт `scripts/ru/install-desktop-locale.ps1`:

```powershell
# Закрыть OpenChamber, затем:
& ".\scripts\ru\install-desktop-locale.ps1" status    # что сейчас установлено
& ".\scripts\ru\install-desktop-locale.ps1" apply     # подменить (делает бэкап)
& ".\scripts\ru\install-desktop-locale.ps1" revert    # вернуть оригинал
```

Скрипт **не удаляет файлы** — только перезаписывает, потому что окружение блокирует
массовое удаление. Бэкап оригинала лежит рядом с `web-dist` в `web-dist.orig`.

### Про обновления приложения

Обновление OpenChamber **затрёт русский язык**: установщик заменит `web-dist` официальной
сборкой. Само по себе это не случится — в приложении `autoDownload = false` и
`autoInstallOnAppQuit = false`, обновление ставится только вручную.

После каждого обновления:

```bash
git checkout ru
git merge upstream/main      # разрешить конфликты как описано выше
bun install
bun run --cwd packages/electron build:web-assets
```

и снова `apply`. Скрипт сам скажет `STATE: STALE`, если маркер патча пережил обновление,
а интерфейс уже откатился.

## Статус pull request'ов в апстрим

Оба PR **закрыты без мержа**. Причина — в
[pull/4123](https://github.com/openchamber/openchamber/pull/4123), дословно от мейнтейнера:

> We're not accepting Russian localization for OpenChamber. This is an intentional
> maintainership decision due to Russia's ongoing war against Ukraine. We don't want
> to ship or maintain Russian UI support. Closing.

| | Ссылка | Состояние |
|---|---|---|
| Обсуждение | [discussions/4122](https://github.com/openchamber/openchamber/discussions/4122) | открыто |
| Локализация интерфейса | [pull/4123](https://github.com/openchamber/openchamber/pull/4123) | **closed** |
| Локализация документации | [pull/4124](https://github.com/openchamber/openchamber/pull/4124) | **closed** |

Это решение мейнтейнера, а не претензия к качеству работы: локаль была полной
(6628 ключей, паритет с `en`, зелёные тесты, проверка в живом UI). Предлагать её
в апстрим повторно смысла нет.

### Что делать дальше

Форк теперь самостоятельный — его нужно просто поддерживать:

1. По мере выхода новых версий апстрима подтягивать их и пересобирать релиз —
   см. «Обновление до новой версии апстрима» и «Релизы».
2. Если апстрим добавил новые ключи локализации — допереводить их,
   см. «Конфликты в локали».
3. Репозиторные доки для апстрима не переводить: `AGENTS.md` прямо требует английский
   для материалов проекта. Переводы живут только здесь.
