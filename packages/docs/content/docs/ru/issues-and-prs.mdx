# Issues и PR

Доска **Issues and PRs** — это отдельная страница со списком issues и пул-реквестов проекта на GitHub, GitLab, Gitea, Forgejo или Gerrit (на GitLab это merge requests, на Gerrit — changes, а issues там нет), либо ваших issues в Linear. Выберите элемент — рядом со списком откроется его предпросмотр. Просмотр другого проекта здесь не меняет проект, в котором работает остальное приложение.

## Открыть доску

- Нажмите значок пул-реквеста в заголовке боковой панели, рядом с запланированными задачами и архивом.
- Выберите **Issues and PRs** в палитре команд.
- Нажмите <kbd>⌘K</kbd>, затем <kbd>B</kbd> (в Windows и Linux — <kbd>Ctrl+K</kbd>, затем <kbd>B</kbd>). Те же клавиши закрывают её.

На телефоне коснитесь кнопки пул-реквеста в нижней части меню сессий. В расширении VS Code доски нет.

Доска открывается на том проекте, вкладке и команде, на которых вы её оставили.

## Поиск элементов

Всё помещается в одну строку панели инструментов. Слева — выбор проекта со значками проектов и поиском. Рядом переключаются **Issues**, **Pull requests** и **Linear**. Issues и пул-реквесты приходят с собственного хоста проекта: GitHub, GitLab, Gitea, Forgejo, Gerrit или хоста, который добавляет [расширение](/extensions/#an-extension-as-a-git-host). Вкладка **Linear** появляется только после подключения Linear. Проект, которого нет ни на одном из этих хостов, показывает только эту вкладку или сообщает, что перечислять нечего. Remote с псевдонимом хоста из `~/.ssh/config`, например `github.com-work`, не считается ни одним из них.

Второй список рядом с выбором проекта определяет, что показывает доска, и появляется, когда в папке больше одного репозитория. В папке, которая сама не является Git-репозиторием, но содержит репозитории, первым и по умолчанию стоит **All repositories**: доска перечисляет issues и пул-реквесты всех репозиториев GitHub в папке вместе, и каждая строка называет свой репозиторий. Поиск работает по всем репозиториям, включая вставленную ссылку или номер. Заметка над списком говорит, сколько репозиториев не включено, например репозиторий на GitLab, Gitea, Forgejo или Gerrit либо тот, который не может прочитать ни один подключённый аккаунт, а его меню показывает, какие и почему. Выберите один репозиторий, чтобы перечислять только его.

Папка, которая сама является Git-репозиторием, перечисляется как есть и остаётся вариантом по умолчанию, а рядом можно выбрать её подмодули и вложенные рабочие копии. **All repositories** там не предлагается, иначе элементы корня перечислялись бы рядом с самими собой. Доска запоминает выбор для каждого проекта, и он не зависит от репозитория, выбранного в представлении Git.

Комментарии, метки, ревьюеры и слияние работают с репозиторием, которому принадлежит элемент. **New session** всё равно начинается в папке проекта. **Changes** и **Walkthrough** открывают пул-реквест в его собственном репозитории и оставляют репозиторий, выбранный в представлении Git, как был. Начать работу в рабочем дереве для таких элементов пока нельзя. Ссылка на issue или пул-реквест одного из этих репозиториев открывается в Tracker и читается через тот репозиторий. На телефоне она открывается на доске, которая тоже читает её через собственный репозиторий, оставляя список как был. В расширении VS Code доски нет, поэтому там ничего из этого не меняется.

В **Linear** выбор проекта становится выбором команды: выберите **All teams** или одну команду. Для проекта, где есть только **Linear**, выбор проекта остаётся рядом с выбором команды, так что можно переключиться на другой проект. Если вы подключили больше одной рабочей области Linear, переключайте рабочие области в том же меню. О подключении Linear — в разделе [Интеграции](/integrations/).

Поиск принимает заголовок, номер или вставленную ссылку. Меню фильтров остаётся открытым, пока вы выбираете, так что фильтры можно комбинировать. На GitHub поле также принимает собственные квалификаторы (`is:closed`, `label:bug`, `author:@me`), и они важнее меню.

Для GitHub, GitLab, Gitea, Forgejo и Gerrit:

- Статус: **Open**, **Closed**, **All**, а для пул-реквестов — **Merged**
- Люди: **Anyone**, **Assigned to me**, **Created by me**, а для пул-реквестов — **Review requested**

Меню **Filter** также перечисляет метки репозитория с поиском и отметкой у каждой метки; каждая отметка сразу сужает список. Фильтр запоминается для каждого репозитория и вкладки.

Для Linear:

- Статус: **Open**, **All**, **Backlog**, **To Do**, **In Progress**, **In Review**, **Done**, **Canceled**, **Duplicate**
- Люди: **Anyone**, **Assigned to me**, **Created by me**
- Приоритет: **All priorities**, **Urgent**, **High**, **Medium**, **Low**, **No priority**

## Чтение элемента

Предпросмотр показывает описание, метки и комментарии. У issue в Linear нажмите на плашку статуса, чтобы перевести его в другое состояние команды.

В строке **Labels** есть кнопка с карандашом, которая открывает список меток репозитория с поиском. Отмечайте и снимайте их. Изменение сохраняется, когда вы закрываете список, поэтому несколько кликов считаются одним изменением. У открытого пул-реквеста (merge request на GitLab) также есть строка **Reviewers**, работающая так же, — с людьми, которые могут делать ревью в этом репозитории. На GitHub автор пул-реквеста не предлагается. У issues Linear обеих строк нет.

Карандаш рядом с заголовком редактирует заголовок и описание вместе. <kbd>⌘</kbd>+<kbd>Enter</kbd> сохраняет (<kbd>Ctrl</kbd>+<kbd>Enter</kbd> в Windows и Linux), <kbd>Esc</kbd> отменяет, и затем предпросмотр читает то, что сохранил хост. У элемента, открытого по ссылке, карандаша нет, как и у хоста, который не умеет менять текст.

В хронологии issues и пул-реквесты перечисляют элементы, которые их упоминают, — с тем, кто упомянул, когда, и чипом (`owner/repo#42` для разных репозиториев), который открывает элемент. У обсуждения такого списка нет: GitHub не предоставляет для него хронологию. GitHub, GitLab, Gitea и Forgejo показывают эти строки, как и хост, добавленный расширением, которое их присылает; Gerrit не показывает ничего.

## Комментарии и ревью

Под активностью issue или пул-реквеста есть поле комментария. **Comment** публикует ваш текст на хосте репозитория, как и <kbd>⌘</kbd>+<kbd>Enter</kbd> (<kbd>Ctrl</kbd>+<kbd>Enter</kbd> в Windows и Linux). Текст остаётся в поле, пока его не опубликуют, поэтому неудачная публикация ничего не теряет. Переход к другому элементу очищает поле. У issues Linear его нет.

У открытого пул-реквеста (merge request на GitLab) также есть **Approve** и **Request changes**, и текст в поле идёт вместе с ревью. **Request changes** требует текста о том, что изменить. Ревью относится к коммитам, которые показывает предпросмотр: если кто-то запушил изменения после, оно отклоняется, а предпросмотр обновляется, чтобы вы посмотрели снова. На GitLab **Request changes** работает, когда вы ревьюер merge request, а текст ревью публикуется отдельным комментарием. Если не удаётся только этот комментарий, ревью всё равно засчитывается, а ваш текст остаётся в поле.

У change на Gerrit есть строка для каждой метки проекта, например Code-Review и Verified, с оценками, которые вам разрешено ставить; выберите их и нажмите **Vote**. Ваш текст идёт вместе с голосами как сообщение. Голоса ставятся к последнему патчсету, поэтому их не предлагают, пока вы читаете более ранний.

У написанного вами комментария рядом с кнопкой отправки есть меню: **Edit** переписывает его на месте, а **Delete** удаляет после вопроса. Ответ редактируется и удаляется так же. Оба действия выполняются на хосте, поэтому комментарий меняется для всех.

## Начало работы

Действия находятся внизу предпросмотра.

- **New session** открывает новую сессию в проекте с элементом, прикреплённым к полю сообщения. Первое сообщение вы пишете сами.
- **Start in worktree…** у issue или **Check out in worktree…** у пул-реквеста открывает диалог New Worktree с уже выбранным элементом. Пул-реквест переключается на свою ветку. См. [Сессии в рабочих деревьях](/worktrees/).

У issue в Linear **Start in** показывает проект, в котором начнётся сессия. Это проект, сопоставленный команде issue в карточке Linear в разделе [Интеграции](/integrations/). Без сопоставления команды это проект по умолчанию, а без него — проект, который доска показывала последним. Здесь можно выбрать другой проект для этого issue.

## Пул-реквесты

Предпросмотр пул-реквеста также показывает его ветку, размер (добавленные и удалённые строки и изменённые файлы), проверки и ревью. Лента **Activity** располагает комментарии, вердикты ревью и новейшие коммиты в порядке их появления. Коммиты, пришедшие подряд, группируются, так что видно, на какие коммиты ответило ревью.

Рядом с размером — две кнопки. **Changes** открывает дифф пул-реквеста в боковой панели, а **Walkthrough** открывает его [разбор](/walkthrough/). Если приложение находится в другом проекте, оно сначала переключается на проект PR. На телефоне **Changes** открывает PR во вкладке **Git** выдвижной панели рабочей области; **Walkthrough** доступен только в десктопе и вебе.

Внизу **Merge** спрашивает перед слиянием и использует ваш обычный способ слияния. Плашка состояния рядом с заголовком открывает меню, которое переключает запрос на изменение (change request) между **Convert to draft** и **Ready for review**, где хост это поддерживает, и закрывает или снова открывает его.

На Gerrit предпросмотр также показывает топик change и то, является ли он приватным или незавершённым. Когда у change несколько патчсетов, список рядом с **Changes** выбирает, из какого берутся файлы и дифф; начинается он с последнего. **Merge** здесь — **Submit**, и он недоступен, пока не выполнены требования к отправке change, а невыполненные названы рядом. **Close** и **Reopen** здесь — **Abandon change** и **Restore change**.

То же меню закрывает открытый issue или пул-реквест (**Close issue**, **Close pull request**, **Close merge request** на GitLab) и открывает закрытый (**Reopen issue**, **Reopen pull request**, **Reopen merge request**). Оба действия не спрашивают подтверждения, поскольку их можно отменить. У слитого пул-реквеста такого пункта нет. На GitHub issue закрывается как выполненный.
