# Issues и PR

Доска **Issues и PR** — отдельная страница со списком issues и pull request проекта из GitHub или GitLab (на GitLab это merge request) или ваших issues из Linear. Выберите элемент — его предпросмотр откроется рядом со списком. Если здесь вы смотрите другой проект, остальное приложение остаётся на своём.

## Открыть доску

- Нажмите значок pull request в заголовке боковой панели, рядом с запланированными задачами и архивом.
- Выберите **Issues и PR** в палитре команд.
- Нажмите <kbd>⌘K</kbd>, а затем <kbd>B</kbd> (<kbd>Ctrl+K</kbd>, а затем <kbd>B</kbd> в Windows и Linux). Те же клавиши закрывают её.

На телефоне коснитесь кнопки pull request внизу меню сессий. В расширении VS Code доски нет.

Доска открывается на том проекте, вкладке и команде, где вы её оставили.

## Поиск элементов

Всё умещается в одной строке панели инструментов. Слева — выбор проекта со значками проектов и поиском. Рядом переключатель **Issues**, **Pull requests** и **Linear**. Issues и pull request берутся из хостинга самого проекта — GitHub или GitLab. Если у проекта нет такого remote, виден только **Linear**.

Если папка проекта сама не git-репозиторий, но внутри неё есть репозитории, второй выбор рядом с выбором проекта определяет, что показывает доска. Первый и по умолчанию — **Все репозитории**: доска перечисляет issues и pull request всех GitHub-репозиториев папки вместе, и каждая строка называет свой репозиторий. Поиск работает по всем ним, включая вставленную ссылку или номер. Примечание над списком говорит, сколько репозиториев не включено, например один на GitLab или один, который не может прочитать ни один подключённый аккаунт; его меню показывает, какие и почему. Выберите один репозиторий, чтобы видеть только его. Доска запоминает выбор для каждого проекта, и он не связан с репозиторием, выбранным в представлении Git.

Комментарии, метки, рецензенты и слияние работают с репозиторием, к которому относится элемент. **Новая сессия** по-прежнему запускается в папке проекта. **Изменения** и **Walkthrough** открывают pull request в его собственном репозитории и не меняют репозиторий, выбранный в представлении Git. Начать работу в worktree для таких элементов пока нельзя. Ссылка на issue или pull request одного из этих репозиториев открывается в Tracker и читается через этот репозиторий. На телефоне она открывается на доске, которая переключается на **Все репозитории**, чтобы найти его. В расширении VS Code доски нет, поэтому там ничего из этого не меняется.

В **Linear** выбор проекта становится выбором команды: выберите **Все команды** или одну команду. Если подключено несколько рабочих пространств Linear, переключайтесь между ними в том же меню. Как подключить Linear, описано в разделе [Интеграции](/ru/integrations/).

Поиск принимает название, номер или вставленную ссылку. Меню фильтров не закрывается, пока вы выбираете, так что фильтры можно сочетать.

Для GitHub и GitLab:

- Статус: **Open**, **Closed**, **All**, а для pull request ещё **Merged**
- Люди: **Anyone**, **Assigned to me**, **Created by me**, а для pull request ещё **Review requested**

Для Linear:

- Статус: **Open**, **All**, **Backlog**, **To Do**, **In Progress**, **In Review**, **Done**, **Canceled**, **Duplicate**
- Люди: **Anyone**, **Assigned to me**, **Created by me**
- Приоритет: **All priorities**, **Urgent**, **High**, **Medium**, **Low**, **No priority**

## Просмотр элемента

В предпросмотре видны описание, метки и комментарии. В issue из Linear нажмите на значок статуса, чтобы перевести его в другое состояние команды.

В строке **Метки** есть кнопка с карандашом: она открывает список меток репозитория с поиском. Отмечайте нужные и снимайте отметки. Изменение сохраняется, когда вы закрываете список, поэтому несколько нажатий считаются одним изменением. У открытого pull request (на GitLab — merge request) есть ещё строка **Рецензенты**, которая работает так же: в ней люди, которые могут делать ревью в репозитории. На GitHub автора pull request в списке нет. У issues из Linear нет ни той, ни другой строки.

## Комментарии и ревью

Под активностью issue или pull request есть поле комментария. **Comment** публикует ваш текст на GitHub или GitLab, так же как <kbd>⌘</kbd>+<kbd>Enter</kbd> (<kbd>Ctrl</kbd>+<kbd>Enter</kbd> в Windows и Linux). Текст остаётся в поле, пока его не опубликуют, так что при неудаче ничего не теряется. При переходе к другому элементу поле очищается. У issues из Linear его нет.

У открытого pull request (на GitLab — merge request) есть ещё **Approve** и **Request changes**, и текст из поля уходит вместе с ревью. Для **Request changes** нужен текст: напишите, что изменить. Ревью относится к коммитам, которые показывает предпросмотр: если с тех пор кто-то сделал push, ревью отклоняется, а предпросмотр обновляется, чтобы вы могли посмотреть ещё раз. На GitLab **Request changes** работает, когда вы рецензент этого merge request, а текст ревью публикуется отдельным комментарием. Если не удалось опубликовать только этот комментарий, ревью всё равно засчитано, а ваш текст остаётся в поле.

## Начало работы

Действия расположены внизу предпросмотра.

- **Новая сессия** открывает новую сессию в проекте с элементом, прикреплённым к полю сообщения. Первое сообщение вы пишете сами.
- **Открыть в worktree…** открывает диалог «Новый worktree» с уже выбранным элементом: для issue это запуск работы, для pull request — получение его ветки. См. [Сессии в worktree](/ru/worktrees/).

Для issue из Linear **Начать в** показывает проект, в котором начнётся сессия. Это проект, сопоставленный с командой issue в карточке Linear в разделе [Интеграции](/ru/integrations/). Если команда не сопоставлена, это проект по умолчанию, а если нет и его — проект, который доска показывала последним. Там же можно выбрать другой проект для этой issue.

## Pull requests

Предпросмотр pull request также показывает его ветку, размер (добавленные и удалённые строки и изменённые файлы), проверки и ревью. Лента **Activity** расставляет комментарии, вердикты ревью и самые новые коммиты в том порядке, как всё происходило. Коммиты, шедшие подряд, сгруппированы, так что видно, на какие коммиты ответило ревью.

Рядом с размером две кнопки. **Изменения** открывают дифф pull request в боковой панели, а **Walkthrough** открывает его [обзорный тур](/ru/walkthrough/). Если приложение сейчас на другом проекте, сначала оно переключится на проект этого PR. На телефоне **Изменения** открывают PR на вкладке **Git** рабочей панели; **Walkthrough** есть только на десктопе и в вебе.

Внизу **Слить** сначала спрашивает, а потом сливает вашим обычным способом. Для черновика есть ещё **Готов к ревью**.

У открытого issue или pull request внизу есть **Закрыть issue** или **Закрыть pull request** (на GitLab — **Закрыть merge request**), а у закрытого — **Открыть issue заново** или **Открыть pull request заново** (на GitLab — **Открыть merge request заново**). Подтверждение не нужно, потому что действие можно отменить. Слитый pull request нельзя ни закрыть, ни открыть заново. На GitHub issue закрывается как выполненная.
