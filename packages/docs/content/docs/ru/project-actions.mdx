# Действия проекта

Действие проекта — это shell-команда, которую вы сохраняете один раз и запускаете кликом: ваш dev-сервер, сборка, прогон тестов. У каждого проекта свой список. Настройте их в **Settings → Projects → Project Actions**.

## Как добавить действие

1. Откройте **Settings → Projects** и найдите раздел **Project Actions**.
2. Добавьте действие, дайте ему имя, выберите иконку и введите команду для запуска.
3. Сохраните.

Вы можете ограничить действие определёнными операционными системами, если команда имеет смысл только на одной из них.

## Как запустить действие

В разделе **Project** панели Work Status — карточки справа от чата — есть строка действий. Нажмите на действие, чтобы запустить его, и нажмите ещё раз, чтобы остановить. Шеврон рядом выбирает другое действие, а его пункт **Add new action** открывает **Settings → Projects**. Строка показывает действие, которое вы выбрали последним, а пока какое-то действие работает, строка показывает именно его. Когда у запуска есть адрес предпросмотра, кнопка с глобусом рядом со строкой открывает его.

С клавиатуры нажмите **⌘⌥R** на macOS или **Ctrl+Alt+R** на Windows и Linux, чтобы открыть диалог действий проекта. Он перечисляет действия текущего проекта с их состоянием. Стрелки перемещают выделение, Enter запускает простаивающее действие или останавливает работающее, а Esc закрывает диалог. Поле поиска фильтрует список, а пункт **Configure actions** в конце открывает настройки действий проекта. Диалог открывается с уже выделенным действием из Work Status, поэтому сочетание клавиш, а затем Enter повторяют ваш последний запуск. Чтобы изменить сочетание, найдите **Open project actions** в **Settings → Shortcuts**.

В палитре команд, которую открывает ⌘P или Ctrl+P, введите «run» или название действия, чтобы найти пункты вроде **Run: dev** и **Stop: dev**. Пункт **Project actions** в палитре открывает диалог.

Каждое действие выполняется в терминале в папке сессии: это рабочее дерево, если сессия находится в нём, или основная рабочая копия для действий, настроенных на запуск там. Терминал открывается, чтобы вы видели вывод. Действия проекта доступны в десктопном приложении и в веб-приложении. В VS Code, на телефонах и в сессиях раздела Chats их нет.

## Как автоматически открыть dev-сервер

Включите **auto-open URL** для действия, которое запускает сервер. OpenChamber следит за выводом, ищет локальный адрес и предлагает открыть его — см. [Предпросмотр и dev-серверы](/preview/). В десктопном приложении его также можно направить через перенаправление порта по SSH.

Если у сервера фиксированный адрес, укажите его в поле URL действия. `{worktree}` и `{branch}` подставляют рабочую копию, в которой выполняется действие, поэтому одно действие работает в каждом рабочем дереве. С [portless](https://github.com/vercel-labs/portless) `https://{worktree}.myapp.localhost` открывает `https://auth.myapp.localhost` в рабочем дереве на ветке `feature/auth` и `https://myapp.localhost` в основной рабочей копии. Возможно, поле вам вообще не понадобится: когда portless печатает свой адрес, OpenChamber открывает именно его, а не порт за ним. В десктопном приложении, подключённом к удалённому экземпляру, он открывает вместо этого порт, поскольку через туннель к удалённой машине проходят только loopback-порты.

## Как разрешить агенту запускать действия

Агент тоже может запускать действия проекта — например, поднять ваш dev-сервер сохранённой командой. Включите **Project actions** в **Settings → General → OpenChamber Tools**; по умолчанию выключено. Сессии в проекте, где есть действия, получают информацию о них.

Агент перечисляет действия для этого компьютера, запускает одно в той же папке, где запустили бы его вы, читает вывод и затем останавливает его. Его запуск виден в меню действий с пометкой **by agent**, чтобы вы не запустили вторую копию. Если действие уже запущено вами, агент использует ваш запуск и не может его остановить. Запуски агента останавливаются, когда его сессия архивируется или OpenChamber закрывается. Сессии в изолированном пространстве этот инструмент не получают.
