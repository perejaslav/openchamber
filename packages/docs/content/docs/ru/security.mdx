# Безопасность

OpenChamber даёт доступ к вашей машине и вашему коду, поэтому закройте его, прежде чем до него сможет добраться кто-то кроме вас. Эта страница рассказывает о пароле UI, passkeys и о том, что важно знать, прежде чем открывать OpenChamber в сеть.

## Задайте пароль UI

Запустите OpenChamber с паролем, и браузерный UI будет его запрашивать:

```bash
openchamber --ui-password be-creative-here
```

Также можно задать его переменной окружения `OPENCHAMBER_UI_PASSWORD` вместо того, чтобы указывать в командной строке. После входа OpenChamber какое-то время помнит устройство, чтобы не спрашивать каждый раз.

Всегда задавайте пароль, если до экземпляра может добраться кто-то ещё — особенно через [туннель](/ru/tunnels/) или публичный интернет.

## Passkeys

Когда пароль задан, вы можете добавить passkeys (Face ID, Touch ID, аппаратный ключ безопасности) для более быстрого входа. Добавьте их в **Настройки → OpenChamber → Ключи доступа**.

Passkeys привязаны к текущему паролю. Если вы измените или удалите пароль, сохранённые passkeys будут очищены, и вам придётся добавить их снова.

## Токены устройств

Устройства, связанные через [Подключение устройства](/ru/connect-devices/), аутентифицируются своими собственными токенами для каждого устройства, а не паролем UI. Ссылки для связывания одноразовые и истекают, если не были использованы; каждое связанное устройство показано в **Настройки → Удалённые экземпляры → Подключиться к этому серверу**, где вы можете отозвать любое из них в любой момент. Подключения вне дома идут через [Private Relay](/ru/private-relay/), который защищён сквозным шифрованием и не может прочитать ваш трафик.

## Прежде чем открывать его

- По умолчанию OpenChamber слушает только вашу собственную машину (`127.0.0.1`). Чтобы слушать шире, нужно намеренно это изменить, и сначала стоит задать пароль.
- Для своих устройств предпочитайте [связывание](/ru/connect-devices/) с [Private Relay](/ru/private-relay/) — наружу не открывается вообще ничего.
- Если вам нужен публичный URL, предпочитайте [туннель](/ru/tunnels/) или приватную сеть (например, VPN), а не открытие порта в интернет.
- Если вы ставите OpenChamber за свой HTTPS-сервер, см. [Reverse Proxy](/ru/reverse-proxy/).

## Корпоративный режим

Если вашей команде можно отправлять содержимое переписки только тем провайдерам моделей, которых вы настроили в OpenCode, включите корпоративный режим. Есть два способа, и достаточно любого.

### Файл политики на машине

Этот способ подходит для ноутбуков, которыми вы управляете. Положите файл с именем `policy.json` в папку, куда может писать только администратор:

| Система | Путь |
|---|---|
| macOS | `/Library/Application Support/OpenChamber/policy.json` |
| Windows | `C:\ProgramData\OpenChamber\policy.json` |
| Linux | `/etc/openchamber/policy.json` |

Путь не зависит от того, как установлен OpenChamber. Десктопное приложение, веб-сервер из npm, CLI и расширение VS Code читают один и тот же файл. Его можно развернуть через систему управления устройствами (Jamf, Intune и подобные). Для сервера в Docker смонтируйте файл по пути для Linux.

```json
{
  "enterpriseMode": true,
  "organization": "Acme",
  "relayUrl": "wss://relay.acme.com/ws",
  "allowNetworkAccess": false,
  "allowedExtensions": ["https://github.com/acme/"],
  "jev": {
    "url": "https://llm.acme.com/v1/systemone",
    "model": "acme-classifier",
    "apiKey": "..."
  }
}
```

Обязателен только `enterpriseMode`. `organization` показывается в настройках как «Управляется Acme», чтобы люди знали, кто это решил. `relayUrl` и `jev` закрепляют ваш собственный relay и вашу собственную конечную точку Jev, `allowNetworkAccess` разрешает другим устройствам добираться до OpenChamber по сети, а `allowedExtensions` перечисляет репозитории расширений, которым вы доверяете. Обо всём этом ниже.

- То, что задаёт пользователь — в настройках или в окружении, — не отключает то, что включает файл.
- Когда файл включает корпоративный режим, решает только файл. Переменные окружения ниже для relay, Jev и доступа к сети игнорируются, потому что пользователь может задать их сам.
- Если файл существует, но его нельзя прочитать или в нём неверный JSON, корпоративный режим остаётся включённым и ничего не закрепляется. Настройки сообщают, что политику не удалось прочитать. Сломанный файл никогда не снимает защиту молча.
- Изменения применяются без перезапуска.
- OpenChamber работает от имени пользователя, поэтому пользователь может прочитать файл. Помните об этом, прежде чем класть в него API-ключ.

### Переменная окружения

На сервере или в контейнере, где вы контролируете окружение, достаточно этого:

```bash
OPENCHAMBER_ENTERPRISE_MODE=1
```

На ноутбуке это более слабый замок: десктопное приложение читает её из профиля командной оболочки при входе (например, `~/.zshrc`), и пользователь может его изменить. Там используйте файл политики.

При этой переменной relay, Jev, доступ к сети и разрешённые расширения тоже задаются своими переменными: `OPENCHAMBER_RELAY_URL`, `OPENCHAMBER_JEV_URL`, `OPENCHAMBER_ALLOW_NETWORK_ACCESS=1`, `OPENCHAMBER_ALLOWED_EXTENSIONS` (URL репозиториев через запятую) и `OPENCHAMBER_ALLOW_LOCAL_EXTENSIONS=1`. В Docker понадобится переменная для сети, ведь сервер должен слушать за пределами контейнера.

### Закрепите OpenCode CLI

Если на ваших машинах уже установлен OpenCode и OpenChamber должен использовать эту установку, укажите её путь в файле политики. Это работает и с корпоративным режимом, и без него.

```json
{
  "opencodeBinary": "/usr/local/bin/opencode"
}
```

- OpenChamber запускает OpenCode только по этому пути. Он игнорирует путь в настройках, `OPENCODE_BINARY` и копию, встроенную в десктопное приложение, — она остаётся на диске неиспользуемой.
- Если по этому пути нет ничего запускаемого, OpenChamber не переключается на другую копию. Он останавливается с ошибкой, в которой назван путь.
- Настройки показывают путь только для чтения, с пометкой, что его задал администратор.
- OpenChamber не устанавливает и не обновляет закреплённый OpenCode и не сообщает о новых версиях. Обновления приходят с вашим развёртыванием.
- CLI должен быть OpenCode 2.x, не старше версии, которую требует OpenChamber. Со старым OpenChamber останавливается на экране «Обновите OpenCode».
- Папка тоже подойдёт, если в ней лежит `opencode` (`opencode.exe` в Windows). Переменной окружения для этого нет, потому что пользователь может задать её сам.

### Скройте встроенные каталоги навыков

OpenChamber поставляется с несколькими публичными каталогами навыков (Anthropic, OpenAI, Cursor, Matt Pocock). Если у вашей организации есть свой, добавьте его как собственный каталог и скройте встроенные в файле политики. Это работает и с корпоративным режимом, и без него.

```json
{
  "hideBuiltinSkillCatalogs": true
}
```

Тогда настройки предлагают только каталоги, которые люди добавили сами, а OpenChamber не загрузит встроенный, даже если его запросят напрямую. Переменной окружения для этого нет, потому что пользователь может задать её сам.

### Примеры

Положите файл политики на Mac. Выполните в Терминале от имени администратора:

```bash
sudo mkdir -p "/Library/Application Support/OpenChamber"
sudo tee "/Library/Application Support/OpenChamber/policy.json" > /dev/null <<'JSON'
{
  "enterpriseMode": true,
  "organization": "Acme"
}
JSON
```

В Linux всё так же, только папка `/etc/openchamber`.

В Windows запустите PowerShell от имени администратора. Последняя строка оставляет папку доступной для записи только администраторам и системе:

```powershell
New-Item -ItemType Directory -Force "C:\ProgramData\OpenChamber" | Out-Null
@'
{
  "enterpriseMode": true,
  "organization": "Acme"
}
'@ | Set-Content -Encoding UTF8 "C:\ProgramData\OpenChamber\policy.json"
icacls "C:\ProgramData\OpenChamber" /inheritance:r /grant:r "Administrators:(OI)(CI)F" "SYSTEM:(OI)(CI)F" "Users:(OI)(CI)RX"
```

Сервер в Docker, добавленный в `environment` файла `docker-compose.yml`. Контейнер слушает за своими пределами, поэтому ему нужно разрешить доступ к сети:

```yaml
environment:
  OPENCHAMBER_UI_PASSWORD: ${OPENCHAMBER_UI_PASSWORD}
  OPENCHAMBER_ENTERPRISE_MODE: "1"
  OPENCHAMBER_ALLOW_NETWORK_ACCESS: "1"
  # Optional:
  OPENCHAMBER_RELAY_URL: wss://relay.acme.com/ws
  OPENCHAMBER_JEV_URL: https://llm.acme.com/v1/systemone
  OPENCHAMBER_JEV_MODEL: acme-classifier
  OPENCHAMBER_JEV_API_KEY: ${ACME_JEV_KEY}
  OPENCHAMBER_ALLOWED_EXTENSIONS: https://github.com/acme/
```

Чтобы проверить, что всё сработало, откройте Настройки → Провайдеры: сверху появится уведомление о корпоративном режиме с названием вашей организации.

### Что меняется

- Провайдеры моделей берутся только из вашей конфигурации OpenCode. Подключение провайдера, вход в него, добавление ключа или создание собственного провайдера в OpenChamber отключены; удаление или переключение уже существующих аккаунтов по-прежнему работает. Это закрывает только вход через приложение; сам замок — политика OpenCode, описанная ниже. Вход в MCP-сервер из вашей конфигурации OpenCode по-прежнему работает, потому что он обращается к этому серверу, а не к провайдеру моделей.
- [Провайдеры классификации (Jev)](/ru/classification-providers/) остаются выключенными, включая собственную конечную точку, которую кто-то вводит в настройках. Предохранитель и Auto не предлагаются, а сессии в работе не получают подсказку «похоже, завершено». Чтобы использовать Jev через свою инфраструктуру, закрепите конечную точку через `jev` в файле политики или через `OPENCHAMBER_JEV_URL` (плюс `OPENCHAMBER_JEV_MODEL` и, если нужен, `OPENCHAMBER_JEV_API_KEY`). Она становится по умолчанию, люди всё ещё могут её отключить, а выбрать что-то другое нельзя.
- Чтение вслух через OpenAI выключено. Собственный сервер речи или транскрипции должен работать на той же машине. Локальные голоса и локальные модели диктовки продолжают работать.
- Push-уведомления на телефоны и в браузеры несут только общий заголовок вроде «Ответ агента готов», без текста сообщения или названия сессии. Уведомления на десктопе остаются на вашей машине и сохраняют полный текст.
- Проверка обновлений продолжается, поэтому исправления безопасности до вас доходят, но она никогда не сообщает об использовании, даже анонимный ID установки.
- [Внешние туннели](/ru/tunnels/) (Cloudflare, ngrok, Tailscale) выключены. Cloudflare и ngrok расшифровывают трафик на своей границе и видят каждый запрос открытым текстом; Tailscale Serve и Funnel открывают эту машину другим устройствам.
- Диаграммы `.drawio` открываются как обычный XML-текст. Редактор диаграмм — это собственная страница diagrams.net, и открытие диаграммы там передаёт ей файл.
- Каталог интеграций в боковой панели скрыт. Он устанавливает внешние сервисы из списка, который поставляется с OpenChamber. Добавление MCP-серверов, плагинов и навыков в настройках работает как раньше.
- Шрифты интерфейса и кода, которые загружаются с публичного CDN, заменяются вашими системными шрифтами. Ваш выбор сохраняется на время, когда режим выключен.
- [Private Relay](/ru/private-relay/) работает только через ваш собственный relay. Запустите [self-hosted relay](https://github.com/openchamber/openchamber-relay) и укажите на него OpenChamber через `relayUrl` в файле политики или `OPENCHAMBER_RELAY_URL=wss://relay.example.com/ws`. Общий relay тоже не может прочитать ваш трафик, ведь он зашифрован сквозным шифрованием, но собственный оставляет метаданные соединения и путь в эту машину внутри вашей сети. Без собственного relay устройства вообще нельзя спарить.
- OpenChamber слушает только на машине, где работает. Настройка десктопа, которая позволяет другим устройствам в локальной сети открывать приложение, выключена, и сервер отказывается запускаться на сетевом адресе — через CLI (`--host`, `--lan`) или через окружение. Если файл политики появляется, пока приложение работает, соединения с других машин отбрасываются до следующего запуска. Разрешите доступ к сети через `"allowNetworkAccess": true` в файле политики или `OPENCHAMBER_ALLOW_NETWORK_ACCESS=1` там, где корпоративный режим включается окружением. Учтите, что соединение идёт по обычному HTTP, поэтому в общей сети его может прочитать кто угодно; сервер, до которого добираются другие, ставьте за [свой HTTPS](/ru/reverse-proxy/).
- [Расширения](/ru/extensions/), которые могут отправлять данные с машины, устанавливаются только из Git-репозитория, указанного в `allowedExtensions`. Сюда входят расширения, которые общаются с внешним API, загружаются с внешних адресов, запускают фоновый сервис, отправляют этому сервису то, что агент говорит в сессиях, читают сессии из OpenCode, запускают сессии, отвечают на запросы разрешений агента, добавляют инструкции или поставляют навыки для агентов, либо поставляют плагин OpenCode — код, который выполняется внутри самого OpenCode. Разрешённое расширение, которое доставляет уведомления, получает только общий заголовок, без текста сообщения, названия сессии или проекта — так же, как телефон. Разрешённое расширение, которое работает как трекер, получает ваши поисковые запросы и идентификаторы элементов, которые вы открываете, а комментарии к сессиям, которые оно публикует, несут фиксированную метку и ссылку на сессию, но никогда то, что в ней говорилось. Разрешённое расширение, которое сообщает об использовании, получает учётные данные, которые OpenCode хранит для провайдеров из его манифеста, — вы одобрили их в его диалоге, — и ничего из ваших сессий. Расширения, которые ничего этого не делают, устанавливаются как обычно. Установленное расширение из любого другого места остаётся выключенным, и настройки говорят почему. В списке хранятся URL репозиториев, ведь расширение выбирает себе имя; запись, заканчивающаяся на `/`, например `https://github.com/acme/`, разрешает все репозитории под ней. На машинах тех, кто создаёт расширения, `"allowLocalExtensions": true` также разрешает установку из локальной папки. ZIP в любом случае остаётся закрытым.
- Переменные окружения из **Настройки → Общие** и из `opencode service set env` не доходят до OpenCode, потому что одна из них может нести ключ провайдера. Git, терминал и действия проекта их по-прежнему получают.
- В расширении VS Code подключение провайдеров выключено, а проверка обновлений не сообщает об использовании. В нём изначально нет Jev, relay, туннелей, push-уведомлений и облачной речи.

Задачи Small Model (заголовки сессий, итоги, сообщения коммитов, обзор диффа) не требуют особого режима. Они всегда работают на маленькой модели, которую вы выбрали в настройках, или на маленькой модели провайдера, с которым работаете, или на модели по умолчанию из вашей конфигурации OpenCode. Они никогда не переключаются на другого провайдера, который случайно подключён.

Какие провайдеры моделей вообще можно использовать, решает OpenCode, а не OpenChamber. Закройте это [политиками OpenCode](https://opencode.ai/v2/docs/policies/): запретите всех провайдеров, затем разрешите тех, кого одобрили.

```jsonc
{
  "experimental": {
    "policies": [
      { "action": "provider.use", "resource": "*", "effect": "deny" },
      { "action": "provider.use", "resource": "anthropic", "effect": "allow" }
    ]
  }
}
```

Запрещённый провайдер исчезает, даже если кто-то добавит для него ключ. Кладите политики в глобальный `~/.config/opencode/opencode.jsonc`, где проект не может их снять, или доставляйте их из рабочей области OpenCode Console, которая имеет последнее слово. Корпоративный режим закрывает то, что OpenChamber отправляет сверх этого.

Веб-поиск и загрузка страниц агентом тоже идут через OpenCode — к сервису поиска и к самим страницам. Если они не должны покидать вашу сеть, запретите их такой же политикой:

```jsonc
{ "action": "permission", "resource": "websearch:*", "effect": "deny" },
{ "action": "permission", "resource": "webfetch:*", "effect": "deny" }
```
