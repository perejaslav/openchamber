# Безопасность

OpenChamber даёт доступ к вашей машине и вашему коду, поэтому закройте его, прежде чем до него сможет добраться кто-то кроме вас. Эта страница описывает пароль UI, ключи доступа и то, что нужно знать, прежде чем выставлять OpenChamber в сеть.

## Задайте пароль UI

Запустите OpenChamber с паролем — и браузерный UI спросит его:

```bash
openchamber --ui-password be-creative-here
```

Пароль можно также задать переменной окружения `OPENCHAMBER_UI_PASSWORD`, а не указывать в командной строке. После входа OpenChamber на некоторое время запоминает устройство, так что пароль не придётся вводить каждый раз.

Всегда задавайте пароль, если экземпляр доступен кому-то ещё — особенно через [туннель](/tunnels/) или из публичного интернета.

## Ключи доступа

Когда пароль задан, можно добавить ключи доступа (Face ID, Touch ID, аппаратный ключ безопасности) для более быстрого входа. Добавляйте их в **Settings → OpenChamber → Passkeys**.

Ключи доступа привязаны к текущему паролю. Если вы измените или удалите пароль, сохранённые ключи доступа очищаются, и их придётся добавить заново.

## Токены устройств

Устройства, сопряжённые через [Подключение устройства](/connect-devices/), аутентифицируются своими токенами для каждого устройства, а не паролем UI. Ссылки для сопряжения одноразовые и истекают, если их не использовать; каждое подключённое устройство перечислено в **Settings → Remote Instances → Connect to this server**, где его можно отозвать в любой момент. Подключения извне дома идут через [Private Relay](/private-relay/), который шифруется от конца до конца и не может прочитать ваш трафик.

## Прежде чем открывать доступ

- По умолчанию OpenChamber слушает только вашу машину (`127.0.0.1`). Чтобы слушать шире, нужно осознанно это изменить, и сначала стоит задать пароль.
- Для своих устройств предпочитайте [сопряжение](/connect-devices/) с [Private Relay](/private-relay/) — тогда наружу ничего не выставляется.
- Если нужен публичный URL, предпочитайте [туннель](/tunnels/) или приватную сеть (например, VPN), а не открытый в интернет порт.
- Если вы ставите OpenChamber за свой HTTPS-сервер, см. [Обратный прокси](/reverse-proxy/).

## Корпоративный режим

Если ваша команда может отправлять содержимое разговоров только тем провайдерам моделей, которых вы настроили в OpenCode, включите корпоративный режим. Есть два способа, и достаточно любого из них.

### Файл политики на машине

Этот способ подходит для ноутбуков, которыми вы управляете. Положите файл `policy.json` в папку, куда может писать только администратор:

| Система | Путь |
|---|---|
| macOS | `/Library/Application Support/OpenChamber/policy.json` |
| Windows | `C:\ProgramData\OpenChamber\policy.json` |
| Linux | `/etc/openchamber/policy.json` |

Путь не зависит от того, как установлен OpenChamber. Десктопное приложение, веб-сервер, запущенный из npm, CLI и расширение VS Code читают один и тот же файл. Его можно раскатать через систему управления устройствами (Jamf, Intune и подобные). Для сервера в Docker смонтируйте файл по пути для Linux.

```json
{
  "enterpriseMode": true,
  "organization": "Acme",
  "relayUrl": "wss://relay.acme.com/ws",
  "allowNetworkAccess": false,
  "allowedExtensions": ["https://github.com/acme/"],
  "jev": {
    "url": "https://llm.acme.com/v1/systemone",
    "model": "acme-classifier",
    "apiKey": "..."
  }
}
```

Обязателен только `enterpriseMode`. `organization` показывается в настройках как «Managed by Acme», чтобы люди знали, кто это решил. `relayUrl` и `jev` закрепляют ваш собственный релей и ваш собственный эндпоинт Jev, `allowNetworkAccess` разрешает другим устройствам обращаться к OpenChamber по сети, а `allowedExtensions` перечисляет репозитории расширений, которым вы доверяете. Обо всех них — ниже.

- Ничего из того, что задаёт пользователь — в настройках или в окружении, — не отключает то, что включает файл.
- Когда файл включает корпоративный режим, решает только файл. Переменные окружения для релея, Jev и сетевого доступа, описанные ниже, игнорируются, потому что пользователь может задать их сам.
- Если файл существует, но не читается или содержит невалидный JSON, корпоративный режим остаётся включённым, и ничего не закреплено. В настройках будет сказано, что политику не удалось прочитать. Сломанный файл никогда не снимает защиту молча.
- Изменения применяются без перезапуска.
- OpenChamber работает от имени пользователя, поэтому пользователь может прочитать файл. Учтите это, прежде чем класть в него ключ API.

### Переменная окружения

На сервере или в контейнере, где окружение под вашим контролем, достаточно этого:

```bash
OPENCHAMBER_ENTERPRISE_MODE=1
```

На ноутбуке это более слабый замок: десктопное приложение читает переменную из профиля командной оболочки при входе (например, `~/.zshrc`), и пользователь может его отредактировать. Там используйте файл политики.

С переменной релей, Jev, сетевой доступ и разрешённые расширения тоже задаются своими переменными: `OPENCHAMBER_RELAY_URL`, `OPENCHAMBER_JEV_URL`, `OPENCHAMBER_ALLOW_NETWORK_ACCESS=1`, `OPENCHAMBER_ALLOWED_EXTENSIONS` (URL репозиториев через запятую) и `OPENCHAMBER_ALLOW_LOCAL_EXTENSIONS=1`. В Docker понадобится сетевая, поскольку сервер должен слушать за пределами контейнера.

### Закрепите OpenCode CLI

Если на ваших машинах уже установлен OpenCode и OpenChamber должен использовать эту установку, укажите её путь в файле политики. Это работает и с корпоративным режимом, и без него.

```json
{
  "opencodeBinary": "/usr/local/bin/opencode"
}
```

- OpenChamber запускает OpenCode только по этому пути. Он игнорирует путь в настройках, `OPENCODE_BINARY` и копию, входящую в комплект десктопного приложения, — та остаётся на диске неиспользованной.
- Если по этому пути нет ничего запускаемого, OpenChamber не переходит на другую копию. Он останавливается с ошибкой, в которой назван путь.
- В настройках путь показан только для чтения, с пометкой, что его задал администратор.
- OpenChamber не устанавливает и не обновляет закреплённый OpenCode и не сообщает о новых версиях. Обновления приходят вместе с вашей раскаткой.
- CLI должен быть OpenCode 2.x, не старее версии, которую требует OpenChamber. С более старой OpenChamber останавливается на экране «update OpenCode».
- Папка тоже подойдёт, если в ней лежит `opencode` (`opencode.exe` в Windows). Переменной окружения для этого нет, потому что пользователь может задать её сам.


### Скройте встроенные каталоги навыков

OpenChamber поставляется с несколькими публичными каталогами навыков (Anthropic, OpenAI, Cursor, Matt Pocock). Если у вашей организации есть свой, добавьте его как пользовательский каталог и скройте встроенные в файле политики. Это работает и с корпоративным режимом, и без него.

```json
{
  "hideBuiltinSkillCatalogs": true
}
```

Тогда в настройках будут доступны только каталоги, которые люди добавили сами, и OpenChamber не загрузит встроенный, даже если его запросить напрямую. Переменной окружения для этого нет, потому что пользователь может задать её сам.

### Примеры

Положите файл политики на Mac. Выполните в Terminal от имени администратора:

```bash
sudo mkdir -p "/Library/Application Support/OpenChamber"
sudo tee "/Library/Application Support/OpenChamber/policy.json" > /dev/null <<'JSON'
{
  "enterpriseMode": true,
  "organization": "Acme"
}
JSON
```

В Linux всё то же самое, только папка — `/etc/openchamber`.

В Windows запустите PowerShell от имени администратора. Последняя строка оставляет папку доступной для записи только администраторам и системе:

```powershell
New-Item -ItemType Directory -Force "C:\ProgramData\OpenChamber" | Out-Null
@'
{
  "enterpriseMode": true,
  "organization": "Acme"
}
'@ | Set-Content -Encoding UTF8 "C:\ProgramData\OpenChamber\policy.json"
icacls "C:\ProgramData\OpenChamber" /inheritance:r /grant:r "Administrators:(OI)(CI)F" "SYSTEM:(OI)(CI)F" "Users:(OI)(CI)RX"
```

Сервер в Docker, добавленный в `environment` файла `docker-compose.yml`. Контейнер слушает за своими пределами, поэтому ему нужно разрешить сетевой доступ:

```yaml
environment:
  OPENCHAMBER_UI_PASSWORD: ${OPENCHAMBER_UI_PASSWORD}
  OPENCHAMBER_ENTERPRISE_MODE: "1"
  OPENCHAMBER_ALLOW_NETWORK_ACCESS: "1"
  # Optional:
  OPENCHAMBER_RELAY_URL: wss://relay.acme.com/ws
  OPENCHAMBER_JEV_URL: https://llm.acme.com/v1/systemone
  OPENCHAMBER_JEV_MODEL: acme-classifier
  OPENCHAMBER_JEV_API_KEY: ${ACME_JEV_KEY}
  OPENCHAMBER_ALLOWED_EXTENSIONS: https://github.com/acme/
```

Чтобы проверить, что всё получилось, откройте Settings → Providers: вверху появится уведомление о корпоративном режиме с названием вашей организации.

### Что меняется

- Провайдеры моделей берутся только из вашей конфигурации OpenCode. Подключение провайдера, вход в него, добавление ключа и создание пользовательского провайдера в OpenChamber отключены; удаление или переключение уже существующих аккаунтов по-прежнему работает. Это закрывает лишь вход через приложение; сам замок — политика OpenCode, описанная ниже. Вход на сервер MCP из вашей конфигурации OpenCode по-прежнему работает, поскольку обращается к этому серверу, а не к провайдеру моделей.
- [Провайдеры классификации (Jev)](/classification-providers/) остаются отключены, включая пользовательский эндпоинт, который кто-то введёт в настройках. Страховочная сеть и Auto не предлагаются, а сессии в работе не получают подсказку «похоже, готово». Чтобы использовать Jev через свою инфраструктуру, закрепите эндпоинт с помощью `jev` в файле политики или через `OPENCHAMBER_JEV_URL` (плюс `OPENCHAMBER_JEV_MODEL` и, если нужно, `OPENCHAMBER_JEV_API_KEY`). Он становится по умолчанию, люди по-прежнему могут его отключить, а выбрать что-то другое нельзя.
- Чтение вслух через OpenAI отключено. Пользовательский сервер речи или транскрипции должен работать на той же машине. Локальные голоса и локальные модели диктовки продолжают работать.
- Push-уведомления на телефоны и в браузеры несут только общий заголовок вроде «Ответ агента готов», без текста сообщения и названия сессии. Уведомления на десктопе остаются на вашей машине и сохраняют полный текст.
- Проверки обновлений продолжают работать, чтобы исправления безопасности до вас доходили, но они никогда не сообщают об использовании, даже анонимный ID установки.
- [Внешние туннели](/tunnels/) (Cloudflare, ngrok, Tailscale) отключены. Cloudflare и ngrok расшифровывают трафик на своей границе и видят каждый запрос в открытом виде; Tailscale Serve и Funnel открывают эту машину другим устройствам.
- Диаграммы `.drawio` открываются как свой XML-текст. Редактор диаграмм — это собственная страница diagrams.net, и открытие диаграммы там передаёт ей файл.
- Каталог интеграций в боковой панели скрыт. Он устанавливает внешние сервисы из списка, который поставляется с OpenChamber. Добавление серверов MCP, плагинов и навыков в настройках работает как раньше.
- Шрифты интерфейса и кода, загружаемые с публичного CDN, заменяются системными. Ваш выбор сохраняется на время, когда режим выключен.
- [Private Relay](/private-relay/) работает только через ваш собственный релей. Запустите [развёрнутый самостоятельно релей](https://github.com/openchamber/openchamber-relay) и направьте на него OpenChamber через `relayUrl` в файле политики или `OPENCHAMBER_RELAY_URL=wss://relay.example.com/ws`. Общий релей тоже не может прочитать ваш трафик, поскольку он шифруется от конца до конца, но свой собственный оставляет метаданные соединения и путь к этой машине внутри вашей сети. Без своего релея устройства вообще нельзя сопрячь.
- Страницы, которыми агент делится с другими людьми по ссылке и PIN, идут только через ваш собственный релей — тот, что задан в `relayUrl` или `OPENCHAMBER_RELAY_URL`. Релей хранит только зашифрованную страницу и ответ, но ссылка ведёт туда. Без своего релея общего доступа нет: агенту его не предлагают, а сервер отказывает. Открытие страницы, которой поделился кто-то другой, работает так же: OpenChamber открывает только ссылки на вашем релее, а без него вставленная ссылка остаётся обычным текстом.
- OpenChamber слушает только машину, на которой работает. Настройка десктопа, позволяющая другим устройствам в локальной сети открывать приложение, отключена, а сервер отказывается запускаться на сетевом адресе — как через CLI (`--host`, `--lan`), так и через окружение. Если файл политики появляется, пока приложение работает, подключения с других машин сбрасываются до следующего запуска. Разрешите сетевой доступ через `"allowNetworkAccess": true` в файле политики или `OPENCHAMBER_ALLOW_NETWORK_ACCESS=1` там, где корпоративный режим включается окружением. Учтите, что соединение идёт по обычному HTTP, поэтому в общей сети его может прочитать любой; сервер, доступный другим, ставьте за [свой HTTPS](/reverse-proxy/).
- [Расширения](/extensions/), которые могут отправлять данные за пределы машины (те, что обращаются к внешнему API, загружаются с внешних адресов, запускают фоновый сервис, передают этому сервису сказанное агентом в сессиях, читают сессии из OpenCode или запускают сессии, отвечают на запросы разрешений агента, добавляют инструкции или поставляют навыки для агентов, либо поставляют плагин OpenCode, то есть код, работающий внутри самого OpenCode), устанавливаются только из репозитория Git, перечисленного в `allowedExtensions`. Разрешённое расширение, которое доставляет уведомления, получает только общий заголовок — без текста сообщения, названия сессии или проекта, как и телефон. Разрешённое расширение-трекер получает ваши поисковые запросы и идентификаторы открытых элементов, а комментарии к сессиям, которые оно публикует, несут фиксированную метку и ссылку на сессию, но никогда — сказанное в ней. Разрешённое расширение, которое сообщает об использовании, получает учётные данные, которые OpenCode хранит для провайдеров из его манифеста, одобренных вами в его диалоге, и ничего из ваших сессий. Расширения, которые ничего этого не делают, устанавливаются как обычно. Установленное расширение из любого другого места остаётся отключённым, и настройки объясняют почему. Список содержит URL репозиториев, поскольку расширение выбирает себе имя; запись, оканчивающаяся на `/`, например `https://github.com/acme/`, разрешает все репозитории под ней. На машинах тех, кто разрабатывает расширения, `"allowLocalExtensions": true` дополнительно разрешает установку из локальной папки. ZIP в любом случае остаётся закрытым.
- Переменные окружения из **Settings → General** и из `opencode service set env` не доходят до OpenCode, поскольку одна из них может нести ключ провайдера. Git, терминал и действия проекта их по-прежнему получают.
- В расширении VS Code подключение провайдеров отключено, а проверки обновлений не сообщают об использовании. В нём изначально нет Jev, релея, туннелей, push-уведомлений и облачной речи.

Задачи для малой модели (названия сессий, краткие итоги, сообщения коммитов, разбор диффа) не требуют особого режима. Они всегда выполняются на малой модели, выбранной вами в настройках, или на малой модели провайдера, с которым вы работаете, или на модели по умолчанию из вашей конфигурации OpenCode. Они никогда не переключаются на другого провайдера, который у вас случайно подключён.

Какими провайдерами моделей вообще можно пользоваться, решает OpenCode, а не OpenChamber. Закройте это через [политики OpenCode](https://opencode.ai/v2/docs/policies/): запретите всех провайдеров, затем разрешите одобренных.

```jsonc
{
  "experimental": {
    "policies": [
      { "action": "provider.use", "resource": "*", "effect": "deny" },
      { "action": "provider.use", "resource": "anthropic", "effect": "allow" }
    ]
  }
}
```

Запрещённый провайдер исчезает, даже если кто-то добавит для него ключ. Положите политики в системную конфигурацию OpenCode (`/etc/opencode/opencode.jsonc` в Linux, `%ProgramData%\opencode\opencode.jsonc` в Windows, `/Library/Application Support/opencode/opencode.jsonc` в macOS) и разрешите писать в её папку только администраторам, как в примере для Windows выше, либо доставляйте их из рабочей области OpenCode Console. Путь системной конфигурации — на машине, где работает OpenCode; в описанной выше схеме с Docker OpenCode работает внутри контейнера, поэтому смонтируйте туда файл только для чтения, в разделе `volumes` файла `docker-compose.yml`: `- ./opencode-policy.jsonc:/etc/opencode/opencode.jsonc:ro`. И то и другое выше глобального `~/.config/opencode/opencode.jsonc` пользователя и файлов проекта, а системная конфигурация выше ещё и Console. Политики Console действуют, только пока рабочая область подключена, и очищаются при отключении, поэтому ограничения, которые должны сохраняться после отключения, кладите в системную конфигурацию. Глобальный файл не даёт проекту снять их, но пользователь может его отредактировать. Корпоративный режим покрывает то, что OpenChamber отправляет сверх этого.

Веб-поиск и загрузка страниц агентом тоже идут через OpenCode — к сервису поиска и к самим страницам. Если они не должны покидать вашу сеть, запретите их такой же политикой. Если в конфигурации уже есть политики, добавьте две записи `tool.use` в конец её списка, сохранив записи провайдеров и любые другие политики. Когда в файле есть и массив `policies` верхнего уровня, и `experimental.policies`, добавляйте в верхний: OpenCode сначала читает `experimental.policies`, а побеждает последняя подходящая запись. Для новой конфигурации пример работает сам по себе:

```jsonc
{
  "experimental": {
    "policies": [
      { "action": "tool.use", "resource": "websearch:*", "effect": "deny" },
```
