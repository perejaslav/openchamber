# Переменные окружения

OpenChamber читает эти переменные окружения при запуске. Для сервисов автозапуска `openchamber startup enable` по умолчанию снимает снимок текущего окружения, поэтому запустите её заново после изменения переменных, которые должен использовать сервис. Переменные, которые OpenChamber сам задал в оболочке, откуда вы его запускаете, — например в терминале десктопного приложения или в оболочке агента, — в сервис не попадают; ваши собственные export оттуда тоже переносятся, если только вы не переэкспортируете имя, которое OpenChamber уже задал в этой оболочке, а обычный терминал этого избегает.

## Переменные для OpenCode, Git и терминала

Чтобы дать OpenCode, Git, терминалу и [действиям проекта](/project-actions/) собственные переменные, например токен API или адрес базы данных, добавьте их в **Settings → General → Environment variables**, а не экспортируйте перед запуском OpenChamber. Значения остаются на машине, где работает OpenChamber, в `environment.json` в каталоге данных, доступном только вашему пользователю. Настройки больше никогда не показывают значение: его можно заменить или удалить, но не прочитать обратно.

- OpenCode получает их при запуске, поэтому после изменения перезапустите его. В настройках есть кнопка для этого.
- Переменные, заданные через `opencode service set env`, тоже доходят до OpenCode. Переменные из настроек важнее.
- Git, терминал и действия проекта получают их при следующем запуске.
- Переменные, которые OpenChamber задаёт для самого OpenCode, например его пароль и конфигурацию, важнее ваших.

Проект может добавить свои переменные или команду, которая их выводит, например `direnv export json`, в **Settings → Projects**. См. [Проекты](/projects/#project-environment).

Эти переменные не доходят до сервера OpenCode, который вы запустили сами, а в расширении VS Code такой настройки нет. Всё перечисленное ниже OpenChamber читает сам при запуске.

## Сервер OpenChamber

### `OPENCHAMBER_HOST`

Адрес привязки веб-сервера OpenChamber. Используйте `0.0.0.0`, чтобы разрешить доступ с других машин.

### `OPENCHAMBER_LAN_URL`

Адрес, по которому другие устройства в вашей сети обращаются к OpenChamber, например `http://192.168.1.20:3000`. Ссылки для сопряжения и QR-коды предлагают его вместо адреса, который OpenChamber определяет сам. Задайте его, когда это определение неверно, например в Docker, где OpenChamber видит только внутренний адрес контейнера.

### `OPENCHAMBER_UI_PASSWORD`

Пароль для браузерного UI. Используйте его, когда привязываетесь за пределами localhost, используете туннели или работаете за обратным прокси.

### `OPENCHAMBER_UI_SESSION_TTL_HOURS`

Сколько длится вход в браузере, в часах, когда «доверять этому устройству» выключено. По умолчанию `12`.

### `OPENCHAMBER_UI_TRUSTED_SESSION_TTL_DAYS`

Сколько длится вход, в днях, на устройстве, которому вы решили доверять. По умолчанию `7`.

### `OPENCHAMBER_API_ONLY`

Запускает OpenChamber в headless-режиме, если задано `true` или `1`. Маршруты API остаются доступны для десктопных и мобильных клиентов, но браузерный UI не отдаётся.

### `OPENCHAMBER_FRAME_ANCESTORS`

Источники, которым разрешено показывать OpenChamber во фрейме на своей странице, через пробел, например `https://dash.example.com`. `*` разрешает любой сайт. По умолчанию встраивать его могут только сам OpenChamber и его десктопное и мобильное приложения, что не даёт другим сайтам накладывать элементы поверх его кнопок.

### `OPENCHAMBER_TRUSTED_PROXIES`

Адреса обратных прокси, которые работают на другой машине или в другом контейнере, через запятую, например `192.168.1.10` или `172.18.0.0/16`. OpenChamber ограничивает неудачные попытки входа для каждого клиента и читает адрес клиента из `X-Forwarded-For`, только когда запрос приходит с этой машины или с адреса из списка. Прокси, которого нет в списке, считается одним клиентом, поэтому неудачные попытки одного человека могут на время закрыть вход всем, кто за ним.

### `OPENCHAMBER_DATA_DIR`

Переопределяет каталог данных OpenChamber. По умолчанию `~/.config/openchamber`.

Всё, что хранит OpenChamber, лежит в этом каталоге: настройки, аутентификация, конфигурации проектов, темы, планы и модели речи. Экземпляр, который до версии 1.23 использовал собственный каталог, при первом запуске получает копии папок `projects`, `themes` и `speech-models` из `~/.config/openchamber`; оригиналы остаются на месте, и ничего не объединяется.

### `OPENCHAMBER_CHATS_DIR`

Переносит управляемые каталоги чатов, которые OpenChamber создаёт для чатов без проекта. По умолчанию `~/.config/openchamber/chats`. Задайте каталог, который может прочитать сервер OpenCode, когда OpenChamber и OpenCode работают от разных пользователей. Существующие чаты не переносятся.

### `OPENCHAMBER_COMPRESS_API`

Управляет сжатием ответов API. `true` или `1` принудительно включает его, `false` или `0` принудительно выключает.

### `OPENCHAMBER_SKIP_API_COMPRESSION`

Отключает сжатие ответов API, если задано `true` или `1`. Это имеет приоритет над `OPENCHAMBER_COMPRESS_API`.

### `OPENCHAMBER_VERBOSE_REQUEST_LOGS`

Включает подробные логи HTTP-запросов, если задано `true` или `1`.

### `OPENCHAMBER_UPDATE_API_URL`

Переопределяет эндпоинт API проверки обновлений. Большинству пользователей лучше оставить это незаданным.

### `OPENCHAMBER_PACKAGE_MANAGER`

Принудительно задаёт менеджер пакетов, который используют операции обновления, когда автоопределение ошибается.

## Прокси

### `HTTP_PROXY`, `HTTPS_PROXY`, `NO_PROXY`

Направляет собственные исходящие запросы OpenChamber, например запросы лимитов использования и каталогов навыков, через прокси. Имена в нижнем регистре тоже работают. Хосты из `NO_PROXY` подключаются напрямую, и `localhost`, `127.0.0.1` и `::1` всегда так и делают, поэтому обратные вызовы входа и локальный сервер OpenCode продолжают работать.

## Сервер OpenCode

### `OPENCODE_HOST`

Подключает OpenChamber к существующему серверу OpenCode. Значение должно быть origin-адресом со схемой `http` или `https`, с явным портом и без пути, query и хеша. `OPENCODE_HOST` имеет приоритет над `OPENCODE_PORT`.

### `OPENCODE_PORT`

Задаёт порт сервера OpenCode. С управляемым OpenCode это запрос управляемого порта; с `OPENCODE_SKIP_START=true` — подключение к внешнему серверу на этом порту.

### `OPENCODE_SKIP_START`

Не даёт OpenChamber запускать собственный сервер OpenCode, если задано `true`.

### `OPENCHAMBER_OPENCODE_HOSTNAME`

Имя хоста для привязки сервера OpenCode, которым управляет OpenChamber. По умолчанию `127.0.0.1`.

### `OPENCHAMBER_OPENCODE_HEALTH_TIMEOUT_MS`

Ограничение времени на проверку работоспособности OpenCode, в миллисекундах. По умолчанию `5000`.

### `OPENCHAMBER_OPENCODE_HEALTH_CONSECUTIVE_FAILURES`

Число подряд засчитанных сбоев проверки работоспособности, после которого OpenChamber перезапускает управляемый процесс OpenCode, если тот всё ещё работает. По умолчанию `20`. Занятые сессии могут отложить перезапуск.

### `OPENCHAMBER_OPENCODE_HEALTH_INTERVAL_MS`

Переопределяет интервал проверки работоспособности управляемого OpenCode, в миллисекундах. Он же задаёт минимальное время между засчитанными сбоями. По умолчанию `0`, что сохраняет интервал сервера в `15000` миллисекунд.

### `OPENCHAMBER_OPENCODE_HEALTH_CACHE_MS`

Как долго OpenChamber повторно использует результат проверки работоспособности управляемого OpenCode, включая неудачный, в миллисекундах. По умолчанию `750`.

### `OPENCODE_BINARY`

Путь к исполняемому файлу `opencode`, который должен запускать OpenChamber.

### `OPENCODE_CONFIG`

Путь к конкретному файлу конфигурации OpenCode.

### `OPENCODE_CONFIG_DIR`

Путь к конкретному каталогу конфигурации OpenCode для агентов, навыков, сниппетов и поиска конфигурации.

### `OPENCODE_DATA_DIR`

Собственный каталог данных для управляемого сервера OpenCode.

### `OPENCODE_JWT_SECRET`

Секрет для подписи токенов аутентификации UI. Для постоянных развёртываний сервиса используйте длинное случайное значение.

## Терминал и Git

### `OPENCHAMBER_TERMINAL_SHELL`

Исполняемый файл оболочки для терминальных сессий OpenChamber.

### `OPENCHAMBER_GIT_BINARY`

Исполняемый файл Git, который используют функции Git в OpenChamber.

### `GIT_BINARY`

Альтернативное переопределение исполняемого файла Git. Для настроек, специфичных для OpenChamber, предпочитайте `OPENCHAMBER_GIT_BINARY`.

### `OPENCHAMBER_GIT_READ_CACHE_TTL_MS`

Время жизни кэша чтения файлов из Git, в миллисекундах. Задайте `0`, чтобы отключить этот кэш при отладке.

## Голос и туннели

### `OPENAI_API_KEY`

Ключ API, который голосовые функции OpenChamber используют, когда обращаются к самому OpenAI. Он никогда не отправляется на пользовательский сервер, совместимый с OpenAI: задайте тому серверу собственный ключ в настройках.

### `OPENCHAMBER_ALLOW_REMOTE_OPENAI_COMPAT_URLS`

Разрешает удалённые базовые URL, совместимые с OpenAI, для голосовых функций, если задано `true` или `1`.

### `NGROK_AUTHTOKEN`

Токен авторизации ngrok, который используют команды туннелей OpenChamber. Настроить ngrok можно и через `ngrok config add-authtoken <token>`.

## Вспомогательные элементы среды выполнения

### `BUN_BINARY`

Исполняемый файл Bun, который OpenChamber должен использовать при запуске демон-процессов.

### `BUN_INSTALL`

Корень установки Bun. OpenChamber использует его, чтобы найти `bin/bun` для запуска демона и обновлений.

### `VITE_OPENCODE_URL`

Базовый URL API на этапе сборки для веб-приложения, собранного Vite. Большинству пользователей не стоит задавать его для обычной работы через CLI или десктопное приложение.
