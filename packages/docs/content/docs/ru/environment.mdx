# Переменные окружения

OpenChamber читает эти переменные окружения при запуске. Для служб автозапуска `openchamber startup enable` по умолчанию сохраняет снимок текущего окружения, поэтому запустите её заново после изменения переменных, которые должна использовать служба. Переменные, которые сам OpenChamber установил в оболочке, откуда вы его запускаете (например, терминале десктопного приложения или оболочке агента), не переносятся в службу. Ваши собственные переменные переносятся, если вы не переопределили имя, уже занятое OpenChamber в той оболочке. В обычном терминале такого конфликта нет.

## Переменные для OpenCode, Git и терминала

Чтобы передавать OpenCode, Git, терминалу и [действиям проекта](/ru/project-actions/) собственные переменные, например API-токен или адрес базы данных, добавляйте их в **Настройки → Общие → Переменные окружения**, а не экспортируйте перед запуском OpenChamber. Значения хранятся на машине с OpenChamber, в файле `environment.json` его папки данных, доступном только вашему пользователю. Настройки не показывают сохранённое значение повторно: его можно заменить или удалить, но не прочитать.

- OpenCode получает переменные при запуске, поэтому после изменения перезапустите его. Настройки предложат соответствующую кнопку.
- Переменные, заданные через `opencode service set env`, тоже поступают в OpenCode. При конфликте приоритет у значений из настроек.
- Git, терминал и действия проекта получают новые значения при следующем запуске.
- Переменные, которые OpenChamber задаёт для самого OpenCode (например, пароль и конфигурация), имеют приоритет над вашими.

Проект может добавлять собственные переменные или команду вроде `direnv export json`, которая их выводит, в разделе **Настройки → Проекты**. См. [Проекты](/ru/projects/).

Эти переменные не поступают на сервер OpenCode, запущенный вами отдельно. В расширении VS Code такой настройки нет. Все перечисленные ниже переменные сам OpenChamber считывает при запуске.

## Сервер OpenChamber

### `OPENCHAMBER_HOST`

Адрес привязки для веб-сервера OpenChamber. Используйте `0.0.0.0`, чтобы разрешить доступ с других машин.

### `OPENCHAMBER_LAN_URL`

Адрес, по которому другие устройства вашей сети подключаются к OpenChamber, например `http://192.168.1.20:3000`. Он используется в ссылках сопряжения и QR-кодах вместо адреса, который OpenChamber определяет сам. Укажите его, если определение ошибается, например в Docker, где виден только внутренний адрес контейнера.

### `OPENCHAMBER_UI_PASSWORD`

Пароль для интерфейса в браузере. Используйте его при привязке вне localhost, работе через туннели или за обратным прокси.

### `OPENCHAMBER_UI_SESSION_TTL_HOURS`

Срок действия входа в браузере в часах, если параметр «Доверять этому устройству» выключен. По умолчанию — `12`.

### `OPENCHAMBER_UI_TRUSTED_SESSION_TTL_DAYS`

Срок действия входа в днях на устройстве, которое вы решили считать доверенным. По умолчанию — `7`.

### `OPENCHAMBER_API_ONLY`

Запускает OpenChamber в headless-режиме, если задано `true` или `1`. Маршруты API остаются доступными для десктопных и мобильных клиентов, но интерфейс в браузере не отдаётся.

### `OPENCHAMBER_FRAME_ANCESTORS`

Адреса сайтов, которым разрешено показывать OpenChamber во фрейме на своей странице, через пробел, например `https://dash.example.com`. Значение `*` разрешает любые сайты. По умолчанию встраивать OpenChamber могут только он сам и его десктопное и мобильное приложения: это мешает посторонним сайтам накладывать свои элементы на его кнопки.

### `OPENCHAMBER_TRUSTED_PROXIES`

Адреса обратных прокси на другой машине или в другом контейнере, разделённые запятыми, например `192.168.1.10` или `172.18.0.0/16`. OpenChamber ограничивает число неудачных попыток входа для каждого клиента и считывает его адрес из `X-Forwarded-For` только если запрос пришёл с этой машины или с указанного здесь адреса. Неуказанный прокси считается одним клиентом: из-за неудачных попыток входа одного пользователя остальные за этим прокси тоже могут на время лишиться возможности войти.

### `OPENCHAMBER_DATA_DIR`

Переопределяет папку данных OpenChamber. По умолчанию — `~/.config/openchamber`.

Всё, что хранит OpenChamber, лежит в этой папке: настройки, аутентификация, конфигурации проектов, темы, планы и модели распознавания речи. Экземпляр, который использовал собственную папку до версии 1.23, при первом запуске получает свои папки `projects`, `themes` и `speech-models`, скопированные из `~/.config/openchamber`; оригиналы остаются на месте, и ничего не объединяется.

### `OPENCHAMBER_CHATS_DIR`

Перемещает управляемые папки чатов, которые OpenChamber создаёт для чатов без проекта. По умолчанию — `~/.config/openchamber/chats`. Укажите папку, которую может читать сервер OpenCode, когда OpenChamber и OpenCode работают под разными пользователями. Существующие чаты не перемещаются.

### `OPENCHAMBER_COMPRESS_API`

Управляет сжатием ответов API. Используйте `true` или `1`, чтобы принудительно включить его, `false` или `0` — чтобы принудительно отключить.

### `OPENCHAMBER_SKIP_API_COMPRESSION`

Отключает сжатие ответов API, если задано `true` или `1`. Имеет приоритет над `OPENCHAMBER_COMPRESS_API`.

### `OPENCHAMBER_VERBOSE_REQUEST_LOGS`

Включает подробные логи HTTP-запросов, если задано `true` или `1`.

### `OPENCHAMBER_UPDATE_API_URL`

Переопределяет конечную точку API для проверки обновлений. Большинству пользователей её задавать не нужно.

### `OPENCHAMBER_PACKAGE_MANAGER`

Принудительно задаёт менеджер пакетов, используемый операциями обновления, когда автоопределение ошибается.

## Прокси

### `HTTP_PROXY`, `HTTPS_PROXY`, `NO_PROXY`

Направляет собственные исходящие запросы OpenChamber (например, проверку лимитов использования и загрузку каталогов навыков) через прокси. Варианты имён в нижнем регистре тоже работают. К хостам из `NO_PROXY` подключение выполняется напрямую. `localhost`, `127.0.0.1` и `::1` всегда обходят прокси, чтобы продолжали работать обратные вызовы авторизации и локальный сервер OpenCode.

## Сервер OpenCode

### `OPENCODE_HOST`

Подключает OpenChamber к уже запущенному серверу OpenCode. Значение должно быть origin `http` или `https` с явным портом и без пути, строки запроса или фрагмента. `OPENCODE_HOST` имеет приоритет над `OPENCODE_PORT`.

### `OPENCODE_PORT`

Задаёт порт сервера OpenCode. С управляемым OpenCode это запрашиваемый управляемый порт; при `OPENCODE_SKIP_START=true` он подключается к внешнему серверу на этом порту.

### `OPENCODE_SKIP_START`

Не даёт OpenChamber запускать собственный сервер OpenCode, если задано `true`.

### `OPENCHAMBER_OPENCODE_HOSTNAME`

Имя хоста для привязки сервера OpenCode, управляемого OpenChamber. По умолчанию — `127.0.0.1`.

### `OPENCHAMBER_OPENCODE_HEALTH_TIMEOUT_MS`

Предельная длительность проверки состояния OpenCode в миллисекундах. По умолчанию — `5000`.

### `OPENCHAMBER_OPENCODE_HEALTH_CONSECUTIVE_FAILURES`

Число последовательных ошибок проверки состояния, после которого OpenChamber перезапускает ещё работающий управляемый процесс OpenCode. По умолчанию — `20`. Если сессии заняты, перезапуск может задержаться.

### `OPENCHAMBER_OPENCODE_HEALTH_INTERVAL_MS`

Переопределяет интервал проверки состояния управляемого OpenCode в миллисекундах. Он также задаёт минимальный промежуток между учитываемыми ошибками. По умолчанию — `0`, то есть сохраняется серверный интервал `15000` миллисекунд.

### `OPENCHAMBER_OPENCODE_HEALTH_CACHE_MS`

Как долго OpenChamber повторно использует результат проверки состояния управляемого OpenCode, в том числе неудачный, в миллисекундах. По умолчанию — `750`.

### `OPENCODE_BINARY`

Путь к исполняемому файлу `opencode`, который должен запускать OpenChamber.

### `OPENCODE_CONFIG`

Путь к конкретному файлу конфигурации OpenCode.

### `OPENCODE_CONFIG_DIR`

Путь к конкретной папке конфигурации OpenCode для агентов, навыков, сниппетов и поиска конфигурации.

### `OPENCODE_DATA_DIR`

Собственная папка данных для управляемого сервера OpenCode.

### `OPENCODE_JWT_SECRET`

Секрет, используемый для подписи токенов аутентификации интерфейса. Для постоянно работающих служб используйте длинное случайное значение.

## Терминал и Git

### `OPENCHAMBER_TERMINAL_SHELL`

Исполняемый файл оболочки, используемый для сессий терминала OpenChamber.

### `OPENCHAMBER_GIT_BINARY`

Исполняемый файл Git, используемый функциями Git в OpenChamber.

### `GIT_BINARY`

Альтернативное переопределение исполняемого файла Git. Для конфигурации, специфичной для OpenChamber, предпочитайте `OPENCHAMBER_GIT_BINARY`.

### `OPENCHAMBER_GIT_READ_CACHE_TTL_MS`

Время жизни (TTL) в миллисекундах для кэшированного чтения файлов из Git. Задайте `0`, чтобы отключить этот кэш при отладке.

## Голос и туннели

### `OPENAI_API_KEY`

API-ключ, который голосовые функции OpenChamber используют при обращении непосредственно к OpenAI. Он никогда не отправляется на сторонний сервер, совместимый с OpenAI: задайте ключ такого сервера отдельно в настройках.

### `OPENCHAMBER_ALLOW_REMOTE_OPENAI_COMPAT_URLS`

Разрешает удалённые базовые URL, совместимые с OpenAI, для голосовых функций, если задано `true` или `1`.

### `NGROK_AUTHTOKEN`

Токен аутентификации ngrok, используемый командами туннеля OpenChamber. Также можно настроить ngrok с помощью `ngrok config add-authtoken <token>`.

## Вспомогательные компоненты среды выполнения

### `BUN_BINARY`

Исполняемый файл Bun, который OpenChamber должна использовать при запуске процессов-демонов.

### `BUN_INSTALL`

Корень установки Bun. OpenChamber использует его, чтобы найти `bin/bun` для запуска демона и обновлений.

### `VITE_OPENCODE_URL`

Базовый URL API на этапе сборки для веб-приложения, собранного Vite. Большинству пользователей не нужно задавать его при обычном использовании CLI или десктопа.
