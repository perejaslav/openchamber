# Расширения

Откройте **Settings → Extensions**, чтобы добавлять в OpenChamber панели, сделанные другими людьми. Расширение — это небольшая страница на правой рейке (rail), рядом со встроенными панелями. Оно может показывать данные из другого сервиса, прикреплять задачу к чату и, если вы разрешите, запускать сессии, отправлять промпты и читать файлы.

Расширения работают в веб-версии OpenChamber, десктопном приложении и мобильном приложении; телефон показывает часть каждого из них, см. [На телефоне](#on-the-phone). VS Code их не загружает. Это не то же самое, что плагины OpenCode.

## Установка расширения

Расширения со значком **Built-in** поставляются вместе с выбранным экземпляром OpenChamber. Они поставляются включёнными и получают объявленные разрешения без отдельного диалога подтверждения. Используйте **Disable** или **Enable** на их карточке; встроенные расширения нельзя удалить или обновить отдельно от приложения. Отключение сохраняет их данные и подключённые учётные записи и остаётся в силе после обновлений приложения.

Настройки их учётных записей находятся в **Settings → Integrations → Built-in integrations**. Сервису всё равно может понадобиться токен API или вход в аккаунт, прежде чем он получит доступ к вашей учётной записи.

1. Откройте **Settings → Extensions**.
2. Вставьте одно из перечисленного в поле **Folder, ZIP, or URL** и выберите **Add**:
   - абсолютный путь к папке на этом компьютере
   - путь к файлу `.zip`
   - https-ссылку на git-репозиторий или zip-файл
   - SSH-адрес Git, например `git@github.com:owner/extension.git`
3. Если расширение запрашивает разрешения, диалог перечислит их. Выберите **Allow and enable** или **Remove**, чтобы убрать расширение.

Ещё можно перетащить `.zip` на поле или выбрать его кнопкой архива рядом; архив загружается на сервер OpenChamber, поэтому это работает и для удалённого экземпляра. В десктопном приложении кнопка папки открывает системный выбор, а перетащенная папка устанавливается по своему пути.

Значок расширения появляется на рейке. Если его нет, см. [Устранение неполадок](/troubleshooting/).

Установка из папки запускается прямо из этой папки, поэтому тот, кто разрабатывает расширение, может править файлы и перезагружать его. Zip или URL сначала копируется в собственную папку данных OpenChamber; исходный файл не трогается.

## Приватные репозитории и Git-идентичности

SSH-установка принимает `git@github.com:owner/extension.git` и `ssh://git@github.com/owner/extension.git` с необязательным `#branch-or-tag`. Выберите Global Identity или сохранённую Git-идентичность в меню отпечатка (fingerprint) рядом с полем установки. Выбор сохраняется для проверки обновлений и самих обновлений; смена ключа этой идентичности применяется при следующей операции.

Global Identity использует конфигурацию Git/SSH и SSH-агент пользователя, который запустил выбранный сервер OpenChamber. На удалённом экземпляре ключ должен быть доступен там. Сначала разблокируйте ключи, защищённые паролем, в SSH-агенте процесса этого сервера. HTTPS-адреса используют учётные данные Git для HTTPS и не переключаются на SSH автоматически. Имена хостов Git должны разрешаться в публичные адреса; локальные SSH-псевдонимы хостов и адреса приватных сетей не поддерживаются.

## Что может делать расширение

Показывать панель и читать, какой проект и какая сессия открыты, можно без разрешения. Всё, что действует от вашего имени, требует разрешения, и весь список вы видите один раз, при установке:

- **Отправлять сообщения в ваших сессиях**: пишет и отправляет промпты модели, а это расходует токены и может запускать инструменты.
- **Доступ к проектам и сессиям**: перечислять зарегистрированные проекты, рабочие деревья и состояния сессий; создавать и открывать сессии в этих проектах. Содержимое разговоров при этом не раскрывается.
- **Читать и записывать файлы проекта**: любой файл в открытом проекте.
- **Читать и записывать файлы вне проекта**: только расположения, перечисленные в диалоге.
- **Использовать вашу Small Model**: разовая генерация текста вне ваших сессий, с моделью из Settings → Sessions → Small Model. Расходует токены.
- **Подключаться к внешнему сервису**: с учётной записью, которую вы подключите в Settings → Integrations.
- **Читать разговор сессии**: только когда вы запускаете действие расширения на этой сессии.
- **Запускать локальный сервис**: отдельная программа с полным доступом вашего пользователя. Разрешайте, только если доверяете автору. Когда расширение хочет получать сведения о том, что происходит в ваших сессиях, эта строка также перечисляет моменты, о которых оно узнаёт: ход завершился, ход завершился сбоем, агент запрашивает разрешение, агент задаёт вопрос. Оно узнаёт о них в каждом проекте, без открытого окна, и получает только идентификаторы: сессию, её проект и элементы, которые вы к ней прикрепили.
- **Читать, что агент говорит в фоне**: финальный ответ каждого хода, вопросы, которые задаёт агент, и то, на что он запрашивает разрешение, в каждом проекте, отправленные локальному сервису расширения. Разрешайте, только если доверяете тому, куда расширение это отправляет.
- **Самостоятельно запускать сессии и отправлять сообщения**: это делает его локальный сервис без открытого окна, а это расходует токены и может запускать инструменты.
- **Добавлять к тому, что читают агенты**: текст в инструкциях ваших сессий и навыки, предлагаемые каждому агенту, пока расширение включено.
- **Добавить плагин в OpenCode**: плагин пакета загружается в ваш OpenCode, пока расширение включено. Код плагина выполняется внутри OpenCode с вашим полным доступом, как локальный сервис, поэтому разрешайте это, только если доверяете автору.
- **Распознавать свои ссылки в чатах**: идентификаторы вроде `DEMO-12` и ссылки на сайт расширения становятся кликабельными в ваших сообщениях чата. Диалог перечисляет, какие именно, и говорит, открывает ли нажатие их в расширении или прикрепляет к вашему сообщению. Ссылки, которые OpenChamber уже знает, например пул-реквесты GitHub и issue в Linear, сохраняют обычное поведение.
- **Показывать метки в боковой панели**: маленькие значки с подсказкой на сессиях и рабочих деревьях, которые называет расширение, например неудачная проверка на ветке. Диалог говорит, открывает ли нажатие панель расширения или ссылку, которую даёт расширение.

Локальный сервис также может работать всё время, пока работает OpenChamber, или просыпаться по расписанию. Диалог говорит об этом в строке **Run a local service**, а ещё говорит, когда то, что вы набираете после `@`, уходит сервису. Расширение может добавлять свои строки в меню `@` и свои блоки в ответы агента. Пауза расширения забирает всё это.

Расширение, которое доставляет ваши уведомления в Slack, Matrix или на собственный сервер, тоже говорит об этом в строке **Run a local service**, строкой, начинающейся с **Delivers your notifications**. Ничего не уходит, пока вы не подключите для него учётную запись в [Settings → Integrations](/integrations/#extension-notification-channels); после этого оно получает то же, что получил бы ваш телефон, а пауза расширения это останавливает.

Когда более новая версия запрашивает больше, чем вы разрешили, карточка показывает **Needs approval** и кнопку **Review permissions**. Пока вы не разрешите новый список, расширение остаётся выключенным.

## Где оно появляется

На сайте есть [карта всех мест, куда расширение может что-то добавить](https://openchamber.dev/extensions/build/).

Расширение может также предложить полноэкранную страницу, например доску задач. Откройте её из его строки в разделе **Pages** боковой панели. Строка появляется, только когда включённое и подтверждённое расширение предлагает страницу. Выбор чата или повторное нажатие на строку возвращает вас назад; перезагрузка, пауза, удаление или смена сервера тоже закрывают страницу. Расширение не может открыть полноэкранную страницу само.

Расширения могут хранить свои данные на подключённом сервере OpenChamber, не кладя файлы в ваш проект. Данные переживают перезагрузки и удаляются вместе с расширением. Доска может отслеживать агентов, работающих в разных проектах или рабочих деревьях, и сама решать, какие у задач статусы.

Кроме панели на рейке, расширение может добавлять что-то в места, которыми вы уже пользуетесь:

- **Меню**: действия на сообщении чата, меню сессии, выделенный текст в сообщении, файл в Files и строки, выделенные в диффе.
- **Поле ввода чата**: меню **+**, слэш-команды вроде `/task ABC-12`, которые прикрепляют что-то, ничего не открывая, и его собственные строки в меню `@`.
- **Чат**: блоки, которые агент рисует в ответе, например график или карточку тикета, а также свой значок, заголовок и раскладку вывода для своих инструментов, как у встроенных инструментов OpenChamber.
- **Work Status**: собственный раздел в панели рядом с чатом.
- **Files**: собственный редактор для типа файлов, например рисунка или таблицы.
- **Боковая панель**: маленькие метки на строках сессий и рабочих деревьев.

Расширение само решает, что из этого предлагать; всё это выключено, пока вы не разрешите расширение. Действия сессий и слэш-команды также появляются в палитре команд (⌘P или Ctrl+P), когда вы ищете их название или название расширения.

Некоторые расширения показывают живую картинку вместо собственной панели: то, в чём агент работает на сервере, например браузер или симулятор. Нажмите на картинку или начните печатать, чтобы взять управление, а на сенсорном экране коснитесь её, и строка состояния покажет **You have control**; браузерные действия агента будут отклоняться, пока вы не нажмёте **Hand back to agent**. Копирование и вставка работают как обычно. Другое устройство, подключённое одновременно, видит, кто управляет, и не может перехватить управление. Такое расширение может добавить свои элементы управления рядом с картинкой, например адресную строку над ней или колонку инструментов сбоку.

## На телефоне

Мобильное приложение и OpenChamber, открытый в браузере телефона, загружают расширения, установленные на сервере, к которому они подключены. **Settings → Extensions** там тоже есть, чтобы добавлять, подтверждать, приостанавливать и удалять их.

То, что OpenChamber сам рисует по данным расширения, показывается на любом телефоне: ссылки в сообщениях чата, раскладка его инструментов в чате, логотипы провайдеров, его строки в меню `@`, метки на строках боковой панели и его карточки учётных записей в **Settings → Integrations**. Нажатие на метку открывает эту строку и вкладку расширения, если его панель сделана для телефона (ниже); иначе показывает текст метки и открывает её ссылку, если она есть.

Эти части расширения тоже показываются без каких-либо дополнительных действий автора:

- блоки в ответах агента
- его раздел во вкладке **Work status** рабочей области
- его редактор файлов, когда вы открываете подходящий файл во вкладке **Files**
- слэш-команды в поле ввода чата
- действия меню, которые работают в фоне и ничего не открывают: в **More actions** сообщения, в листе выделенного текста, в меню сессии по долгому нажатию в списке сессий, при долгом нажатии на строку в **Files** и под полем комментария выделенных строк диффа

Панели нужно больше места, чем есть на телефоне, поэтому она показывается, только когда автор расширения указал, что она сверстана для телефона. Такое расширение получает:

- собственную вкладку в рабочей области, после Work status, Git, Files, Terminal и Project knowledge. **Settings → General → Workspace panel tabs** упорядочивает и скрывает её вместе с остальными.
- свой пункт в меню **+** поля ввода чата
- свои действия меню, которые открывают панель или окно прикрепления

Для любого другого расширения всё это на телефоне не показывается, а его меню содержат только действия, работающие в фоне. Прикреплённый им чип сообщает, что расширение не открывается на телефоне, а его ссылки сохраняют обычный смысл.

У полноэкранной страницы своё правило: она показывается в **More** в списке сессий, когда автор пометил саму страницу как сверстанную для телефона или когда страница использует панель, сверстанную для телефона.

## Расширение с плагином OpenCode

Расширение может поставлять плагин OpenCode, чтобы вы устанавливали одну вещь вместо двух. В его диалоге разрешений есть строка, начинающаяся с **Add a plugin to OpenCode**. Как только вы разрешите, OpenChamber в течение пары секунд добавит плагин в OpenCode, который запускает для вас, без перезапуска; отключение или удаление расширения убирает его тем же путём. В ваш собственный `opencode.json` ничего не записывается, поэтому плагин никогда не переживает расширение и никогда не работает в OpenCode, который вы запускаете в терминале.

Когда OpenChamber не запускал OpenCode, с которым общается, или ваше окружение задаёт собственный `OPENCODE_CONFIG`, конфигурация OpenChamber до этого OpenCode не доходит. Экран расширения говорит об этом и предлагает **Add to global config**. Это записывает папку плагина в вашу глобальную конфигурацию OpenCode: тогда он работает в каждом OpenCode на этом компьютере, включая терминал, остаётся включённым, когда расширение выключено, и управлять им вы можете в **Settings → Plugins**. Если вы удалите расширение, OpenCode покажет эту запись как плагин, который не удалось загрузить, и продолжит работать, пока вы не удалите запись там. OpenCode на другой машине не может загрузить папку с этой; экран говорит об этом.

VS Code не загружает расширения, поэтому OpenCode, который он запускает, никогда не получает плагин. Телефон подключается к серверу OpenChamber, и плагин работает в OpenCode этого сервера. Сессия внутри изолированного пространства запускает собственный OpenCode, который никогда не получает плагин. В корпоративном режиме плагин считается как локальный сервис: расширение устанавливается только из репозитория, который указал ваш администратор.

## Расширение как Git-хост

Расширение может добавить Git-хост рядом с GitHub, GitLab, Gitea, Forgejo и Gerrit. Тогда в его диалоге разрешений есть строка, начинающаяся с **Acts as the Git host**, и в ней назван хост. Там же сказано, что OpenChamber ему отправляет: имена репозиториев, ветки и текст issue и пул-реквестов, который вы пишете.

Как только вы это разрешите, хост получает собственную карточку в **Settings → Integrations**, рядом со встроенными хостами. Подключите там учётную запись токеном и адрес хоста, если карточка его запрашивает. После этого проект, чей remote находится на этом хосте, работает как любой другой: его issue и пул-реквесты есть на доске [Issues и PR](/issues-and-prs/) и в меню **+** чата, его ветки показывают значки пул-реквестов, и из его пул-реквеста можно запустить рабочее дерево. О том, что делает каждая из этих возможностей, см. [Git-хостинги](/github/).

Ваш токен остаётся в OpenChamber. Расширение просит OpenChamber обратиться к хосту за него, и OpenChamber добавляет токен в каждый запрос, только для адреса, который вы подключили. Расширение его никогда не получает.

Пауза расширения убирает хост, пока вы не включите его снова, а ваша учётная запись остаётся. Удаление расширения забывает учётную запись. VS Code не показывает Git-хосты из расширений.

В OpenChamber SDK есть рабочий пример `examples/source-control-provider`, с которого можно начать свой. См. [Создание расширения](/sdk/).

## Расширение как трекер

Расширение может добавить трекер рабочих элементов рядом с Linear: YouTrack, Jira, Plane или собственный трекер. Тогда в его диалоге разрешений есть строка, начинающаяся с **Acts as the tracker**, и в ней он назван. Там же сказано, что OpenChamber ему отправляет: ваши поисковые запросы и открываемые элементы, а также что его просят менять их состояние и публиковать комментарии сессий от вашего имени.

Как только вы это разрешите, трекер получает собственную карточку в **Settings → Integrations** в разделе **Extension accounts**. Подключите там учётную запись: токеном или входом в браузере после того, как введёте client id приложения, которое зарегистрировали в трекере, а сначала адрес сервера, если карточка его запрашивает. После этого его элементы есть везде, где есть элементы Linear: в меню **+** чата и в окне выбора, в New Worktree, среди прикреплённых элементов сессии и в живых состояниях элементов, за которыми вы следите. Вставленная ссылка на один из его элементов распознаётся так же. О том, что делает каждая из этих возможностей, см. [Linear](/integrations/#linear).

Ваши токены остаются в OpenChamber. Расширение просит OpenChamber обратиться к трекеру за него, и OpenChamber добавляет учётные данные в каждый запрос, только для сервера, который вы подключили. Расширение их никогда не получает, и писать туда могут только его вызовы смены состояния и комментариев.

Пауза расширения убирает трекер, пока вы не включите его снова, а ваши учётные записи остаются. Удаление расширения их забывает. VS Code не показывает трекеры; на телефоне элементы трекера видны, а учётные записи подключаются из веб- или десктопного приложения.

В OpenChamber SDK есть рабочий пример `examples/tracker-provider` с поддельным трекером, который можно запустить рядом. См. [Создание расширения](/sdk/).

## Расширение как провайдер использования

Расширение может добавить провайдера использования рядом со встроенными: провайдера, которого OpenChamber сам не читает, или собственного. Тогда в его диалоге разрешений есть строка, начинающаяся с **Reports usage like a built-in provider**, и в ней перечислены провайдеры OpenCode, чьи учётные данные оно читает, например `openrouter`; расширение, которое не перечисляет ни одного, так и говорит.

Как только вы это разрешите, его карточка встаёт после встроенных провайдеров в **Settings → Usage**, с названием и значком расширения, и попадает в лимиты частоты запросов в шапке, в Work Status, во всплывающее окно на телефоне и в трей десктопа, когда вы отметите **Show in Work Status**, как любой встроенный провайдер. При каждом обновлении OpenChamber передаёт расширению учётные данные, которые OpenCode хранит для каждого перечисленного провайдера, и больше ничего; версия, которая перечисляет другого провайдера, снова запрашивает ваше подтверждение. Использование расширение читает само, а OpenChamber рисует его так же, как встроенное.

Пауза расширения убирает карточку, пока вы не включите его снова, а ваши настройки использования для него остаются. Удаление расширения убирает карточку навсегда. VS Code не показывает использование из расширений; на телефоне карточка видна, а расширение настраивается из веб- или десктопного приложения. Сессия внутри изолированного пространства читает использование с собственного сервера этого пространства, на котором расширений нет.

В OpenChamber SDK есть рабочий пример `examples/quota-provider` с поддельным API использования, который можно запустить рядом. См. [Создание расширения](/sdk/).

## Подключение учётной записи

Расширение, которое работает с сервисом, получает карточку в **Settings → Integrations** в разделе **Extension accounts**. В зависимости от сервиса карточка запрашивает токен API, имя пользователя и токен или client id для входа через сервис. Выберите **Connect**; **Disconnect** забывает сохранённый токен. Дополнительные поля, которые объявляет расширение, сохраняются сами, когда вы их покидаете.

Токен остаётся на сервере OpenChamber. Страница расширения его никогда не видит.

## Обновление

Расширения, установленные по git-URL, могут обновляться сами. Открытие **Settings → Extensions** проверяет каждое из них не чаще раза в час; **Check for updates** проверяет сразу. Карточка с более новой версией показывает **Update available** и кнопку **Update**. Обновление сохраняет ваши разрешения, учётные записи и настройки; если новая версия запрашивает больше, диалог подтверждения появляется снова. Установки из папки и zip не обновляются: заменяйте их вручную.

Добавьте `#v1.2.0` или `#stable` к git-URL при установке, чтобы следить за тегом или веткой вместо ветки по умолчанию.

## Пауза и удаление

На каждой карточке есть переключатель **Enabled**. Выключенное состояние оставляет расширение установленным, но скрывает его панель и блокирует его вызовы. **Remove** удаляет из папки данных OpenChamber то, что было установлено из zip или по URL; для установки из папки он только забывает путь, а ваша папка остаётся.
