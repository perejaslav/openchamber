# Git-хосты: issues и pull request

Подключите аккаунт на хосте, где живёт ваш проект, и OpenChamber сможет показывать его issues и pull request, начинать сессию из одного из них и открывать, проверять и сливать pull request за вас. Пять хостов встроены: GitHub, включая GitHub Enterprise; GitLab, включая self-managed GitLab; Gitea; Forgejo, включая Codeberg; и Gerrit. [Расширение](/ru/extensions/#расширение-как-git-хост) может добавить ещё один.

Хост, с которым общается OpenChamber, определяется remote проекта. Проект, чей `origin` находится на gitlab.com, использует ваш аккаунт GitLab для доски, значка pull request на его ветках и панели Git. Remote на псевдониме хоста из `~/.ssh/config`, например `github.com-work`, не сопоставляется ни с одним хостом. Gitea и Forgejo сопоставляются с псевдонимом, чья конфигурация SSH указывает на веб-адрес экземпляра, и с remote по SSH-адресу клонирования экземпляра, как только вы введёте этот адрес в **Настройки → Интеграции**.

Слова следуют за хостом. GitLab говорит merge request, а Gerrit — change.

## Подключение хоста

1. Откройте **Настройки → Интеграции**. У каждого хоста своя карточка.
2. Разверните карточку хоста вашего проекта и войдите:
   - **GitHub**: выберите **Подключить GitHub**, откройте показанную ссылку, введите короткий код и подтвердите. Для GitHub Enterprise выберите **Добавить экземпляр** в разделе **Другие инстансы**, введите адрес сервера и вставьте personal access token.
   - **GitLab**: на gitlab.com войдите по короткому коду, personal access token или через вход `glab`. Для self-managed GitLab добавьте его адрес и вставьте personal access token.
   - **Gitea**: добавьте адрес сервера и вставьте personal access token.
   - **Forgejo**: для Codeberg вставьте personal access token; для другого сервера сначала добавьте его адрес.
   - **Gerrit**: добавьте адрес сервера, затем имя пользователя Gerrit и HTTP-пароль.

Когда подключение выполнено, ваш аккаунт отображается на карточке. Вы можете подключить на хосте несколько аккаунтов и переключаться между ними или отключиться в любой момент. Если на той же машине выполнен вход в `gh` CLI, OpenChamber может использовать его и для GitHub. Области доступа, которые нужны каждому токену, и версии, которые нужны каждому хосту, описаны в [Интеграциях](/ru/integrations/#gitlab-gitea-forgejo-и-gerrit).

Подключённый аккаунт также может быть [Git-идентичностью](/ru/git-identities/) проекта, поэтому коммиты несут его имя, а push по HTTPS используют его токен.

## Начать работу из issue или pull request

Когда вы создаёте [сессию worktree](/ru/worktrees/), её можно начать из issue или pull request хоста проекта:

- выберите **issue**, и OpenChamber назовёт ветку в её честь
- выберите **pull request**, и он переключится на ветку pull request; вы можете включить его дифф, чтобы у агента было всё изменение целиком
- выберите **change в Gerrit**, и он переключится на последний патчсет на ветке с именем `change-<number>`

Новая сессия открывается с уже прикреплённым элементом в поле сообщения. За вас ничего не отправляется: выберите модель и агента, скажите, что нужно сделать, и отправьте.

Доска [Issues и PR](/ru/issues-and-prs/) показывает те же элементы с фильтрами, предпросмотром, комментариями и ревью, и тоже позволяет начинать сессии оттуда.

## Открыть pull request и управлять им

На вкладке **PR** в [панели Git](/ru/git/) можно создать pull request, обновить его, отметить черновик как готовый или выполнить слияние. OpenChamber может написать заголовок и описание из ваших изменений.

- **GitLab**: та же вкладка открывает merge request. При слиянии доступны merge и squash.
- **Gitea** и **Forgejo**: то же, что на GitHub.
- **Gerrit**: change создаётся через push на ревью, и каждый следующий push загружает новый патчсет. См. [Push на ревью в Gerrit](/ru/git/). Слияние — это **Принять**, и оно ждёт, пока change выполнит свои требования к отправке. Ревью — это голоса в метках проекта, например Code-Review и Verified.

## Привязать issue или pull request к сообщению

В поле ввода чата откройте меню **+** и выберите пункт привязки для вашего хоста, например **Привязать задачу или PR из GitHub**, **Привязать задачу или MR из GitLab** или **Привязать изменение из Gerrit**. Выберите один или несколько элементов. Каждый идёт вместе с вашим следующим сообщением как контекст, pull request может принести свой дифф, а панель статуса работы сессии сохраняет ссылку на него. Привязка только добавляет контекст; ваше сообщение говорит, что с ним делать.

У Gerrit нет issues, поэтому там показываются только changes.
