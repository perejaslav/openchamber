# Git-хостинги: issue и пул-реквесты

Подключите аккаунт на хостинге, где живёт ваш проект, — и OpenChamber сможет перечислять его issue и пул-реквесты, начинать сессию с любого из них, а также открывать, проверять и сливать пул-реквесты за вас. Пять хостингов встроены: GitHub, включая GitHub Enterprise; GitLab, включая самостоятельно развёрнутый GitLab; Gitea; Forgejo, включая Codeberg; и Gerrit. [Расширение](/extensions/#an-extension-as-a-git-host) может добавить ещё один.

Хостинг, с которым общается OpenChamber, определяет remote проекта. Проект, чей `origin` находится на gitlab.com, использует ваш аккаунт GitLab для доски, значка пул-реквеста на его ветках и панели Git. Remote на алиасе хоста из `~/.ssh/config`, например `github.com-work`, ни с каким хостингом не сопоставляется. Gitea и Forgejo сопоставляются с алиасом, SSH-конфигурация которого указывает на веб-адрес экземпляра, и с remote на SSH-адресе клонирования экземпляра, как только вы введёте этот адрес в **Settings → Integrations**.

Слова следуют за хостингом. GitLab говорит merge request, а Gerrit — change.

## Подключите хостинг

1. Откройте **Settings → Integrations**. У каждого хостинга своя карточка.
2. Разверните карточку хостинга вашего проекта и войдите:
   - **GitHub**: выберите **Connect GitHub**, откройте показанную ссылку, введите короткий код и подтвердите. Для GitHub Enterprise выберите **Add instance** в разделе **Other instances**, введите адрес вашего сервера и вставьте personal access token.
   - **GitLab**: на gitlab.com войдите по короткому коду, personal access token или через вход `glab`. Для самостоятельно развёрнутого GitLab добавьте его адрес и вставьте personal access token.
   - **Gitea**: добавьте адрес вашего сервера и вставьте personal access token.
   - **Forgejo**: для Codeberg вставьте personal access token; для другого сервера сначала добавьте его адрес.
   - **Gerrit**: добавьте адрес вашего сервера, затем имя пользователя Gerrit и HTTP-пароль.

Когда всё подключено, на карточке виден ваш аккаунт. На одном хостинге можно подключить несколько аккаунтов и переключаться между ними либо отключить их в любой момент. Если `gh` CLI авторизован на той же машине, OpenChamber может использовать его и для GitHub. Какие scope нужны каждому токену и какие версии нужны каждому хостингу — в [Интеграциях](/integrations/#gitlab-gitea-forgejo-and-gerrit).

Подключённый аккаунт может быть и [Git-идентичностью](/git-identities/) проекта, тогда коммиты несут его имя, а push по HTTPS использует его токен.

## Начните работу с issue или пул-реквеста

Создавая [сессию в рабочем дереве](/worktrees/), вы можете начать её с issue или пул-реквеста хостинга проекта:

- выберите **issue** — и OpenChamber назовёт ветку в честь него
- выберите **пул-реквест** — и она переключится на ветку пул-реквеста; можно приложить его дифф, чтобы у агента было всё изменение
- выберите **change в Gerrit** — и она переключится на последний патчсет в ветке с именем `change-<number>`

Новая сессия открывается с уже прикреплённым элементом в поле ввода. За вас ничего не отправляется: выберите модель и агента, скажите, что нужно сделать, и отправьте.

Доска [Issues и PR](/issues-and-prs/) перечисляет те же элементы, с фильтрами, превью, комментариями и ревью, и тоже запускает оттуда сессии.

## Открывайте пул-реквесты и управляйте ими

На вкладке **PR** в [панели Git](/git/) можно создать пул-реквест, обновить его, перевести черновик в готовый или слить. OpenChamber может написать заголовок и описание по вашим изменениям.

- **GitLab**: та же вкладка открывает merge request. При слиянии предлагаются merge и squash.
- **Gitea** и **Forgejo**: то же, что на GitHub.
- **Gerrit**: change создаётся push-ем на ревью, и каждый следующий push загружает новый патчсет. См. [Push на ревью в Gerrit](/git/#push-for-review-on-gerrit). Слияние — это **Submit**, и оно ждёт, пока change выполнит свои требования к отправке. Ревью — это голоса по меткам проекта, например Code-Review и Verified.

## Привяжите issue или пул-реквест к сообщению

В поле ввода чата откройте меню **+** и выберите пункт связи для вашего хостинга, например **Link GitHub Issue or PR**, **Link GitLab Issue or MR** или **Link Gerrit change**. Выберите один или несколько элементов. Каждый уходит с вашим следующим сообщением как контекст, пул-реквест может принести свой дифф, а панель состояния работы сессии хранит ссылку на него. Прикрепление только добавляет контекст; что с ним делать, говорит ваше сообщение.

Можно также вставить в сообщение ссылку на issue, пул-реквест или issue в Linear. Она превращается в чип с номером и заголовком прямо там, где вы вставили её, и уходит с сообщением так же. Ссылка, которую приложение не может прочитать, остаётся обычным текстом, а уведомление объясняет почему.

У Gerrit нет issue, поэтому там показываются только change.
