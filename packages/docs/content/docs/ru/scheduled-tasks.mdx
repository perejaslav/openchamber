# Запланированные задачи

Запланированная задача запускает промпт за вас по расписанию — например, ежедневное «подведи итог вчерашних изменений» или еженедельная уборка. Когда она срабатывает, OpenChamber запускает новую сессию и отправляет промпт сам. Откройте планировщик кнопкой в верхней части боковой панели сессий.

## Создание задачи

1. Откройте диалог запланированных задач из боковой панели сессий.
2. Добавьте задачу и дайте ей название.
3. Выберите, когда она запускается:
   - **daily** — в один или несколько моментов каждый день
   - **weekly** — в выбранные дни недели и время
   - **once** — одна дата и время
   - **cron** — произвольное cron-выражение
4. Задайте, что она делает: промпт для отправки, а также провайдера, модель и агента. Промпт может быть слэш-командой, например `/review`.
5. Сохраните и убедитесь, что задача включена.

Любую задачу можно запустить сразу кнопкой **run now**, чтобы проверить, что она делает то, что вы ожидаете.

Отметьте **Run as goal**, чтобы запуск доводил свой промпт до завершения, а не останавливался после одного ответа, — см. [Цели сессии](/session-goals/).

## Циклы: запланированные задачи как файлы markdown

**Цикл** (loop) — это запланированная задача, определённая как переносимый файл markdown, который можно закоммитить в репозиторий. Положите файл в `.agents/loops/` и откройте список Scheduled Tasks, чтобы синхронизировать его, — перезапуск сервера не нужен:

```markdown
---
name: daily-digest
schedule: "0 9 * * *"
enabled: true
model: anthropic/claude-sonnet-4-5
agent: plan
timezone: Europe/Kyiv
---
Summarize repository changes since yesterday and post the digest.
```

### Где лежат файлы

- **Область проекта** — `.agents/loops/*.md` в папке проекта или в любой родительской папке вплоть до корня рабочего дерева git.
- **Область пользователя** — `~/.agents/loops/*.md` применяется к каждому открытому проекту.

Если цикл проекта и цикл пользователя имеют одинаковое название, побеждает цикл проекта.

### Поля

| Поле | Значение |
|---|---|
| `name` | Название задачи (обязательно, максимум 80 символов). |
| `schedule` | Cron-выражение (обязательно) — файлы циклов поддерживают только cron. |
| `enabled` | Поставьте `true`, чтобы запускать. Циклы **по умолчанию выключены**, поэтому коммит файла никогда не запускает задачу сам по себе. Цикл, пришедший из репозитория, также ждёт, пока вы включите его в Scheduled Tasks на своей машине, и снова ждёт после изменения его расписания, модели или промпта. Циклам в `~/.agents/loops` достаточно одного `true`. |
| `model` | `provider/model` (обязательно), например `anthropic/claude-sonnet-4-5`. |
| `agent` | Агент для использования (необязательно). |
| `timezone` | Часовой пояс IANA (необязательно, по умолчанию зона сервера). |
| body | Промпт выполнения (обязательно). Может быть слэш-командой, например `/review src/`. |

### Как ведут себя циклы

- **Файл главнее**, пока он существует. **Edit** открывает его во встроенном редакторе файлов, переключатель включения обновляет его frontmatter, а удаление задачи удаляет файл markdown после подтверждения. **Run now** остаётся доступным.
- Состояние выполнения (последний запуск, следующий запуск, статус) живёт в конфигурации проекта и никогда не записывается обратно в файл markdown.
- Переименование поля `name` переименовывает задачу на месте. Если файл цикла временно не разбирается (из-за правки, конфликта слияния), его задача сохраняется с последним рабочим определением, пока файл не исправят.
- Расписания `daily`/`weekly`/`once` и настройки цели остаются только в интерфейсе; файлы циклов всегда cron.

## Как выглядит успех

После запуска задача показывает, когда она запускалась в последний раз, удалась ли она, и ссылку на созданную сессию. Если запуск не удался, ошибка тоже показывается там.

## Что учитывать

Задачи срабатывают, только пока работает сервер OpenChamber. Если вы его закроете, запланированные запуски приостанавливаются, пока он не поднимется снова.
