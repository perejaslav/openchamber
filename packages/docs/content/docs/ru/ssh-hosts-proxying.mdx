# SSH-хосты и проксирование

Используйте **Settings → Remote Instances** в десктопном приложении, чтобы импортировать сохранённые SSH-хосты, подключиться к удалённой машине и открыть дополнительные порты через то же SSH-соединение.

> SSH-хосты и SSH-проксирование доступны **только в десктопе**. Они используют SSH-клиент на вашем компьютере.

## Импорт SSH-хоста

OpenChamber читает хосты из вашего локального конфига SSH — того же места, которое используют команды вроде `ssh work-server`.

1. Откройте **Settings → Remote Instances**.
2. Выберите хост в разделе **Saved SSH hosts**.
3. Если хост задан шаблоном, введите реальный адрес назначения, например `deploy@app.example.com`.
4. Сохраните и подключитесь.

OpenChamber создаёт удалённый экземпляр с помощью этой SSH-команды. Когда он достигает состояния **ready**, в десктопном приложении открывается интерфейс удалённого OpenChamber.

## Добавление дополнительных пробросов портов

У каждого удалённого экземпляра есть раздел **Port Forwards**. Он нужен, когда что-то по одну сторону SSH-соединения должно достучаться до порта по другую сторону.

OpenChamber поддерживает три типа проброса:

- **Local (-L)** — открывает порт на вашем компьютере, который подключается к чему-то на удалённой машине.
- **Remote (-R)** — открывает порт на удалённой машине, который подключается обратно к вашему компьютеру.
- **Dynamic (-D)** — открывает локальный SOCKS-прокси через SSH-соединение.

Для большинства предпросмотров приложений и дашбордов, работающих на удалённой машине, используйте **Local (-L)**.

## Использование SOCKS-прокси

Выберите **Dynamic (-D)**, когда хотите, чтобы другие инструменты на вашем компьютере работали через удалённую машину. OpenChamber открывает локальный порт SOCKS-прокси для этого SSH-соединения.

Когда соединение готово, скопируйте локальный адрес прокси из строки проброса или используйте его. Настройте браузер или инструмент на использование этого адреса как SOCKS5-прокси.

## Держите это закрытым

Используйте `127.0.0.1` или `localhost` как локальный адрес привязки, если только вы намеренно не хотите, чтобы другие устройства в вашей сети могли достучаться до проброшенного порта.
