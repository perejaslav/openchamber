# Сервер OpenCode

OpenChamber работает поверх сервера OpenCode. По умолчанию он запускает его для вас, так что вам ничего делать не нужно. Эта страница нужна только если вы хотите направить OpenChamber на сервер, который уже запущен, или управлять тем, который он запускает.

## Как OpenChamber находит сервер

Когда OpenChamber запускается, он ищет сервер в таком порядке:

1. повторно использует сервер, который уже запустил
2. подключается к внешнему серверу, если задана одна из переменных `OPENCODE_HOST`, `OPENCODE_PORT` или `OPENCODE_SKIP_START`
3. подключается к общему локальному демону `opencode serve --service`, если включён параметр **Использовать общий сервис OpenCode**
4. иначе запускает и обслуживает собственный

По умолчанию OpenChamber управляет своим сервером на выделенном порту. Порт может измениться после перезапуска. OpenChamber не подключается автоматически к другому серверу OpenCode на порту `4096`.

## Использование общего сервиса OpenCode

Если вы также пользуетесь CLI или TUI OpenCode, можно подключить OpenChamber к той же локальной фоновой службе `opencode serve --service` без переменных окружения.

1. Откройте **Настройки → Общие → Сервер OpenCode**.
2. Включите **Использовать общий сервис OpenCode**.

OpenChamber считывает адрес и пароль работающей службы из файла `service.json` OpenCode и переключается на неё. Если служба не запущена, но установлен CLI OpenCode, OpenChamber сам запускает `opencode serve --service`. В корпоративном режиме он подключается только к уже работающей локальной службе и не запускает её.

Отключение этого параметра возвращает OpenChamber на собственный приватный сервер OpenCode, не останавливая общую службу.

После `opencode update` работающая служба использует прежнюю версию до перезапуска. Если при подключении OpenChamber обнаружит, что установленная версия OpenCode новее работающей службы, он перезапустит её, кроме корпоративного режима. В уведомлении об обновлении OpenCode выберите **Обновить**, чтобы выполнить `opencode upgrade`, а затем **Перезагрузить OpenCode**, чтобы перезапустить службу уже на новой версии.

## Включение инструментов OpenChamber на внешнем локальном сервере

Когда OpenChamber подключён к локальному внешнему серверу (через **Использовать общий сервис OpenCode** либо `OPENCODE_HOST` и `OPENCODE_SKIP_START`), он не может внедрить свои управляемые плагины при запуске сервера. Вместо этого он предоставляет одну папку с плагином, которую нужно зарегистрировать в глобальной конфигурации OpenCode:

1. Откройте **Настройки → Общие → Сервер OpenCode**.
2. В информационном блоке выберите **Добавить в конфигурацию OpenCode**.

Если глобальный файл `opencode.json` доступен только для чтения или управляется организацией, выберите **Копировать путь** в том же блоке и добавьте путь к папке в список `plugins` вашей управляемой конфигурации OpenCode.

После регистрации инструменты OpenChamber, переключение моделей при исчерпании лимитов и названия сессий начинают работать автоматически, пока OpenChamber открыт. Встроенные инструменты OpenCode, дублирующие его функции (например, браузер и автоматизация), на это время скрываются. После закрытия OpenChamber плагин отключается, и OpenCode возвращает обычные встроенные инструменты и промпты.

Инструменты OpenChamber требуют локального сервера OpenCode на той же машине и недоступны при подключении к удалённому серверу.

## Подключение к серверу, который вы уже запускаете

Задайте это перед запуском OpenChamber:

```bash
OPENCODE_HOST=http://localhost:4096 OPENCODE_SKIP_START=true openchamber
```

- `OPENCODE_HOST` — полный адрес вашего сервера OpenCode, включая порт (значение вида `http://localhost:4096`). В конце не должно быть пути.
- `OPENCODE_SKIP_START=true` — говорит OpenChamber не запускать собственный сервер.

Если вам нужно изменить только порт, задайте `OPENCODE_PORT` вместо `OPENCODE_HOST`.

Если в `OPENCODE_HOST` нет порта или есть путь, OpenChamber игнорирует его и возвращается к запуску собственного сервера. Следите за журналами запуска — там будет предупреждение `[config]`, если ожидаемое подключение не произошло.

## Общий сервер для OpenChamber и VS Code

Десктопное приложение и расширение VS Code обычно запускают разные серверы OpenCode. В Windows некоторые плагины, включая `opencode-mem`, не могут открывать одну базу данных из двух процессов. Подключите оба приложения к одному серверу, чтобы избежать конфликта.

Для общего сервера нужна версия OpenCode 2.2.4 или новее. Со старой версией оба приложения остановятся на экране «Обновите OpenCode».

1. Закройте OpenChamber Desktop и VS Code, чтобы остановились их управляемые серверы. Остановите и другие серверы OpenCode, использующие данные того же плагина, например запущенные в терминале. OpenCode TUI тоже запускает фоновую службу, которая остаётся после его закрытия. Проверьте её через `opencode service status` и остановите командой `opencode service stop`.
2. Запустите один сервер OpenCode и оставьте его работать:

   ```bash
   opencode serve --port 4096
   ```

   OpenCode напечатает адрес в строке `server listening on`. Используйте его там, где далее указан `http://localhost:4096`.

   Если не заданы ни `OPENCODE_PASSWORD`, ни `OPENCODE_SERVER_PASSWORD`, OpenCode выведет сгенерированный `server password`. Если одна из переменных задана, пароль не печатается и сервер использует указанное значение. Не разглашайте пароль; он понадобится в следующих шагах.

3. Запустите OpenChamber Desktop с `OPENCODE_HOST=http://localhost:4096`, `OPENCODE_SKIP_START=true` и `OPENCODE_PASSWORD`, равным паролю сервера. В Windows запустите приложение из PowerShell:

   ```powershell
   $env:OPENCODE_HOST = 'http://localhost:4096'
   $env:OPENCODE_SKIP_START = 'true'
   $password = Read-Host 'OpenCode server password' -AsSecureString
   $env:OPENCODE_PASSWORD = [System.Net.NetworkCredential]::new('', $password).Password
   & "$env:LOCALAPPDATA\Programs\@openchamberelectron\OpenChamber.exe"
   ```

   Если приложение установлено в другом месте, укажите путь к своему `OpenChamber.exe`.

4. Из того же окна PowerShell запустите VS Code командой `code`. В настройках VS Code задайте `openchamber.apiUrl` равным `http://localhost:4096`, затем выполните **Developer: Reload Window**.

Теперь оба приложения используют сервер по этому адресу. Он должен работать, пока вы используете хотя бы одно из них. Каждый раз запускайте оба приложения из PowerShell, как в шагах 3 и 4: при открытии из меню «Пуск» десктопное приложение снова запускает собственный сервер, а у VS Code нет пароля общего сервера. Если сервер перезапущен без заданного пароля, он выдаст новый — используйте его. Прежнее имя `OPENCODE_SERVER_PASSWORD` также работает, если `OPENCODE_PASSWORD` не задана. Не открывайте такой сервер для недоверенной сети. Эта схема не работает с автоматически управляемым сервером десктопного приложения, поскольку его порт и пароль меняются.

Внешний сервер не получает управляемые плагины OpenChamber автоматически. См. [Включение инструментов OpenChamber на внешнем локальном сервере](#включение-инструментов-openchamber-на-внешнем-локальном-сервере), чтобы зарегистрировать плагин в глобальной конфигурации OpenCode. Если приложения не могут подключиться, см. [Подключение к OpenCode](/ru/troubleshooting/opencode-connection/).

## Управление сервером из CLI

```bash
openchamber status
openchamber logs
openchamber restart
openchamber stop
```

`openchamber` сам по себе запускает сервер в фоне. Добавьте `--foreground`, чтобы оставить его привязанным к вашему терминалу.

## Запуск OpenChamber при входе в систему

Используйте `startup enable`, чтобы установить нативный пользовательский сервис. OpenChamber использует `launchd` на macOS, `systemd --user` на Linux и Task Scheduler на Windows.

```bash
openchamber startup enable
openchamber startup status
openchamber startup disable
```

Чтобы защитить UI, задайте пароль при включении сервиса:

```bash
OPENCHAMBER_UI_PASSWORD='secret' openchamber startup enable
```

Для headless-сервера, который стартует при входе и предназначен для десктопных или мобильных клиентов, добавьте `--api-only` и доступный хост:

```bash
openchamber startup enable --port 3000 --api-only --host 0.0.0.0 --ui-password secret
```

`startup enable` сохраняет снимок текущего окружения в сервисе, поэтому он ведёт себя ближе к запуску `openchamber` из той же оболочки. Так сохраняются токены провайдеров, `PATH`, настройки SSH-агента и другие CLI-переменные авторизации и конфигурации. Переменные, которые работающий OpenChamber добавил в эту оболочку, — например, собственные настройки десктопного приложения или пароль управляемого OpenCode, — не сохраняются. Используйте `--no-env-snapshot`, если хотите минимальное окружение сервиса.

Сервис запуска также запоминает `--port`, `--host`, `--ui-password` и `--api-only`. Перезапуск из CLI и перезапуск при обновлении повторно используют эти сохранённые настройки.

Чтобы создать ссылку подключения для другого приложения OpenChamber, используйте:

```bash
openchamber connect-url --port 3000 --server http://your-host:3000 --qr
```

Запустите `openchamber connect-url --help`, чтобы увидеть все параметры ссылки, включая `--name`, `--lan`, `--server`, `--api-only`, `--ui-password` и `--qr`.

Туннелями для этого запущенного сервиса по-прежнему можно управлять отдельно:

```bash
openchamber tunnel start --port 3000
openchamber tunnel stop --port 3000
```

Остановка туннеля не перезапускает сервис или приложение.

## «OpenCode перезапускается»

Пока сервер запускается или перезапускается, OpenChamber показывает состояние «OpenCode перезапускается» и приостанавливает запросы, пока он не будет готов. Это нормально сразу после запуска или перезапуска. Если это состояние не проходит, см. [Подключение к OpenCode](/ru/troubleshooting/opencode-connection/).
