# Сервер OpenCode

OpenChamber работает поверх сервера OpenCode. По умолчанию он запускает сервер для вас, так что делать ничего не нужно. Эта страница нужна, только если вы хотите указать OpenChamber на сервер, который уже запускаете сами, или управлять тем, который он запускает.

## Как OpenChamber находит сервер

При запуске OpenChamber ищет сервер в таком порядке:

1. использует сервер, который уже запустил сам
2. подключается к внешнему, если вы настроили `OPENCODE_HOST`, `OPENCODE_PORT` или `OPENCODE_SKIP_START`
3. подключается к общему локальному демону `opencode serve --service`, если включён пункт **Use shared OpenCode service**
4. иначе запускает и обслуживает собственный

По умолчанию OpenChamber управляет своим сервером на выделенном порту. Порт может измениться после перезапуска. К другому серверу OpenCode на порту `4096` он сам не подключается.

## Общий сервис OpenCode

Если вы также пользуетесь CLI или TUI OpenCode, можете направить OpenChamber на тот же локальный фоновый сервис `opencode serve --service`, не задавая переменные окружения.

1. Откройте **Settings → General → OpenCode Server**.
2. Включите **Use shared OpenCode service**.

OpenChamber читает адрес и пароль работающего сервиса из `service.json` OpenCode и переключается на него. Если сервис не запущен, а бинарный файл CLI OpenCode установлен, OpenChamber запустит `opencode serve --service` за вас. В корпоративном режиме OpenChamber подключается только к уже запущенному локальному сервису и сам его не запускает.

Если выключить эту опцию, OpenChamber вернётся к своему отдельному серверу OpenCode, не останавливая общий сервис.

После `opencode update` работающий сервис остаётся на старой версии до перезапуска. Когда OpenChamber подключается и находит установленный релиз OpenCode новее работающего сервиса, он перезапускает сервис — кроме корпоративного режима. В уведомлении об обновлении OpenCode выберите **Update**, чтобы выполнить `opencode upgrade`, затем **Reload OpenCode**, чтобы перезапустить сервис на новой версии.

## Включение инструментов OpenChamber на внешнем локальном сервере

Когда OpenChamber подключается к локальному внешнему серверу (через **Use shared OpenCode service** или через `OPENCODE_HOST` и `OPENCODE_SKIP_START`), он не может внедрить свои управляемые плагины при старте сервера. Вместо этого он предоставляет одну папку плагина, которую вы регистрируете в глобальной конфигурации OpenCode:

1. Откройте **Settings → General → OpenCode Server**.
2. В информационном баннере нажмите **Add to OpenCode config**.

Если ваш глобальный `opencode.json` доступен только для чтения или управляется вашей организацией, нажмите **Copy path** в том же баннере и добавьте путь к этой папке в список `plugins` в управляемой конфигурации OpenCode.

После регистрации инструменты OpenChamber, переключение при лимитах и заголовки сессий включаются автоматически, пока OpenChamber запущен, и скрывают пересекающиеся встроенные инструменты OpenCode (например, его встроенные инструменты браузера и автоматизации), пока OpenChamber открыт. Когда OpenChamber закрывается, плагин отключается, и OpenCode возвращается к своим стандартным встроенным инструментам и промптам.

Инструменты OpenChamber требуют локального сервера OpenCode на той же машине и недоступны при подключении к удалённому серверу.

## Подключение к серверу, который вы уже запускаете

Задайте это до запуска OpenChamber:

```bash
OPENCODE_HOST=http://localhost:4096 OPENCODE_SKIP_START=true openchamber
```

- `OPENCODE_HOST` — полный адрес вашего сервера OpenCode, включая порт (например, `http://localhost:4096`). В конце не должно быть пути.
- `OPENCODE_SKIP_START=true` — сообщает OpenChamber, что не нужно запускать собственный сервер.

Если нужно изменить только порт, задайте `OPENCODE_PORT` вместо `OPENCODE_HOST`.

Если в `OPENCODE_HOST` нет порта или есть путь, OpenChamber игнорирует его и запускает собственный сервер. Следите за логами запуска: там будет предупреждение `[config]`, если подключение, которого вы ждали, не произошло.

## Один сервер на VS Code

Десктопное приложение и расширение VS Code обычно запускают отдельные серверы OpenCode. В Windows некоторые плагины, включая `opencode-mem`, не могут открыть одну и ту же базу данных в двух процессах. Направьте оба приложения на один сервер, чтобы избежать этого конфликта.

Общему серверу нужен OpenCode 2.2.4 или новее. На более старой версии оба приложения остановятся на экране «update OpenCode».

1. Закройте OpenChamber Desktop и VS Code, чтобы их управляемые серверы остановились. Остановите и любой другой сервер OpenCode, который использует те же данные плагинов, например запущенный в терминале. TUI OpenCode тоже запускает фоновый сервер, который продолжает работать после закрытия. Проверьте его командой `opencode service status` и остановите командой `opencode service stop`.
2. Запустите один сервер OpenCode и оставьте его работать:

   ```bash
   opencode serve --port 4096
   ```

   OpenCode печатает адрес, на котором слушает, в строке `server listening on`. Используйте этот адрес везде, где в шагах ниже сказано `http://localhost:4096`.

   Если не заданы ни `OPENCODE_PASSWORD`, ни `OPENCODE_SERVER_PASSWORD`, OpenCode также печатает сгенерированный `server password`. Если задана одна из них, пароль не печатается, и сервер использует заданный вами. Держите пароль в тайне и используйте его в следующих шагах.

3. Запустите OpenChamber Desktop с `OPENCODE_HOST=http://localhost:4096`, `OPENCODE_SKIP_START=true` и `OPENCODE_PASSWORD`, равным паролю сервера. В Windows запускайте его из окна PowerShell:

   ```powershell
   $env:OPENCODE_HOST = 'http://localhost:4096'
   $env:OPENCODE_SKIP_START = 'true'
   $password = Read-Host 'OpenCode server password' -AsSecureString
   $env:OPENCODE_PASSWORD = [System.Net.NetworkCredential]::new('', $password).Password
   & "$env:LOCALAPPDATA\Programs\@openchamberelectron\OpenChamber.exe"
   ```

   Если вы установили Desktop в другое место, используйте путь к своему `OpenChamber.exe`.

4. Запустите VS Code из того же окна PowerShell командой `code`. В настройках VS Code задайте `openchamber.apiUrl` как `http://localhost:4096`, затем выполните **Developer: Reload Window**.

Оба приложения теперь используют сервер по этому адресу. Держите его запущенным, пока пользуетесь любым из приложений. Каждый раз запускайте оба приложения из PowerShell, как в шагах 3 и 4: если открыть Desktop из меню «Пуск», он снова запустит собственный сервер, а у VS Code не будет пароля для общего. Если вы перезапустите сервер без заданного пароля, он напечатает новый — используйте его. Старое имя `OPENCODE_SERVER_PASSWORD` тоже работает, когда `OPENCODE_PASSWORD` не задана. Не выставляйте сервер в недоверенную сеть. Эту схему нельзя использовать с автоматически управляемым сервером Desktop, у которого меняются порт и пароль.

Внешний сервер не получает управляемые плагины OpenChamber автоматически; см. [Включение инструментов OpenChamber на внешнем локальном сервере](#enable-openchamber-tools-on-an-external-local-server), чтобы зарегистрировать плагин OpenChamber в глобальной конфигурации OpenCode. См. [Подключение к OpenCode](/troubleshooting/opencode-connection/), если какое-то из приложений не может подключиться.

## Управление сервером из CLI

```bash
openchamber status
openchamber logs
openchamber restart
openchamber stop
```

`openchamber` сам по себе запускает сервер в фоне. Добавьте `--foreground`, чтобы оставить его привязанным к терминалу.

## Запуск OpenChamber при входе в систему

Используйте `startup enable`, чтобы установить нативный пользовательский сервис. OpenChamber использует `launchd` в macOS, `systemd --user` в Linux и планировщик задач в Windows.

```bash
openchamber startup enable
openchamber startup status
openchamber startup disable
```

Чтобы защитить интерфейс, задайте пароль при включении сервиса:

```bash
OPENCHAMBER_UI_PASSWORD='secret' openchamber startup enable
```

Для headless-сервера, который запускается при входе и предназначен для десктопных или мобильных клиентов, добавьте `--api-only` и доступный хост:

```bash
openchamber startup enable --port 3000 --api-only --host 0.0.0.0 --ui-password secret
```

`startup enable` сохраняет снимок текущего окружения в сервис, чтобы он вёл себя ближе к запуску `openchamber` из той же оболочки. Так остаются доступны токены провайдеров, `PATH`, настройки SSH-агента и другие переменные авторизации и конфигурации CLI. Переменные, которые работающий OpenChamber добавил в эту оболочку, — например, собственные настройки десктопного приложения или пароль управляемого OpenCode, — не включаются. Используйте `--no-env-snapshot`, если нужен минимальный набор переменных окружения сервиса.

Сервис автозапуска запоминает `--port`, `--host`, `--ui-password` и `--api-only`. Перезапуск из CLI и перезапуск при обновлении используют эти сохранённые настройки.

Чтобы создать ссылку подключения для другого приложения OpenChamber, используйте:

```bash
openchamber connect-url --port 3000 --server http://your-host:3000 --qr
```

Запустите `openchamber connect-url --help`, чтобы увидеть все параметры ссылки, включая `--name`, `--lan`, `--server`, `--api-only`, `--ui-password` и `--qr`.

Вы по-прежнему можете независимо управлять туннелями для этого работающего сервиса:

```bash
openchamber tunnel start --port 3000
openchamber tunnel stop --port 3000
```

Остановка туннеля не перезапускает сервис или приложение.

## «OpenCode is restarting»

Пока сервер запускается или перезапускается, OpenChamber показывает состояние «OpenCode is restarting» и приостанавливает запросы до готовности. Это нормально сразу после запуска или перезапуска. Если это состояние не проходит, см. [Подключение к OpenCode](/troubleshooting/opencode-connection/).
