# Проекты

Проект — это папка на вашем компьютере, за которой следит OpenChamber, обычно одна кодовая база. Переключение проекта переключает папку, в которой работает агент, вместе с сессиями и настройками этого проекта.

## Добавьте проект

Добавить проект можно из нескольких мест:

- пункт **Add project** в палитре команд
- кнопка **+** вверху боковой панели сессий
- обозреватель папок, когда вы выбираете каталог

Укажите папку — и OpenChamber её запомнит. Название берётся из папки; позже его можно изменить.

## Переключайте проекты

Выберите проект в боковой панели, чтобы сделать его активным. Всё — сессии, git, заметки — следует за открытым проектом.

## Сделайте проект узнаваемым

Откройте **Settings → Projects**, чтобы задать проекту своё название, цвет или иконку. OpenChamber пытается найти иконку автоматически — см. [Иконки проектов](/project-icons/).

> В VS Code OpenChamber всегда использует открытую папку как единственный проект, поэтому добавлять или переключать там нечего. Страница настроек Projects там скрыта.

## Группируйте сессии по папкам

В боковой панели щёлкните сессию правой кнопкой и выберите **Move to folder**, чтобы положить её в папку, или **New folder...**, чтобы создать папку. Папка принадлежит корню проекта или одному рабочему дереву, и в строке папки есть кнопки переименования и удаления. Папка корня проекта может содержать и целые рабочие деревья: откройте меню рабочего дерева и выберите **Move to folder**. Удаление папки сохраняет то, что в ней было; содержимое возвращается в проект.

Папки хранятся на сервере OpenChamber, поэтому всё, что подключено к тому же серверу, видит одни и те же папки: другой компьютер, вошедший на него, веб-приложение и телефон. Изменение на одном появляется на других в течение секунды, без перезагрузки. У каждого сервера свои папки. То, какие папки свёрнуты, остаётся на каждом устройстве.

Телефон показывает папки, включая рабочие деревья в них, но не может их менять. Переносите сессии на десктопе или в веб-приложении.

Когда устройство впервые подключается после обновления с версии, которая хранила папки на каждом устройстве, его папки добавляются к серверным. Папка с тем же названием в том же месте, что уже есть на сервере, присоединяется к ней, и её сессии идут вместе с ней; ничего не теряется. Сессия, которую сервер уже разложил, остаётся в папке сервера.

Удаление сессии убирает её из папки, а закрытие проекта удаляет его папки. В VS Code папки остаются в расширении и не разделяются.

## Окружение проекта

Когда инструменты проекта приходят из direnv, devenv или оболочки Nix, Git-хуки, терминал и [действия проекта](/project-actions/) не находят их сами. Откройте **Settings → Projects**, выберите проект и в разделе **Environment**:

- добавьте переменные, нужные только этому проекту
- или задайте **environment command**, которая их выводит, например `direnv export json` или `devenv print-dev-env --json`

Команда выполняется в папке проекта, а для рабочего дерева — в его собственной папке. Она выполняется снова, когда вы делаете коммит, открываете терминал или запускаете действие, если с последнего запуска прошло несколько минут, а **Run again** запускает её сразу. Открытый проект сам по себе её не запускает. Под полем видно, сколько переменных добавил последний запуск или почему он не удался. Неудачный запуск ничего не добавляет, и Git с терминалом продолжают работать без него.

Эти переменные попадают в Git, терминал и действия проекта поверх переменных из **Settings → General → Environment variables** (см. [Переменные окружения](/environment/#variables-for-opencode-git-and-the-terminal)). OpenCode обслуживает все проекты из одного процесса, поэтому переменные проекта до него не доходят: то, что нужно агенту, кладите в общий список.

Команда принадлежит только вам. Она не читается из репозитория, поэтому клонированный репозиторий не может заставить OpenChamber что-либо выполнить.
