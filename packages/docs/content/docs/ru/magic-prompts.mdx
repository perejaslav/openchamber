# Магические промпты

OpenChamber использует встроенные промпты за кулисами каждый раз, когда что-то делает автоматически, — пишет сообщение коммита, готовит пул-реквест, проверяет issue, разрешает конфликт, делает сводку сессии. Магические промпты — это место, где вы читаете и переписываете эти промпты. Откройте его в **Settings → Magic Prompts**.

Для обычной работы эта страница не нужна. Обращайтесь к ней, когда хотите, чтобы процесс вёл себя иначе, — скажем, сообщения коммитов в определённом стиле.

## Редактирование промпта

1. Откройте **Settings → Magic Prompts**.
2. Выберите промпт из групп в боковой панели — Git, Planning и Session.
3. Отредактируйте текст и сохраните.

У некоторых промптов есть видимая часть (сообщение, которое вы увидите) и часть с инструкциями (скрытые указания для агента). В промптах могут быть `{{placeholders}}`, которые заполняет OpenChamber, например дифф или заголовок issue, — оставляйте их на месте.

## Сброс

Передумали? У каждого промпта есть **reset to default**, а ещё есть **reset all**, если хотите начать заново везде.

## Промпты проекта

У промпта может быть и переопределение для одного проекта. OpenChamber использует переопределение проекта, если оно есть, иначе ваше глобальное переопределение, иначе встроенный текст. Сохранённое переопределение учитывается, даже когда оно пустое.

Чтобы добавить его, выберите проект в селекторе в верхней части боковой панели, затем выберите **Project** в **Scope**. Нажмите **Save** под каждым блоком, который меняете. Кнопки сброса меняют только открытую область. В **Project** пункты **Remove project override** и **Remove all project overrides** возвращают ваше глобальное переопределение или встроенный текст. Сохранение встроенного текста в **Global** удаляет ваше глобальное переопределение. В **Project** этот текст остаётся сохранённым, поэтому проект сохраняет встроенный текст, даже когда ваше глобальное переопределение говорит другое.

Переопределения проекта сохраняются в ключе `magicPrompts` файла `.openchamber/project.json` в рабочей копии (checkout) проекта, в том же файле, что и [конфигурация в репозитории](/repository-config/). Закоммитьте его, чтобы поделиться промптами с командой. Глобальные переопределения остаются в `magic-prompts.json` в папке данных сервера.

Рабочее дерево использует промпты проекта из его основной рабочей копии, если вы не добавили это рабочее дерево как отдельный проект. Чат без проекта, папка, не принадлежащая ни одному проекту, и работа в изолированном пространстве используют только глобальные промпты. В расширении VS Code нет страницы Magic Prompts. Там вы редактируете файлы вручную, а глобальный файл всегда `~/.config/openchamber/magic-prompts.json`.

Когда файл проекта не удаётся прочитать, например потому что он не является корректным JSON, процессы, которым он нужен, останавливаются с ошибкой и не переходят на встроенный текст. Settings показывает причину и кнопку **Retry**. Отсутствующий файл проекта не является ошибкой, и тогда проект наследует все промпты.

## Где используется каждый промпт

У каждого промпта ниже указано, где он выполняется и какой триггер его запускает. Проверьте триггер перед редактированием, чтобы понимать, какой процесс вы меняете.

### Git

| Промпт | Где выполняется | Когда срабатывает |
| --- | --- | --- |
| Генерация коммита | Кнопка генерации в поле коммита в представлении git и экран Changes на мобильном | Вы генерируете сообщение коммита. Подставляются выбранные файлы и темы недавних коммитов ветки, чтобы тема соответствовала стилю вашего репозитория. |
| Генерация PR | Форма создания пул-реквеста во вкладке PR представления git | Вы генерируете заголовок и описание PR. Подставляются базовая и головная ветки, коммиты и изменённые файлы между ними, ваш дополнительный контекст и шаблон PR репозитория, если он есть. |
| Walkthrough | Панель разбора изменений Changes | Вы генерируете разбор. По умолчанию пусто. Всё, что вы напишете, добавляется к промпту разбора как ваши пожелания по тону, акцентам и тому, на чём останавливаться; формат разбора оно изменить не может. |
| Разрешение конфликтов merge/rebase | Диалог конфликтов в представлении git, когда merge или rebase останавливается на конфликтах | Вы выбираете «Resolve in current session» или «Resolve in new session». Агент читает конфликтующие файлы, предлагает стратегию разрешения для каждого файла и ждёт вашего подтверждения, прежде чем редактировать, индексировать или продолжать операцию. |
| Разрешение конфликтов cherry-pick | Раздел «Re-integrate commits» для сессии в рабочем дереве | Перенос коммитов сессии на целевую ветку упирается в конфликт, и вы передаёте его агенту. Агент разрешает конфликты внутри временного рабочего дерева, индексирует разрешённые файлы и продолжает cherry-pick. |

### Planning

| Промпт | Где выполняется | Когда срабатывает |
| --- | --- | --- |
| Планирование по todo | Панель Todos в боковой панели проекта | Вы отправляете todo в сессию или в новую сессию рабочего дерева. Текст todo становится видимым сообщением; инструкции превращают его в диалог планирования с вопросами, а не в прыжок сразу к реализации. |
| Улучшение плана | Действие «Improve» у сохранённого плана в представлении Plans | Вы отправляете сохранённый план в процесс улучшения. Агент сначала читает файл плана, затем предлагает изменения на основе текущего состояния репозитория и предлагает отредактировать тот же файл. |
| Реализация плана | Действие «Implement» у сохранённого плана | Вы отправляете сохранённый план в процесс реализации. Агент читает файл плана и реализует его от начала до конца, не расширяя объём, и сохраняет правки плана обратно в файл, когда сам план оказывается неверным. |

### Session

Большинство из них работают за слэш-командами, которые вводятся в поле ввода чата. Большинство также появляются как стартовые чипы в черновике новой сессии.

| Промпт | Где выполняется | Когда срабатывает |
| --- | --- | --- |
| Тур по кодовой базе | `/explore` | Вы просите общий обзор кодовой базы. |
| Сводка сессии | `/summary`, необязательно `/summary <topic>` | Вы подводите итог разговора на данный момент, это удобно для передачи в новую сессию. Нужна существующая сессия. |
| Ревью рабочей области | `/workspace-review` | Вы просите агента проверить текущий дифф рабочей области на соответствие замыслу, корректность и безопасность. |
| Планирование функции | `/plan-feature` | Вы превращаете грубую идею функции в план реализации через управляемый диалог вопросов и ответов. |
| Формулировка цели | `/craft-goal`, необязательно `/craft-goal <idea>` | Вы превращаете идею в проверяемую цель Goal для диалога Goal. |
| Наверстать | `/catch-up` | Вы возвращаетесь к проекту и спрашиваете, на чём всё стоит и что делать дальше. |
| Отладка | `/debug` | Вы исследуете баг: агент выдвигает гипотезы, подтверждает корневую причину по коду и только потом предлагает исправление. |
| Взвешивание вариантов | `/weigh` | Вы знаете, что хотите построить, но не как. Агент сравнивает два-три подхода и рекомендует один. |
| Fusion | Действие «Run fusion» у группы мультизапуска | Вы объединяете выводы нескольких запусков в один ответ. Выводы запусков добавляются после инструкций. |

### Промпты без страницы в Settings

Несколько промптов срабатывают автоматически и не имеют редактируемой страницы в Settings:

| Промпт | Когда срабатывает |
| --- | --- |
| Запланированная задача | `/schedule-task`, необязательно с начальной идеей. Ведёт диалог, который определяет запланированную задачу. |
| Передача в проверку | `/handoff-review` или кнопка Review в представлении диффа с включённой передачей. Генерирует передачу (handoff) в рабочей сессии. |
| Стартовое сообщение сессии проверки | Первое сообщение сгенерированной сессии проверки — с передачей, если она была создана, и без неё в остальных случаях. |
| Отзыв проверки / ответ реализующей сессии | Передают сообщения между двумя сессиями: отзыв проверяющего возвращается в реализующую сессию, а ответ реализующего — обратно в сессию проверки. |
