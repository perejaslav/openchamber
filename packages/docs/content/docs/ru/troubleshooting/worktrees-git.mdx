# Рабочие деревья и Git

Проблемы, которые возникают с [сессиями в рабочих деревьях](/worktrees/) и [представлением git](/git/), и как их устранить.

## Рабочее дерево требует внимания

OpenChamber помечает рабочее дерево, когда что-то не так:

- **папка отсутствует** — папку рабочего дерева удалили или переместили вне OpenChamber; удалите сессию и создайте новое рабочее дерево
- **detached или незарождённая ветка** — рабочее дерево не на обычной ветке; переключите его на неё
- **идёт merge, rebase или cherry-pick** — операция осталась незавершённой; завершите или прервите её из представления git

## Не удаётся создать рабочее дерево

- **ветка уже существует** — выберите другое имя ветки или воспользуйтесь вариантом с существующей веткой
- **имя уже занято** — выберите другое имя рабочего дерева

## Не удаётся сгенерировать коммит или PR

Генерация сообщения коммита или описания PR выполняется в вашей активной сессии, поэтому нужна открытая сессия с выбранной рабочей моделью. Откройте или выберите сессию и попробуйте снова.

## Проблемы с SSH или путями Windows

- убедитесь, что ключ SSH, который использует репозиторий, — тот, что задан в вашей [Git-идентичности](/git-identities/)
- в Windows git использует пути в стиле Unix (например, `/c/Users/...`) — OpenChamber это обрабатывает, но пользовательские пути к ключам SSH должны быть в той же форме
