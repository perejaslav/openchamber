# Провайдеры классификации (Jev)

Некоторым функциям OpenChamber нужно быстрое решение до того, как они начнут действовать: рискованна ли эта команда, что это за задача, выглядит ли работа законченной? На такие вопросы отвечает небольшая модель решений Jev (её делает TypeSafe). Эта страница рассказывает, как дать OpenChamber доступ к Jev.

Jev никогда не пишет код и не отвечает в вашем чате. Он возвращает только вердикт, а OpenChamber действует по нему. OpenChamber ждёт ответ не дольше четырёх секунд, прежде чем отправить сообщение или выполнить действие, и до пятнадцати секунд для проверок после хода, где от него ничего не зависит.

## Что использует Jev

| Функция | Вопрос, на который отвечает Jev |
| --- | --- |
| [Разрешения и защита](/permissions/) | Спросить ли у вас агента перед выполнением этого действия? |
| [Автоматический выбор модели](/auto-model-routing/) | К какой из ваших категорий относится этот промпт? |
| [Сессии в работе](/sessions-in-work/) | Похож ли этот ход на завершение работы? |
| [Итог сессии и предложение](/sessions-in-work/#recap-and-next-message-suggestion) | Стоит ли после этого хода генерировать итог или предложение следующего сообщения? |

Без провайдера защита и Auto скрыты, а сессии в работе не получают подсказку «похоже, готово». Сессии всё равно переходят в работу, когда вы отправляете сообщение. Итоги и предложения работают и так, просто без фильтра.

## Настройка

Jev выключен, пока вы его не включите: ничего из ваших разговоров не уходит провайдеру классификации, пока вы его не выберете. Откройте **Settings → Providers → Classification providers** и выберите, куда идут запросы Jev. Кроме **Off**, есть семь вариантов.

### Промо OpenCode Zen

Бесплатно ограниченное время, ключ не нужен. Пока идёт промо, OpenCode позволяет OpenChamber использовать Jev через OpenCode Zen без оплаты.

Когда промо закончится, этот вариант исчезнет, и OpenChamber переключится на один из ключей ниже, если он у вас есть.

### Ключ OpenCode Zen

Использует ключ API Zen, сохранённый в OpenCode, с оплатой с вашего баланса Zen.

1. Откройте **Settings → Providers** и добавьте ключ API провайдеру **OpenCode Zen** (см. [Провайдеры, модели и агенты](/providers/)).
2. Вернитесь в **Classification providers** и выберите **OpenCode Zen key**.

Входа через аккаунт OpenCode недостаточно. Для Jev Zen принимает только ключ API.

### Ключ OpenRouter

Использует ключ API OpenRouter, сохранённый в OpenCode, с оплатой с вашего аккаунта OpenRouter. Если вы уже используете модели OpenRouter в OpenCode, настраивать ничего не нужно. Ключ в переменной окружения `OPENROUTER_API_KEY` тоже подойдёт. Если есть и то и другое, побеждает ключ, сохранённый в OpenCode.

1. Откройте **Settings → Providers** и добавьте ключ API провайдеру **OpenRouter**.
2. Вернитесь в **Classification providers** и выберите **OpenRouter key**.

### Ключ Vercel AI Gateway

Использует ключ API AI Gateway, сохранённый в OpenCode, с оплатой с вашего аккаунта Vercel. Ключ в переменной окружения `AI_GATEWAY_API_KEY` тоже подойдёт. Если есть и то и другое, побеждает ключ, сохранённый в OpenCode.

1. Откройте **Settings → Providers** и добавьте ключ API провайдеру **Vercel AI Gateway**.
2. Вернитесь в **Classification providers** и выберите **Vercel AI Gateway key**.

### Google Gemini

Использует Gemini Decision 1 — собственную модель решений Google — через Decisions API Google, с оплатой с вашего аккаунта Google. OpenChamber задаёт ей те же вопросы, что и Jev. На бесплатном тарифе Google может использовать полученные данные для улучшения своих продуктов ([условия Gemini API](https://ai.google.dev/gemini-api/terms#data-use-unpaid)).

1. Получите ключ API в [Google AI Studio](https://aistudio.google.com/apikey).
2. Вставьте его в поле **Gemini API key** и нажмите **Save**.

Сохранение ключа также выбирает его. Ключ остаётся на сервере OpenChamber в отдельном файле и никогда не отправляется в браузер.

Если у провайдера **Google** в OpenCode уже есть ключ API, поле можно пропустить и выбрать **Google Gemini**. Ключ в `GOOGLE_API_KEY`, `GOOGLE_GENERATIVE_AI_API_KEY` или `GEMINI_API_KEY` тоже подойдёт. Ключ, сохранённый в OpenChamber, важнее обоих. Держите ключ в OpenChamber, если Gemini нужен только для решений: ключ в провайдере Google в OpenCode также открывает все чат-модели Gemini в OpenCode, а ключ API Gemini нельзя ограничить одной моделью.

### Ключ TypeSafe API

Ваш собственный ключ и квота TypeSafe.

1. Получите ключ API в [TypeSafe](https://docs.typesafe.ai).
2. Вставьте его в поле **TypeSafe API key** и нажмите **Save**.

Сохранение ключа также выбирает его. Ключ остаётся на сервере OpenChamber в отдельном файле и никогда не отправляется в браузер.

### Пользовательский эндпоинт

Любой сервис, говорящий на System One API от TypeSafe: шлюз, развёрнутый самостоятельно, корпоративный прокси или провайдер, которого здесь нет.

1. В разделе **Custom endpoint** заполните **Endpoint URL** и **Model** (например, `jev-latest`).
2. Добавьте **API key**, если сервису он нужен. Он отправляется как токен `Bearer`.
3. Нажмите **Save**.

Вставьте полный адрес, на котором отвечает сервис, например `https://api.typesafe.ai/v1/systemone` или `https://proxy.company.internal/v1/decision` корпоративного прокси. OpenChamber вызывает его ровно так, как вы вставили, и ничего не добавляет к пути. Работают только `http` и `https`, а ключ идёт в отдельное поле, никогда в URL.

Сохранение также выбирает эндпоинт. Как и ключ TypeSafe, эндпоинт и его ключ остаются на сервере OpenChamber в отдельном файле, а ключ никогда не отправляется в браузер.

Сервер также может получить эндпоинт из окружения, что удобно, когда вы настраиваете OpenChamber для команды:

```bash
OPENCHAMBER_JEV_URL=https://jev.example.com/v1/systemone
OPENCHAMBER_JEV_MODEL=jev-latest        # optional, this is the default
OPENCHAMBER_JEV_API_KEY=...             # optional
```

На ноутбуках, которыми вы управляете, вместо этого укажите тот же эндпоинт в разделе `jev` [файла политики](/security/#a-policy-file-on-the-machine) машины. Он важнее окружения.

В любом случае он заменяет эндпоинт, сохранённый в настройках, и настройки показывают его, не давая никому изменить. В [корпоративном режиме](/security/#enterprise-mode) это единственный источник Jev, разрешённый кроме **Off**, и он выбран по умолчанию.

Карточка в **Settings → Providers** показывает **Ready**, когда провайдер работает.

## Когда выбранный вариант перестаёт работать

Если выбранного провайдера нельзя использовать (промо закончилось, ключ удалён), OpenChamber переходит к первому из ваших собственных работающих ключей: ключ TypeSafe, затем пользовательский эндпоинт, затем OpenRouter, затем Vercel AI Gateway, затем ключ Zen. Он никогда не переходит на промо или на Google Gemini, а **Off** остаётся выключенным. Страница сообщает, какой вариант используется прямо сейчас.

Если Jev медлит или даёт сбой на отдельном запросе, ничего не ломается. У каждой функции есть безопасный ответ на такой случай:

- Защита оставляет действие ждать вас.
- Auto отправляет промпт резервной модели.
- На сессиях в работе не появляется подсказка «похоже, готово».
- Итог и предложение генерируются так, будто Jev не существует.

## Что видит Jev

Jev получает ваше последнее сообщение и для контекста фрагменты недавнего разговора: до трёх предыдущих ходов, урезанных до нескольких сотен символов каждый, а когда ход завершается — ответ агента, урезанный до начала и конца. Для защиты он также получает действие, на которое агент просит разрешение, в том виде, как его описывает OpenCode: команду, которую агент хочет выполнить, либо файл и изменение для правки. Когда агент создаёт файл, этим изменением становится весь файл, включая изображения, записанные текстом, например SVG. Когда Jev проверяет цель, он получает цель и последний ответ агента — до 10 000 символов.

Запросы идут с сервера OpenChamber напрямую в OpenCode Zen, OpenRouter, Vercel AI Gateway, Google, TypeSafe или ваш пользовательский эндпоинт — в зависимости от выбора.

## Где это работает

Jev работает на сервере OpenChamber, поэтому он доступен в десктопном приложении, веб-приложении и на телефоне, подключённом к любому из них. Расширение VS Code общается с OpenCode напрямую и не имеет Jev: там нет ни защиты, ни Auto, ни подсказки «похоже, готово».
