# Создание расширения

Используйте `@openchamber/sdk`, чтобы добавить в OpenChamber собственную панель. Расширение — это небольшая веб-страница, которую OpenChamber показывает на правой рейке. Она общается с приложением через `connectHost()`: может читать текущий проект и сессию, показывать всплывающие уведомления, вставлять текст в поле ввода чата, прикреплять задачу к сессии и, с одобрения пользователя, запускать сессии и отправлять промпты.

Расширения работают в веб-версии OpenChamber, в десктопном приложении и в мобильном приложении. На телефоне ваша панель и страница показываются, только когда вы укажете, что они подходят для телефона; см. [На телефоне](#on-the-phone). VS Code не загружает расширения.

На сайте есть [карта всех мест, куда расширение может что-то добавить](https://openchamber.dev/extensions/build/).

## Что такое расширение

Папка с тремя файлами:

- `package.json` с блоком `openchamber` (манифест)
- `panel/index.html` — страница, которую показывает OpenChamber
- `panel/main.js` — ваш скрипт, собранный в один классический файл (IIFE, не ES-модуль, потому что страница загружается в изолированный iframe)

OpenChamber никогда не компилирует ваш код. Поставляйте собранный файл `.js`. В SDK входит команда сборки; подойдёт любой сборщик, выдающий IIFE.

```bash
npm install @openchamber/sdk
bunx openchamber-guest-bundle panel/main.ts panel/main.js
```

Команда сборки работает на Bun. Без Bun используйте esbuild или любой другой сборщик с `--format=iife --platform=browser`.

Полное рабочее расширение, все три файла, есть на странице [Пример](/sdk/example/). Скопируйте его и измените API и список.

Сошлитесь из `index.html` на `main.js` обычным `<script src="main.js"></script>`.

## Установка во время работы

1. Запустите OpenChamber в вебе или на десктопе.
2. Откройте Settings → Extensions.
3. Вставьте абсолютный путь к вашей папке и нажмите Add.

OpenChamber читает манифест и показывает диалог со списком того, что запрашивает расширение (см. [Возможности](#capabilities)). Одобрите его, и ваш значок появится на рейке. Нажмите на него, и страница загрузится.

Можно также добавить локальный `.zip` или https-ссылку на репозиторий Git либо zip-файл. Обновляться может только установка из Git: поднимите `version` в `package.json` и сделайте push, и OpenChamber проверит вскоре после открытия, а затем каждые несколько часов, сообщит пользователю один раз и предложит обновление в Settings → Extensions. Ссылка `openchamber://extensions/install?url=<encoded repository URL>` на любой странице открывает десктопное приложение с этим репозиторием в диалоге добавления, так что вы можете предложить кнопку установки. `#tag` или `#branch` в URL закрепляет, за чем именно следовать. Такие расширения копируются в папку данных OpenChamber и запускаются из этой копии, поэтому поставляйте собранные файлы, а не `node_modules` или исходники TypeScript. Удаление расширения удаляет копию. Установка из папки работает прямо из вашей папки, поэтому можно править, пересобирать и перезагружать.

## Манифест

```json
{
  "name": "@acme/hello",
  "version": "1.0.0",
  "openchamber": {
    "apiVersion": 1,
    "engines": { "openchamber": ">=1.24.0" },
    "id": "acme-hello",
    "name": "Hello",
    "icon": "window",
    "contributes": {
      "panel": { "entry": "panel/index.html" },
      "attach": "dialog",
      "page": true,
      "capabilities": ["prompt", "sessions"],
      "integration": {
        "name": "Acme",
        "description": "Tasks from Acme",
        "token": {
          "apiOrigin": "https://api.acme.example",
          "account": { "path": "/me", "name": "login" },
          "scheme": "bearer"
        },
        "settings": [{ "id": "list-id", "label": "List ID" }]
      }
    }
  }
}
```

`version` обязателен и должен быть semver. Settings → Extensions показывает его на карточке.

`apiVersion` равен `1`. OpenChamber отклоняет любое другое значение.

`engines.openchamber` необязателен. Укажите самую старую версию OpenChamber, с которой работает ваше расширение, как `1.24.0` или `>=1.24.0`. Более старые сборки откажутся его устанавливать, вместо того чтобы сломаться позже.

`id`, `name` и `icon` задают расширение. `id` пишется в kebab-case и должен быть уникальным среди установленных расширений. `icon` — имя Remixicon (`RiWindowLine` превращается в `window`) или SVG-файл в вашей папке, например `icon.svg`. `contributes.panel` — панель расширения на рейке: её `entry` — HTML-файл в вашей папке. Расширение без панели на рейке не указывает `panel`. Старые пакеты держат `id`, `name` и `icon` внутри `panel`, и это продолжает работать.

`contributes.attach` необязателен. Он добавляет ваше расширение в меню «+» рядом с полем ввода чата, чтобы пользователь мог выбрать задачу и прикрепить её к сессии.

- `"dialog"` открывает вашу страницу в окне
- `true` или `"panel"` вместо этого открывает панель на рейке
- `{ "mode": "dialog", "entry": "panel/attach.html" }` открывает в окне отдельную вашу страницу, так что выбору не нужно делить код с панелью на рейке
- не указывайте его — и расширения не будет в этом меню

Ваша страница может узнать, где она находится, из `ctx.surface`: `panel`, `dialog`, `page`, `status` или `block`. Когда пользователь нажимает на прикреплённый элемент, его `data` возвращается в `ctx.item`. Открытие с рейки, из меню «+» или из строки в разделе Pages начинается без элемента.

`contributes.page: true` делает вашу панель доступной на весь экран из её собственной строки в разделе Pages боковой панели. Используйте `{ "entry": "panel/page.html", "title": "Board" }` для отдельного HTML и необязательного заголовка. Поставляйте этот HTML и его собранные скрипты. `true` использует повторно `panel.entry`; странице с собственным `entry` панель на рейке не нужна, поэтому расширение может быть только полноэкранной страницей. Страница использует ту же песочницу и разрешения и открывается только когда пользователь её выберет. Перезагрузка, пауза, удаление или переключение сервера закрывают её.

Для доски используйте `host.storage` для постоянного JSON и методы project/worktree/session для общих данных приложения. `startSession` может нацелиться на другой проект или рабочее дерево, не закрывая доску. О подписках, живых состояниях и частичных результатах создания см. [Host API](/sdk/host/).

`contributes.integration` необязателен. Он добавляет карточку в Settings → Integrations, где пользователь подключает учётную запись. См. [Учётные записи и сеть](#accounts-and-network).

`contributes.service` необязателен. Он объявляет локальный процесс, который OpenChamber запускает рядом с расширением, для того, до чего веб-страница не дотянется, например для сокета Docker. Этот процесс работает с полным доступом пользователя и без песочницы, поэтому диалог подтверждения предупреждает о нём; объявляйте его, только когда страница не может справиться сама. См. файл пакета `GUEST_SERVICES.md`. Сервис с `provides: ["browser"]` также может заменить браузер агента: он отвечает на действия `browser.*` на сервере, поэтому агенты работают в браузере без открытого десктопного приложения, а пользователь выбирает его в Settings → OpenChamber Tools. Такому сервису панель не нужна. Сервису можно также сообщать, что происходит в сессиях пользователя: объявите рядом `contributes.sessionEvents`, и OpenChamber будет отправлять сервису каждый завершённый или упавший ход, каждый запрос разрешения и каждый вопрос агента, из всех проектов, без открытого окна. См. [События сессий](/sdk/host/#session-events). А сервис с `provides: ["notifications"]` доставляет уведомления пользователя рядом с десктопом и телефоном — в Slack, Matrix или на ваш собственный сервер; пользователь подключает учётную запись в Settings → Integrations, а токен остаётся в OpenChamber. См. [Каналы уведомлений](/sdk/host/#notification-channels). Сервис с `provides: ["tracker"]` — это трекер рабочих элементов рядом с Linear, с карточкой учётной записи в Extension accounts; см. [Трекеры](/sdk/host/#trackers). А сервис с `provides: ["quota"]` сообщает об использовании рядом со встроенными провайдерами, читая учётные данные, которые OpenCode хранит для провайдеров, перечисленных в манифесте; см. [Провайдеры использования](/sdk/host/#usage-providers). Сервис также может ставить маленькие значки на строки боковой панели через `contributes.marks`; см. [Отметки на строках боковой панели](/sdk/host/#marks-on-sidebar-rows).

## Возможности

Рисование панели и чтение текущей сессии не требуют разрешений. А всё, что действует от имени пользователя, — требует. Перечислите их в `contributes.capabilities`:

| Возможность | Что она разрешает |
| --- | --- |
| `prompt` | отправлять сообщения в сессию пользователя (`prompt({ send: true })`, `startSession` с `text`) |
| `sessions` | перечислять проекты, рабочие деревья и состояния сессий; создавать и открывать сессии в зарегистрированных проектах |
| `files` | читать и писать файлы внутри открытого проекта (`readFile`, `writeFile`, `listDir`, `stat` с относительным путём) |
| `model` | разовая генерация текста на Small Model пользователя (`generate`), вне любой сессии |
| `shells` | следить за командами оболочки, которые ваши агенты выполняют в фоне, читать их вывод и останавливать их (`onRunningShells`, `readShellOutput`, `stopShell`) |
| `microphone` | слышать пользователя через микрофон, для звонков или голосового ввода (`openMicrophone`) |

Ещё тринадцать добавляются за вас: `network` при объявлении `integration`, `service` при объявлении `service`, `filesystem` при объявлении шаблонов `filesystem`, `origins` при объявлении `origins`, `conversation`, когда действие с сессией запрашивает сообщения (см. [Действия, команды и значок](#actions-commands-and-the-badge)), `transcript`, когда `sessionEvents` или `sessionControl` запрашивает `content` (см. [События сессий](/sdk/host/#session-events)), `sessionControl`, когда ваш сервис действует в сессиях (см. [Вызов OpenChamber](/sdk/host/#calling-openchamber-from-your-service)), `sessionAnswers`, когда он отвечает за пользователя на запросы разрешений и формы агента (`sessionControl: { answers: true }`), `instructions`, когда он добавляет к тому, что читают агенты, `skills` при объявлении `contributes.skills` — папки пакета с навыками, которые доходят до каждого агента, пока расширение включено, `opencodePlugin` при объявлении `contributes.opencodePlugin` (см. [Плагин OpenCode в вашем пакете](#an-opencode-plugin-in-your-package)), `links` при объявлении `contributes.links` (см. [Ссылки в сообщениях чата](#links-in-chat-messages)) и `marks` при объявлении `contributes.marks` (см. [Отметки на строках боковой панели](/sdk/host/#marks-on-sidebar-rows)).

Пользователь видит полный список один раз, при установке расширения, и одобряет его или удаляет расширение. Если новая версия просит больше, диалог появляется снова. Вызов, которому нужна не одобренная пользователем возможность, завершается ошибкой `NOT_GRANTED`.

## Плагин OpenCode в вашем пакете

Расширение может поставлять плагин OpenCode, чтобы людям нужно было установить одну вещь вместо двух. Объявите `"opencodePlugin": "plugin"` — папку внутри пакета с `index.js` или `server.js` в корне. OpenCode не читает `main`, поэтому для точки входа в другом месте задайте в `package.json` папки `name` и `exports`. Точка входа по умолчанию экспортирует `{ id, setup }` — форму, которую загружает OpenCode; она ничего не импортирует, потому что OpenCode загружает её голым `import()` из вашей папки, где ничего не установлено. `input` инструмента — обычная JSON Schema, а его `execute` отвечает `{ content }`.

```json
{
  "contributes": {
    "panel": { "id": "teapot-tools", "name": "Teapot Tools", "icon": "cup" },
    "opencodePlugin": "plugin"
  }
}
```

В диалоге подтверждения появляется ещё одна строка, **Add a plugin to OpenCode**, где прямо сказано, что код плагина выполняется внутри OpenCode с полным доступом пользователя. После разрешения OpenChamber указывает вашу папку в управляемой им конфигурации OpenCode — в том же файле, где лежит `contributes.skills`; запущенный OpenCode следит за этим файлом и загружает плагин в течение пары секунд. Отключение или удаление расширения так же убирает плагин. В собственный `opencode.json` пользователя ничего не пишется: этот файл его, и плагин в нём пережил бы ваше расширение и работал бы в каждом OpenCode на машине.

Там, где этот файл не достигает OpenCode, экран расширения говорит об этом и предлагает **Add to global config**, что записывает вашу папку в глобальную конфигурацию OpenCode пользователя как запись, которой он с этого момента владеет. Так бывает, когда OpenChamber не запускал тот OpenCode, с которым общается, или когда окружение сервера задаёт свой `OPENCODE_CONFIG` (тогда плагин загрузится при следующем запуске OpenCode). OpenCode на другой машине не может загрузить папку с этой; экран говорит об этом и ничего не предлагает. О плагине, который не загрузился, OpenCode сообщает в Settings → Plugins, если у него есть запись там; ваше расширение в любом случае продолжает работать. Установка отказывает пакету, у которого нет папки плагина или в `package.json` не указан файл точки входа.

VS Code не загружает расширения, поэтому никакой плагин не достигает запускаемого им OpenCode. Телефон подключается к серверу OpenChamber, и плагин работает в OpenCode этого сервера. Сессия в изолированном пространстве запускает собственный OpenCode, который никогда не читает конфигурацию хоста. Корпоративный режим относится к плагину как к локальному сервису: он устанавливается только из репозитория, который указал администратор. В SDK есть рабочий пример, `examples/opencode-plugin`.

## Ссылки в сообщениях чата

Расширение может делать свои идентификаторы и ссылки кликабельными в сообщениях чата, так что `DEMO-12` в ответе агента открывает эту задачу в вашем расширении вместо вкладки браузера. Объявите, что распознавать и что делает клик:

```json
"links": {
  "action": "open",
  "identifier": { "keys": ["DEMO"] },
  "urls": { "origin": "https://tasks.example.com", "identifier": "key-number", "item": ["/tasks/{id}"] }
}
```

- `identifier.keys` — до 8 буквальных ключей в верхнем регистре. `DEMO` заявляет `DEMO-12` как целое слово; код, ссылки, пути и слова вроде `XDEMO-1` или версии вроде `DEMO-1.5` остаются текстом.
- `urls` заявляет ссылки на одном https-origin, совпадающем точно. `item` — шаблоны ссылок в форме трекера: `{id}` один раз, в пути или как `?name={id}`, и `{segment}` или `{segments+}` для изменяющихся частей. `identifier` говорит, как выглядит `{id}`: `key-number`, `number` или `short-code`. Вы никогда не пишете регулярное выражение; OpenChamber компилирует шаблоны.
- `action: "open"` открывает ваше расширение с `ready.item` (или `onItem`), установленным в `{ kind: "link", identifier, url? }`: в вашем диалоге, если `attach` равен `"dialog"`, иначе в вашей панели на рейке. Сужайте его через `isGuestLinkItem`. Нужен `panel.entry`. `url` — это нажатая ссылка без фрагмента и без параметров запроса, кроме собственных параметров шаблона; для идентификатора в тексте это ссылка, которую называет ваш первый шаблон без `{segment}`, если такой есть и идентификатор имеет форму, объявленную `urls.identifier` (`DEMO-12` никогда не заполняет `number`).
- `action: "attach"` вместо этого кладёт чип с идентификатором в поле ввода и требует шаблон без `{segment}` или `{segments+}`, чтобы чип мог назвать свою ссылку; с `identifier.keys` `urls.identifier` не может быть `number`.

Распознавание работает в ответах агентов и в сообщениях самого пользователя, но не в рассуждениях, выводе инструментов или представлении Files, а копирование сообщения сохраняет его текст как есть. Ссылка, которую OpenChamber читает сам, элемент трекера, issue или пул-реквест репозитория, либо коммит сохраняют свой обычный маршрут, а клик с модификатором сохраняет смысл браузера. Объявление `links` добавляет возможность `links`: диалог подтверждения перечисляет ваши ключи и origin и говорит, что делает клик, а версия, которая меняет что-то из этого, спросит снова. `examples/tasks-demo` распознаёт `DEMO-2` и `https://example.com/tasks/DEMO-2`.

## Генерация текста

С возможностью `model` метод `host.generate` просит у Small Model пользователя разовый ответ: резюме, заголовок, черновик. Ничего не попадает в сессию, история не сохраняется, и расширение никогда не выбирает провайдера. OpenChamber использует ту же модель, что и для своей фоновой работы, выбранную в Settings → Sessions → Small Model, или малая модель провайдера, с которым работает пользователь, или модель по умолчанию из его конфигурации OpenCode.

```ts
const { text } = await host.generate({
  prompt: task.description,
  system: "Write a one-line summary. Return only the summary.",
  maxOutputTokens: 200,
});
```

Когда модель недоступна, вызов завершается ошибкой `NO_MODEL`; модель, которая дала ошибку, — `MODEL_FAILED`. Промпты ограничены 64 000 символов, и вызов ждёт до 960 секунд. Пользователь видит это разрешение как «Use your Small Model», и оно стоит ему токенов, поэтому держите промпты короткими и вызывайте его по клику, а не на каждое нажатие клавиши.

## Учётные записи и сеть

Ваша страница работает в песочнице и не может сама выйти в сеть: скрипты, стили, изображения, шрифты и медиа загружаются только из вашего пакета, а `fetch` достигает только файлов вашего пакета. Поставляйте шрифты и изображения внутри пакета, а не загружайте их с CDN.

Чтобы обращаться к внешнему сервису, объявите `integration`, и OpenChamber сделает вызовы за вас через `host.request`, приложив токен пользователя. Токен никогда не попадает на вашу страницу.

Для всего остального, что вашей странице нужно напрямую — например, шрифтов или изображений с CDN или из публичного API, — перечислите до 8 https-origin:

```json
"origins": ["https://fonts.example.com"]
```

Пользователь видит их в диалоге подтверждения как адреса, на которые ваше расширение может отправлять данные и с которых может получать их, и одобряет их заново, если обновление добавит новый. Одобренные origin открыты для `fetch`, изображений, шрифтов, стилей и медиа, но никогда для скриптов: код должен поставляться в вашем пакете. Origin страницы — `null`, поэтому чтобы прочитать ответ `fetch`, сервер должен разрешить CORS для этого origin.

В [корпоративном режиме](/security/#enterprise-mode) расширение с `origins`, `integration` или `service` устанавливается только из репозитория Git, который указал администратор. Если ваше расширение может работать без них, оно остаётся доступным для установки таким командам. Чтобы собрать его на такой машине, попросите у администратора `allowLocalExtensions`, который позволяет установить его из папки.


- `token`: пользователь вставляет токен API на карточке Settings → Integrations. `apiOrigin` — единственный origin, который может вызывать `request`. `account` необязателен: путь для GET и имя поля, чтобы карточка могла показать, кто подключён. `scheme` говорит, как отправляется токен; см. таблицу ниже. Сверьтесь с документацией API провайдера, какой заголовок он ждёт.
- `oauth`: пользователь вставляет client id, и OpenChamber выполняет поток авторизации. Нужны `authorizeUrl`, `tokenUrl` и `apiOrigin`.
- `host: { "provider": "linear" }`: повторно использует учётную запись Linear, уже подключённую в OpenChamber. Client id не нужен.

Что отправляет каждый `scheme`:

| `scheme` | Заголовок, который отправляет OpenChamber | Когда использовать |
| --- | --- | --- |
| не указан | `Authorization: <token>` | API документирует голый токен в заголовке |
| `"bearer"` | `Authorization: Bearer <token>` | API документирует bearer-токен или personal access token |
| `"basic"` | `Authorization: Basic base64(username:token)` | API документирует HTTP Basic auth с именем пользователя (часто email) и токеном API; карточка спрашивает оба, а `usernameLabel` задаёт имя первого поля |

`settings` добавляет на карточку текстовые поля. Их значения приходят в `ctx.settings`. Поле с `"secret": true` скрыто на карточке и никогда не попадает на страницу; ваш сервис читает его через `readSettings()`.

## Файлы

Ваша страница не может сама трогать диск. OpenChamber читает и пишет за неё, в пределах, одобренных пользователем.

- Относительный путь (`README.md`, `src/index.ts`, `.`) означает открытый проект. Нужна возможность `files`. Если открытого проекта нет — `NO_DIRECTORY`.
- Путь, начинающийся с `/` или `~/`, означает любое другое место. Он должен совпасть с одним из шаблонов, объявленных в `contributes.filesystem`, и пользователь видит эти точные шаблоны в диалоге подтверждения:

```json
"filesystem": ["~/.config/opencode/opencode.json", "~/notes/**"]
```

Шаблоны используют `*` для одного сегмента пути и `**` для любой глубины. Всё вне них — `BAD_PATH`, даже после подтверждения. `..` не разрешён никогда.

```ts
const config = await host.readFile("~/.config/opencode/opencode.json");
await host.writeFile("~/.config/opencode/opencode.json", nextJson);
const { entries } = await host.listDir(".");
```

Записи атомарны: OpenChamber пишет временный файл и переименовывает его, поэтому читатель никогда не увидит недописанный файл. Файлы читаются и пишутся как текст UTF-8, до 2 МБ.

## Раздел в Work Status

`contributes.statusSection` добавляет ваш собственный раздел в панель Work Status рядом с чатом. Пользователи включают и выключают его и перемещают в списке разделов этой панели, как встроенные разделы.

```json
"statusSection": { "entry": "status/index.html", "title": "Recent commits", "height": 160 }
```

- `true` использует повторно `panel.entry`.
- `entry` — отдельная HTML-страница в вашей папке. С ней `panel.entry` не нужен, поэтому расширение может быть только этим разделом, без значка на рейке.
- `title` заменяет имя панели в заголовке раздела, до 60 символов.
- `height` — начальная высота в пикселях, от 24 до 480 (по умолчанию 120). Вызывайте [`host.setHeight()`](/sdk/host/), когда содержимое меняет размер.

Ваша страница видит `ctx.surface` как `status`. OpenChamber загружает её, только пока панель Work Status видна и ваш раздел развёрнут, и выгружает, когда пользователь сворачивает раздел, поэтому не держите там ничего, что нельзя восстановить. Расширение только с разделом может использовать возможности, сервис, интеграцию, файлы и страницу с собственным `entry`, но не `page: true`, `attach`, `actions` или `commands`. Раздел показывается в вебе, на десктопе и во вкладке Work status на телефоне, где он не требует opt-in и получает ширину телефона. Пример `git-graph-status` — полный раздел.

## Редактор для вашего типа файлов

`contributes.fileEditors` открывает файлы в вашей странице вместо текстового редактора. Когда пользователь открывает подходящий файл в Files, OpenChamber показывает там ваш редактор с тем же переключателем исходника, кнопкой полного экрана и кнопкой сохранения, что у встроенных просмотрщиков.

```json
"fileEditors": [
  { "id": "canvas", "title": "Excalidraw", "match": ["*.excalidraw", "*.excalidraw.md"], "entry": "editor/index.html" }
]
```

- `match` сравнивает только имена файлов, без учёта регистра. `*` совпадает с любым набором символов, `?` — с одним. Шаблон не может содержать `/` и не может состоять только из подстановочных знаков.
- `entry` — HTML-страница в вашей папке. `panel.entry` не нужен, поэтому расширение может быть только редактором, без значка на рейке.
- `content` — `"text"` (по умолчанию) или `"binary"`, см. ниже.
- До 8 редакторов на расширение, до 16 шаблонов в каждом.

OpenChamber хранит файл. Ваша страница никогда его не читает и не пишет и не нуждается в возможности для этого. OpenChamber передаёт вам текст, запрашивает изменённый текст при сохранении и берёт на себя Cmd/Ctrl+S, автосохранение, запрос о несохранённых изменениях, окончания строк и изменения на диске:

```ts
import { connectHost, createFileSaveTracker } from "@openchamber/sdk";

const host = connectHost();
let tracker = createFileSaveTracker(null);

host.onFileOpen((file) => {
  if (file.encoding !== "text") return; // a text editor always gets text
  load(file.content); // file.path, file.name, file.readOnly too
  tracker = createFileSaveTracker(versionOf(currentText()));
});

// Call this after every edit. `edited` holds autosave back until the user stops.
const changed = () => host.reportFileChange(tracker.observe(versionOf(currentText())));

host.onFileSnapshot(() => ({ content: currentText(), version: versionOf(currentText()) }));

// Edits made while OpenChamber was writing keep the file unsaved.
host.onFileSaved((version) => host.reportFileChange({ dirty: tracker.markSaved(version), edited: false }));
```

`version` — любая короткая строка, которая меняется при изменении документа, например хеш. Если файл не открывается вашим редактором, вызовите `host.reportFileUnsupported()`, и OpenChamber покажет свой исходник с уведомлением. Файлы больше 20 МБ остаются в представлении исходника.

### Бинарные файлы

Установите `"content": "binary"`, чтобы открывать файлы, которые не являются текстом: электронные таблицы, документы или изображения. Ваш редактор получает байты файла и возвращает байты; всё остальное работает так же.

```ts
host.onFileOpen((file) => {
  if (file.encoding !== "binary") return;
  open(file.bytes); // a Uint8Array, exactly as on disk
});

host.onFileSnapshot(() => ({ bytes: currentBytes(), version: versionOf(currentBytes()) }));
```

Бинарный редактор может заявить любой файл, подходящий под его шаблоны, включая те, которые OpenChamber показывает сам, например изображения и PDF. У него нет представления исходника, и когда пользователь переводит его в полноэкранный режим или обратно с несохранёнными изменениями, OpenChamber сначала сохраняет их. Чтение и запись формата — забота вашего редактора: OpenChamber записывает обратно ровно те байты, которые вы вернули.

Ваша страница видит `ctx.surface` как `file`. OpenChamber перезагружает её, снова передавая файл, когда файл меняется на диске, пользователь отбрасывает изменения или редактор переходит в полноэкранный режим и обратно. Побеждает первое включённое расширение, чей шаблон совпадает, — оно идёт впереди собственных просмотрщиков OpenChamber. Расширение только с редактором может использовать возможности, сервис, интеграцию, файлы и страницу с собственным `entry`, но не `page: true`, `attach`, `actions` или `commands`. Редактор открывается в вебе, на десктопе и во вкладке Files на телефоне, где он занимает весь экран и не требует opt-in. Пример `checklist-editor` — полный редактор.

## Действия, команды и значок

Помимо рейки и меню «+», расширение может появляться ещё в трёх местах. Все они передают расширению `item` так же, как клик по чипу.

**Действия с сообщениями и сессиями.** Объявите пункты меню, и OpenChamber покажет их рядом со встроенными:

```json
"actions": [
  { "id": "create-task", "label": "Create task", "icon": "add-line", "where": "message", "roles": ["assistant"] },
  { "id": "summarize", "label": "Summarize session", "where": "session", "payload": ["messages"] }
]
```

`where` также принимает `selection` (выделенный в сообщении текст), `file` (строка в Files) и `diff` (выделенные строки файла или diff). Их элементы несут `kind` с тем же именем: у `selection` есть текст, у `file` — путь, у `diff` — путь и диапазон строк. Для выделения `display` говорит, как показывать действие: `label` (по умолчанию), `icon` с подписью в подсказке или `both`.

Действие с сообщением открывает ваше расширение с `ctx.item` вида `kind: "message"`: id и заголовок сессии, каталог проекта, id сообщения, его роль и текст. Действие с сессией открывает его с `kind: "session"` и id, заголовком и каталогом сессии. Добавьте `"payload": ["messages"]`, и элемент также несёт всю переписку, от старых к новым, тем же текстом, что даёт экспорт в Markdown. Для этого нужна возможность `conversation`, которую пользователь видит отдельной строкой в диалоге подтверждения. `item.action` говорит, какой пункт нажали.

**Слэш-команды, которые прикрепляют.** Объявите команду и обработайте её на странице:

```json
"commands": [{ "name": "task", "description": "Attach a task by id" }]
```

```ts
host.onResolve(async ({ command, args }) => {
  const task = await findTask(args.trim());
  return task ? { providerId: "acme-tasks", id: task.id, title: task.title, url: task.url } : null;
});
```

Когда пользователь вводит `/task ABC-12` в поле ввода чата, OpenChamber просит ваше расширение обработать её и прикрепляет то, что вы вернёте, как чип, ничего не открывая. Возвращайте `null` для «ничего не найдено». Если ваша панель закрыта, OpenChamber загружает её в фоне для этого вызова. Имя, которое уже использует OpenChamber или OpenCode, игнорируется.

Действия с сессиями и слэш-команды также появляются в палитре команд (⌘P или Ctrl+P), когда пользователь ищет по подписи, команде или имени вашего расширения. Действие с сессией там выполняется для открытой сессии. Команда попадает в начало поля ввода чата, а то, что пользователь уже ввёл, становится её аргументом, и выполняется, когда он отправит сообщение. Действия с сообщениями, выделением, файлами и diff остаются в своих меню.

**Значок на иконке рейки.** `host.setBadge(3)` ставит точку на ваш значок и число в его подсказку, например количество открытых задач; `host.setBadge(null)` очищает его. Открытие панели тоже его очищает.

## Ваши инструменты в чате

Когда ваш плагин OpenCode или сервер MCP добавляет инструмент, чат показывает его вызовы с общей иконкой и сырым выводом. Объявите, как они должны выглядеть, без кода:

```json
"tools": [
  {
    "match": "jira_*",
    "name": "Jira",
    "icon": "task-line",
    "title": "{input.key}",
    "subtitle": "{output.status}",
    "output": "table",
    "columns": ["key", "summary", "status"]
  }
]
```

`match` — имя инструмента, как его сообщает OpenCode; завершающая `*` совпадает с префиксом. `icon` — имя Remixicon или файл `.svg` в вашем пакете, как `panel.icon`. `title` и `subtitle` — шаблоны над `input`, `output` и `metadata` вызова. `output` выбирает, как рисуется тело: `text`, `json` (дерево), `markdown`, `code` с `language`, `table` с `columns` (строки берутся из массива вывода или из `output.items`), `card` с `card` (один элемент как карточка, см. ниже) или `auto` для поведения по умолчанию. Точный `match` важнее подстановочного, а при равенстве побеждает первое установленное расширение. Разрешение не нужно: это меняет только то, как рисуются данные, уже находящиеся в чате.

С включённым Code Mode в OpenCode агент вызывает инструменты из короткого скрипта, а не по одному. Скрипт с одним вызовом показывается как строка этого инструмента, и `output` — то, что вернул скрипт. Пишите `match` с `_` там, где в скрипте точка: `tools.github.list_issues` в скрипте — это `github_list_issues`. Скрипт с несколькими вызовами сохраняет свою строку.

Расширению, которое только оформляет инструменты, страница вообще не нужна: не указывайте `panel.entry`, и у него не будет значка на рейке, только карточка в Settings → Extensions. Без страницы оно может объявлять `tools` и `providerLogos` и ничего больше. Раздел Work Status, редактор файлов или полноэкранная страница с собственным `entry` — другое исключение, см. выше.

### Карточка для одного элемента

Когда инструмент отвечает одним объектом, например issue, `output: "card"` рисует его как карточку вместо сырого JSON. `card` говорит, какая часть вывода куда идёт:

```json
"tools": [
  {
    "match": "jira_get_issue",
    "name": "Jira issue",
    "title": "{input.key}",
    "output": "card",
    "card": {
      "label": "{output.key} · {output.fields.issuetype.name}",
      "title": "{output.fields.summary}",
      "status": {
        "value": "{output.fields.status.name}",
        "tones": { "In Progress": "info", "Blocked": "error", "Done": "success" }
      },
      "fields": [
        { "label": "Assignee", "value": "{output.fields.assignee.displayName}" },
        { "label": "Priority", "value": "{output.fields.priority.name}" }
      ],
      "link": { "label": "Open in Jira", "url": "{output.url}" }
    }
  }
]
```

`label` — маленькая строка сверху, `title` — заголовок, `status` — значок, `fields` — до восьми подписанных значений, `link` — ссылка внизу. Объявите хотя бы одно из первых четырёх. Каждое значение — шаблон, который читает `output` инструмента. `tones` окрашивает значок по его точному тексту: `info`, `success`, `warning`, `error` или `neutral`. Статус, который вы не указали, — нейтральный.

Когда вывод — массив или содержит массив `items`, та же `card` рисует компактный список: одна строка на элемент с его подписью, заголовком, первым полем и статусом, где `{output.…}` читает этот элемент. Показываются первые 200 элементов, и у строк нет ссылки.

Часть, значения которой нет в выводе, опускается. Если ничего из указанного там нет или вывод не JSON, чат показывает вывод так, как показал бы без правила.

Ссылка открывает только адрес `https`. `"{output.url}"` берёт адрес из вывода как есть. Можно также написать адрес самому вокруг значений: `"https://tracker.example.com/browse/{output.key}"`. Каждое значение тогда подвергается percent-кодированию, поэтому оно не может изменить хост или путь, которые вы написали. Расширение с `settings` интеграции (см. «Учётные записи и сеть» выше) может также читать несекретную настройку: `"https://{settings.site}/browse/{output.key}"`, где пользователь сохранил имя хоста вроде `acme.atlassian.net` как `site`. Настройка, содержащая полный адрес, порт или путь, ссылки не даёт, как и отсутствующее значение.

`card` требует релиз OpenChamber новее 2.7.0. Более старый отказывает расширению как недопустимому, и `engines.openchamber` этого не меняет.

## Логотип вашего провайдера

Когда ваш плагин OpenCode регистрирует провайдера моделей, списки выбора моделей и настройки обычно рисуют для него общий значок. Поставьте логотип в своём пакете и назовите провайдера, без кода:

```json
"providerLogos": {
  "acme-cloud": "assets/acme-cloud.svg"
}
```

Ключ — ID провайдера, как его сообщает OpenCode. Значение — `.svg` или `.png` в вашем пакете, до 1 МБ, и отсутствующий, пустой или больший файл проваливает установку. Пакет может назвать до 256 провайдеров, и два ID могут указывать на один файл. Логотип сохраняет свои цвета, а `currentColor` в SVG следует светлой или тёмной теме. Он заменяет логотип, который приложение поставляет для этого ID. Всё, что пользователь задал для этого провайдера, идёт первым, а при равенстве побеждает первое установленное расширение. Разрешение не нужно. Телефон тоже показывает эти логотипы; VS Code расширения не загружает, поэтому не показывает.

## На телефоне

Мобильное приложение и OpenChamber, открытый в браузере телефона, загружают расширения, установленные на сервере, к которому они подключаются. То, что OpenChamber рисует из вашего манифеста, работает там без изменений: ссылки в сообщениях чата, вёрстка ваших инструментов, логотипы провайдеров, строки меню `@`, отметки на строках боковой панели и карточки учётных записей. Нажатие на отметку открывает вкладку вашей рабочей области в сессии этой строки, когда вы задали `panel.mobile`, как клик на десктопе открывает вашу панель; без этого нажатие показывает текст отметки и открывает её `url`, если он есть.

Узкие фреймы показываются на телефоне без каких-либо действий с вашей стороны, на ширину телефона:

- блоки в чате
- ваш раздел Work Status, во вкладке Work status рабочей области
- ваш редактор файлов, который занимает вкладку Files
- поповеры, в нижнем листе (ниже)

Слэш-команды там работают, как и действия с `"mode": "background"`. Фоновые действия появляются в собственных меню телефона: лист More actions сообщения, лист для выделенного текста, меню долгого нажатия на строке сессии, долгое нажатие на строке Files и подписанные кнопки под полем комментария для выделенных строк diff.

Вашей панели и странице нужен opt-in, потому что страница, свёрстанная под панель десктопа, обычно ломается на 390px:

```json
"contributes": {
  "panel": { "entry": "panel/index.html", "mobile": true },
  "page": { "entry": "panel/page.html", "mobile": true }
}
```

- `panel.mobile: true` делает вашу панель вкладкой рабочей области телефона с вашим значком на ней. Он также распространяется на живую картинку, закреплённую в панели, ваш пункт в меню «+» (`attach: "dialog"` открывается там на весь экран), действия без `"mode": "background"`, ссылки `action: "open"`, нажатия на чипы и `openSurface("plugin:<id>")`.
- `page: true` использует повторно HTML панели, поэтому следует `panel.mobile`. Объект страницы с собственным `entry` следует только своему `mobile: true`: `panel.mobile` его не включает, и ему не нужна готовая для телефона панель, поэтому пакет может быть только страницей для телефона. Страница перечислена в разделе More списка сессий телефона и открывается на весь экран со стрелкой назад.

Без opt-in ничего из этого не открывается на телефоне: меню опускают ваши действия, которые открыли бы панель, нажатие на чип говорит, что ваше расширение не открывается на телефоне, ссылка сохраняет обычный смысл, а `openSurface` отклоняется с `UNSUPPORTED`.

Верстайте страницу с opt-in примерно на 360px ширины и под касания. `ready.device` говорит, где находится фрейм:

| Поле | Что это |
| --- | --- |
| `formFactor` | `phone`, `tablet` или `desktop` |
| `pointer` | `coarse` для пальца, `fine` для мыши |
| `insets` | `{ top, right, bottom, left }` в px: безопасная область, на которую приложение отступает свой экран на телефоне с вырезом, нули в остальных случаях |
| `keyboard` | px экрана фрейма, который закрывает экранная клавиатура, `0` пока она опущена |

OpenChamber отправляет новый `ready`, когда что-то из этого меняется, например при повороте или появлении клавиатуры, поэтому читайте его в `onReady` вместе с темой.

[UI-кит](/sdk/ui/) увеличивает свои элементы до размеров для касания при `pointer: coarse`: строки списков и варианты выбора не меньше 44px высотой, кнопки и поля ввода 40px, маленькие кнопки, триггеры и вкладки 36px. Поля ввода сохраняют текст не меньше 16px, потому что iOS приближает меньшее поле в фокусе. Размеры масштабируются вместе с размером интерфейса пользователя и доходят до вашего расширения, когда вы пересоберёте его с текущим SDK.

Поповер открывается в нижнем листе приложения на телефоне, шириной листа и запрошенной вами высотой, до предела листа. Он остаётся, пока пользователь его не закроет, что вы слышите как `outside`. `mountPopoverAnchor` открывает его по нажатию пальцем или пером, и это нажатие заменяет собственный клик элемента: ваш обработчик клика для него не выполняется. Положите в поповер то, что сделал клик, когда это нужно пользователю с касанием. Клик мышью или с клавиатуры не меняется. В `API.md` пакета SDK есть вызовы поповера.

Старые версии OpenChamber игнорируют `mobile` и устанавливают пакет как раньше, а `device` в `ready` не передают, поэтому считайте отсутствующий `device` десктопом с мышью.

## Первые строки в панели

```ts
import { connectHost } from "@openchamber/sdk";

const host = connectHost();

host.onReady((ctx) => {
  document.body.dataset.theme = ctx.theme.mode;
  document.body.dataset.surface = ctx.surface;
});
```

`connectHost` работает только внутри OpenChamber. Открытый как обычный файл, он отклоняет каждый вызов с `HOST_UNAVAILABLE`.

Сначала собирайте панель из блоков в `@openchamber/sdk/ui`: кнопок, полей, выпадающих списков, вкладок, списков и прочего, оформленных в цветах и шрифтах приложения, чтобы панель ощущалась частью OpenChamber. Собственный HTML и CSS пишите только для того, чего нет в ките. См. [UI-кит](/sdk/ui/).
