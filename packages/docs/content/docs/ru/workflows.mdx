# Workflows

Workflow разделяет большую задачу на множество небольших частей и назначает каждой своего агента. Агент в вашей сессии пишет короткий скрипт: каких агентов запустить и что поручить каждому. OpenChamber выполняет скрипт в фоне, поэтому основная сессия остаётся свободной, пока агенты работают. После завершения отчёт о запуске приходит в эту сессию.

Workflows подходят для множества похожих независимых задач: ревью каждого изменённого файла, аудита всех маршрутов API, переноса кода во множестве файлов или исследования с отдельной проверкой каждого источника. Одну функцию или несколько последовательных шагов быстрее выполнить в одной сессии.

## Включение

По умолчанию инструмент Workflows выключен. Откройте **Настройки → Общие → Инструменты OpenChamber** и включите **Инструмент Workflows**. В работающих сессиях он появится на следующем ходе. Если отключить его снова, инструмент и инструкции к нему исчезнут из всех сессий, а панель Workflows скроется. Ранее созданные запуски вернутся после повторного включения.

Workflows автоматически работают с управляемым сервером OpenCode от OpenChamber. Для локального внешнего или общего сервера OpenCode нужно зарегистрировать плагин OpenChamber в глобальной конфигурации через **Настройки → Общие → Сервер OpenCode** (см. [Сервер OpenCode](/ru/opencode-server/#включение-инструментов-openchamber-на-внешнем-локальном-сервере)). На удалённом сервере OpenCode и в расширении VS Code Workflows недоступны.

## Запуск workflow

1. Попросите о нём обычными словами, например: «Запусти workflow, который проверит каждый изменённый файл этой ветки и перечислит найденные ошибки».
2. Агент предложит план и модель для каждого этапа. Согласуйте модели до запуска — см. [Модели и стоимость](#модели-и-стоимость).
3. В чате появится карточка с планом. Выберите **Запустить workflow**, чтобы начать, или **Не запускать**, чтобы отказаться. До вашего выбора ничего не запускается, если вы не разрешили запуск без подтверждения (см. ниже).
4. Во время работы карточка показывает каждый этап и агента. В строке сессии в боковой панели появится **Workflow выполняется**, а в разделе **Workflows** панели состояния работы — сам запуск. Выберите **Остановить**, чтобы завершить его досрочно.
5. По окончании отчёт приходит в сессию сообщением. Завершённый или неудачный запуск пробуждает агента, чтобы он отреагировал на результат; остановленный или отклонённый — нет.

Остановленный или неудачный запуск можно продолжить кнопкой **Продолжить**. Агенты, которые уже ответили, сохраняют свои ответы: заново запускаются только остальные.

Агенты работающего workflow не могут запускать собственные workflows.

## Запуск без подтверждения

В разделе **Инструмент Workflows** параметр **Запускать без моего подтверждения** определяет, будет ли запуск, начатый агентом, ждать вашего нажатия:

- **Нет**: каждый запуск ждёт, пока вы выберете **Запустить workflow**
- **Для лидов**: запуски, которые начинает [лид](/ru/leads/), стартуют сразу; остальные сессии по-прежнему ждут
- **Всегда**: каждый запуск начинается сразу

Запуск, который стартует автоматически, сразу отмечен в карточке как выполняющийся, без кнопки **Запустить workflow**. При этом вы всё равно можете нажать **Остановить**. Настройка полезна для работы, которую вы уже согласовали и оставили: например, попросили агента опробовать несколько моделей на маленьком тесте и затем выполнить всю задачу на лучшей, пока вас нет.

Обычная сессия всё равно сначала предлагает в чате план и модели — настройка пропускает только нажатие кнопки. Лид самостоятельно управляет своей работой, поэтому с вариантом **Для лидов** может начать запуск без отдельного вопроса. Сервер считывает настройку при каждом запуске: переключение обратно на **Нет** снова заставляет все запуски ждать подтверждения. Ограничения ниже не меняются.

## Модели и стоимость

Каждый агент workflow использует модель вашей сессии, если скрипт не указывает другую. Десятки агентов на дорогой модели обойдутся во много раз дороже, чем на небольшой. Поэтому агент предлагает модель для каждого этапа: более дешёвую — для чтения и сверки с готовым списком, более сильную — там, где нужно оценивать варианты или писать код для вашего проекта. Если выбор не подходит, измените его до подтверждения запуска.

Одновременно работают не более 8 агентов, а за все попытки одного запуска можно запустить не более 200 агентов.

## Панель Workflows

Панель **Workflows** справа показывает запуски проекта: агентов, журнал, результат и скрипт, а также модель и расход токенов каждого агента. Откройте сессию любого агента из панели или карточки в чате, чтобы прочитать весь его разговор. Значок панели появляется, когда у проекта есть хотя бы один запуск или сохранённый workflow.

Агенты workflow не отображаются в боковой панели сессий: один запуск может создать сотню агентов. Доступ к ним остаётся через карточку запуска и панель Workflows.

**Удалить запуск** убирает завершённый запуск из панели. Сессии агентов сохраняются.

## Сохранённые workflows

Попросите агента сохранить workflow, который понадобится снова. Он сохраняется в проекте как `.openchamber/workflows/<name>.js`, поэтому его можно закоммитить вместе с репозиторием.

Запустите сохранённый workflow через **Сохранённые workflows** в меню выбора запусков на панели. Он сразу начнётся в открытой или новой сессии, куда затем придёт отчёт. Также можно попросить агента запустить его по имени.
