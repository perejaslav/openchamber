# Конфигурация в репозитории

Действия проекта, команды настройки рабочего дерева Git (worktree) и стартеры черновика (draft starters) по умолчанию живут в ваших собственных настройках OpenChamber. Больше их никто не видит. Если вы хотите, чтобы коллега, склонировав репозиторий, получил то же действие dev-сервера и тот же `bun install` в каждом новом рабочем дереве, перенесите эти элементы в репозиторий.

OpenChamber хранит их в файле `.openchamber/project.json` в корне репозитория. Файл появляется, только когда вы переносите туда первый элемент, и исчезает, когда убираете последний. Коммитьте его как любой другой файл.

## Что где лежит

| Остаётся в ваших настройках | Можно перенести в репозиторий |
|---|---|
| Заметки и todo | Действия проекта |
| Запланированные задачи | Команды настройки рабочего дерева |
| Какое действие репозитория скрыто у вас | Стартеры черновика (закреплённые команды и навыки) |
| Ваш ответ о доверии к командам репозитория | Планы |

Запланированные задачи ваши и никогда не попадают в репозиторий. Заметки и todo тоже остаются в ваших настройках, если вы не включите для проекта **Keep notes and todos in the repository** (см. [Заметки, todo и планы проекта](/notes-todos-plans/)).

## Перенос элемента

Откройте **Settings → Projects** и выберите проект. У каждого действия и каждой команды настройки есть кнопка **Move to repository**, а у каждого элемента, пришедшего из репозитория, — **Move to my settings**. Стартеры на экране новой сессии показывают ту же пару при наведении. У планов она есть в каждой строке вкладки Plans.

Перенос — это именно перенос. Элемент уходит из одного места и появляется в другом, ничего не дублируется.

Элементы из репозитория показывают значок **In repo**. Действия из репозитория можно скрыть из своего меню кнопкой **Hide for me**. Это меняет только ваше меню, а не файл.

## Файл

```json
{
  "version": 1,
  "setupWorktree": [
    "bun install"
  ],
  "setupWorktreeWait": true,
  "teardownWorktree": [
    "docker compose down"
  ],
  "projectActions": [
    {
      "id": "dev",
      "name": "Dev server",
      "command": "bun run dev",
      "icon": "rocket",
      "autoOpenUrl": true,
      "platforms": ["macos", "linux"]
    },
    {
      "id": "test",
      "name": "Tests",
      "command": "bun test"
    }
  ],
  "draftStarters": [
    { "type": "skill", "name": "triage-prs" }
  ],
  "plansDir": "docs/plans"
}
```

Обязателен только `version`. Все остальные ключи необязательны, и OpenChamber записывает только те, которые что-то содержат.

`setupWorktree` — список shell-команд, которые OpenChamber выполняет внутри нового рабочего дерева сразу после его создания, по порядку. Используйте `$ROOT_PROJECT_PATH` для пути к основной рабочей копии. `setupWorktreeWait: true` заставляет OpenChamber дождаться этих команд, прежде чем запускать сессию в рабочем дереве.

`teardownWorktree` — список shell-команд, которые OpenChamber выполняет внутри рабочего дерева непосредственно перед его удалением или архивацией, по порядку, например `docker compose down` для стека, который запустило рабочее дерево. Если одна из них завершится ошибкой, рабочее дерево останется, а OpenChamber покажет ошибку команды. Сначала выполняются команды из репозитория, затем ваши, в том числе когда вы используете только свои команды настройки. На них распространяется тот же вопрос о доверии, что и на команды настройки.

`projectActions` — список действий проекта, тех, которые вы запускаете из Work Status, из диалога действий проекта и из палитры команд. `id`, `name` и `command` обязательны. `icon` необязательна и по умолчанию берётся значок play; OpenChamber знает такие имена: `play`, `build`, `lint`, `terminal`, `tools`, `bug`, `flask`, `rocket`, `code`, `server`, `branch`, `search`, `settings`, `brain`, `stack`, `robot`, `command` и `file`. `autoOpenUrl: true` открывает адрес, который выводит команда, см. [Предпросмотр и dev-серверы](/preview/). `platforms` ограничивает действие значениями `macos`, `linux` или `windows`. `runIn: "parent"` выполняет действие в основной рабочей копии, а не в текущем рабочем дереве.

`draftStarters` закрепляет команды и навыки на экране новой сессии. Каждая запись — `{ "type": "command" | "skill", "name": "..." }`, а сама команда или навык должны существовать в конфигурации OpenCode этого репозитория.

`plansDir` — где лежат планы репозитория. Пропустите его, чтобы использовать `.openchamber/plans`. См. ниже.

Этот файл можно писать вручную. Ключ неправильной формы делает весь файл недействительным, и страница Projects говорит почему, вместо того чтобы молча его игнорировать.

## Как сочетаются элементы из репозитория и ваши

Команды настройки из репозитория выполняются первыми, затем ваши. Отметьте **Use only my setup commands** в разделе Worktree, чтобы вообще пропустить команды репозитория.

Действия объединяются по `id`. Действие в ваших настройках с тем же id, что и действие из репозитория, заменяет его. Стартеры объединяются по названию.

Флаг ожидания берётся из ваших настроек, если вы его задали, иначе из репозитория.

## Доверие

Команды настройки и действия из репозитория выполняются на вашей машине, а `git pull` может их изменить. Поэтому в первый раз, когда одно из них вот-вот выполнится, OpenChamber показывает точный текст команд и спрашивает. **Trust and run** запоминает ваш ответ на этом экземпляре. **Not this time** выполняет только ваши собственные команды.

Ответ привязан к самим командам. Когда pull меняет команду из репозитория, вопрос возвращается для нового текста. Забыть ответ можно кнопкой **reset trust** в разделе Worktree настроек проекта.

Перенос своей команды в репозиторий считается доверием к ней, ведь вы только что её видели.

## Планы в репозитории

Планы на вкладке Plans тоже могут жить в репозитории как файлы Markdown. По умолчанию это папка `.openchamber/plans`. Задайте **Plans folder** в настройках проекта, чтобы использовать другую папку внутри репозитория, например `docs/plans`, если ваша команда уже держит планы там. Своя папка полностью заменяет папку по умолчанию: OpenChamber читает и пишет только её, поэтому при смене перенесите существующие файлы сами.

Каждый файл `.md` в этой папке показывается на вкладке Plans, включая файлы, написанные другими инструментами. Правка в OpenChamber сохраняет файл так, как вы его набрали. План, перенесённый в репозиторий, сохраняет свою идентичность, поэтому сессии, к которым он был прикреплён, по-прежнему его находят.
