# Git-идентичности

Git-идентичность — это имя и email, которые несут ваши коммиты, и способ, которым репозиторий входит на свой remote. Если вы работаете и с личными, и с рабочими репозиториями, можно сохранить идентичности и применять нужную для каждого репозитория. Управляйте ими в **Settings → Git**.

## Добавление идентичности

1. Откройте **Settings → Git** и выберите **New**.
2. Введите **User name** и **Email address**, с которыми коммитить.
3. Выберите **Auth method** — то, как идентичность делает push и pull:
   - **This machine**: то, что Git на этой машине уже использует, например SSH-ключи, менеджер учётных данных или CLI `gh`
   - **Account**: выбранная вами **Source control account**, любая учётная запись, подключённая на карточке хоста в [Integrations](/integrations/), например GitHub, GitLab, Gitea, Forgejo или Gerrit; push идёт по HTTPS с токеном этой учётной записи
   - **SSH**: ключ, который OpenChamber хранит для этой идентичности
   - **Anonymous**: читает публичные репозитории по HTTPS без входа и не может делать push
4. По желанию задайте ей цвет и значок, чтобы её было легко узнать.

Глобальная идентичность вашей системы тоже показывается, только для чтения.

В Gerrit идентичность с учётной записью входит в Git с вашим именем пользователя Gerrit и HTTP-паролем, который вы подключили. Учётная запись GitHub Enterprise обслуживает issue и пул-реквесты, но клонирование и push там идут через **This machine** или **SSH**.

## Применение идентичности к репозиторию

Нажмите кнопку идентичности в верхней части [панели Git](/git/) и выберите нужную. Экраны добавления и клонирования предлагают тот же выбор. Идентичность, которая не может добраться до репозитория, остаётся в списке, но выключенной, с причиной: учётная запись на другом хосте, учётная запись или **Anonymous** на SSH-remote, либо SSH-ключ на HTTPS-remote.

Применение идентичности записывает её в **локальную** конфигурацию git этого репозитория, поэтому она влияет только на этот репозиторий, а ваша глобальная настройка остаётся как есть. Git в терминале и shell агента тоже её используют. **System identity** удаляет то, что записал OpenChamber, и снова отвечает ваша собственная конфигурация Git.

## Пароли SSH-ключей

Для зашифрованного SSH-ключа введите его необязательный пароль перед **Find keys in ~/.ssh**, затем подтвердите отпечаток и добавьте ключ. OpenChamber хранит ключ зашифрованным и сохраняет пароль в хранилище учётных данных OpenCode. Сохранённые пароли работают только для действий Git в приложении. Команды Git в терминале и запущенные агентом их не получают, поэтому зашифрованный управляемый ключ не может пройти аутентификацию этим путём.
