# Host API

Эта страница нужна, когда требуются точные методы `connectHost`, лимиты и коды ошибок. Об устройстве папок, манифесте и установке читайте в разделе [Создание расширения](/sdk/).

```ts
import { connectHost, HostRequestError } from "@openchamber/sdk";

const host = connectHost();
```

`connectHost` выбрасывает `HOST_UNAVAILABLE`, если нет `window`. Вне OpenChamber он возвращает клиент, у которого каждый вызов отклоняется с `HOST_UNAVAILABLE`. Вызывайте `dispose()`, когда убираете страницу; вызовы, которые ещё выполняются, отклоняются с тем же кодом.

## Что OpenChamber присылает вам

`onReady` срабатывает с первым снимком и снова каждый раз, когда OpenChamber его обновляет.

Это не одноразовый колбэк монтирования. Смонтируйте интерфейс и зарегистрируйте подписки один раз; последующие снимки используйте, чтобы обновлять тему и контекст, не заменяя поля ввода и черновики. Пример с защитой от повторного монтирования — в [UI-ките](/sdk/ui/). Слушатели полей вроде `onConnection` повторяют текущее значение и могут получить его снова вместе с обновлённым снимком. Сравнивайте поля, от которых зависят ваши данные, прежде чем запускать новый запрос, и игнорируйте ответы устаревших запросов.

| Поле | Что это |
| --- | --- |
| `theme.mode` | `light` или `dark` |
| `theme.tokens` | цвета приложения (поверхности, текст, состояния взаимодействия, primary, success/warning/error/info), `font`, `mono` и `radius`. Передайте это в `applyHostReady` до того, как смонтируете интерфейс. |
| `locale` | тег языка приложения |
| `directory` | каталог текущего проекта или `null` |
| `session` | `{ id, title, busy }` или `null`. Если заголовка нет, вместо него берётся id сессии. `busy` — живой статус. `model` и `agent` (агент OpenCode) появляются, когда они есть у сессии. |
| `surface` | `panel` на рейке, `dialog` в окне прикрепления, `page` во весь экран, `status` в панели Work Status, `file` как редактор файлов в Files, `block` в UI-блоке в чате |
| `item` | для чего открыта эта поверхность, или `null`: прикреплённый элемент, по которому кликнул пользователь (те же поля, что вы передали в `attach`, включая `data`), сообщение (`kind: "message"`) или сессия (`kind: "session"`) из одного из объявленных вами действий. См. [Действия](/sdk/#actions-commands-and-the-badge). |
| `connection` | `{ connected, account }` для вашей интеграции |
| `settings` | значения полей, объявленных вами в `integration.settings` |
| `device` | `{ formFactor, pointer, insets, keyboard }`: `phone`, `tablet` или `desktop`; `coarse` или `fine`; отступы безопасной зоны в px; px, которые закрывает экранная клавиатура. Присылается снова при изменении, например при повороте или появлении клавиатуры. Старые хосты его не передают. См. [На телефоне](/sdk/#on-the-phone). |

Токены доступа здесь никогда не появляются, как и в результате `request`.

`ready.session` и `onSession` также дают необязательные значения `context` и `tokens`. `context: { tokens, limit } | null` — заполнение контекстного окна после последнего шага ассистента, причём `limit: null`, когда окно модели неизвестно. После сжатия контекста оно становится `null` до следующего измеренного ответа. `tokens: { prompt, output, reasoning, cacheRead, cacheWrite, cacheHitPercent } | null` содержит накопленное использование в сессии. `prompt` включает некешированный ввод плюс чтения и записи кеша, а `cacheHitPercent` равен `null`, когда токенов промпта нет. Оба значения равны `null`, пока их нельзя измерить; старые хосты их не передают. Изменения приходят через `onSession`.

`onDirectory`, `onSession`, `onSessionLifecycle`, `onConnection`, `onSettings` и `onItem` повторяют последнее значение, если вы подписались поздно, а затем продолжают срабатывать при каждом изменении.

`theme.tokens` включает `primaryText`, `successText`, `warningText`, `errorText` и `infoText`. Эти обязательные поля содержат вычисленные хостом цвета текста для нейтральных фонов и тонированных элементов UI-кита, а не сплошные заливки. `applyHostReady` применяет их при каждом снимке. CSS-переменные описаны в [UI-ките](/sdk/ui/).

| `reportFileUnsupported()` | редакторы файлов: этот файл нельзя открыть здесь, покажите вместо него его исходник |

## attach, startSession и sessionLink

Все три принимают одни и те же поля элемента:

```ts
await host.attach({
  providerId: "acme-hello",
  id: "TICKET-1",
  title: "Login is broken",
  url: "https://example.com/TICKET-1",
});

await host.attach({
  providerId: "acme-hello",
  id: "!12",
  title: "Fix login",
  url: "https://example.com/merge_requests/12",
  kind: "pull",
  author: "ada",
  branches: { head: "feature", base: "main" },
  text: "Optional notes for the model",
});

await host.startSession({
  providerId: "acme-hello",
  id: "!12",
  title: "Fix login",
  url: "https://example.com/merge_requests/12",
  kind: "pull",
  worktree: true,
  text: "Optional first message",
});
```

`providerId` — это id вашей панели; OpenChamber всё равно перезаписывает его вашим id. `id` — ваш собственный идентификатор элемента. `kind` — `issue` (по умолчанию) или `pull`. `text` — необязательный контекст для модели, от 1 до 16000 символов после обрезки пробелов. `data` — необязательный ваш собственный JSON (статус, комментарии, что угодно), до 16000 символов в сериализованном виде. OpenChamber хранит его вместе с чипом и возвращает без изменений в `ctx.item`, когда пользователь нажимает на чип; в модель он никогда не попадает.

`startSession` принимает `projectId`, не переключая текущий проект. Не указывайте `worktree` для целевого каталога, используйте `true` для сгенерированного рабочего дерева, `{ kind: "existing", directory }` для известного рабочего дерева или `{ kind: "new", name?, baseBranch? }` для нового с именем. Имя задаёт и ветку, и рабочее дерево. `navigation` по умолчанию равно `"preserve"`; `"open"` выбирает новый чат. Модель, агент и вариант для первого сообщения фиксируются в момент начала создания.

Результат содержит `sessionId`, `directory`, `sent`, `linked` и необязательный `worktree`. `sent` принимает значения `sent`, `no-model`, `skipped` или `failed`; `linked: false` означает, что элемент не был сохранён в созданной сессии. Если после сбоя начальной подготовки или создания сессии осталось рабочее дерево, возвращается `sessionId: null` и `failure: "bootstrap-failed" | "session-create-failed"`, а также его каталог и рабочее дерево. Проверьте этот результат перед повторной попыткой. Вызов ждёт до 180 секунд; тайм-аут не означает, что создание откатили.

`sessionLink` прикрепляет элемент к сессии, которая открыта сейчас. Нет проекта или нет сессии — ошибка `NO_SESSION`.

Ограничения, которые клиент проверяет до того, как что-либо отправить:

| Поле | Максимум символов |
| --- | --- |
| `id` | 128 |
| `title` | 200 |
| `url` | 2000 |
| `text` | 16000 |
| `data` (сериализованный) | 16000 |
| `author` | 80 |
| каждое имя ветки | 200 |

## prompt и жизненный цикл сессии

```ts
await host.prompt({ text: "Fix the login" });
await host.prompt({ text: "Fix the login", send: true });

host.onSessionLifecycle((event) => {
  document.body.dataset.phase = event.phase;
});
```

Без `send` вызов `prompt` заменяет текст в поле ввода чата. С `send: true` он отправляет сообщение той моделью и тем агентом, которые выбрал пользователь. Расширение никогда их не выбирает. Нет открытой сессии — `NO_SESSION`. Отправка, пока сессия занята, — `SESSION_BUSY`; запись в поле во время занятости работает. Результат — `{ sent }` с теми же значениями, что у `startSession`.

`onSessionLifecycle` сообщает, что делает сессия. `phase` равно `started`, пока работает модель, `completed`, когда она переходит в простой, и `failure` при неожиданном статусе. Поздний слушатель сразу получает текущую фазу.

## Проекты, рабочие деревья и живые сессии

Эти методы используют существующее разрешение `sessions` и общие хранилища приложения. Они не запускают сканирование Git на каждый запрос и не раскрывают содержимое разговоров.

```ts
const projects = await host.listProjects();
const projectId = projects.projects[0]?.id;
if (projectId) {
  const worktrees = await host.listWorktrees(projectId);
  const sessions = await host.listSessions(projectId);
  const stop = await host.onSessions(projectId, (snapshot) => {
    renderSessions(snapshot.sessions, snapshot.state);
  });
  // Call stop() when this view closes.
}
```

`onProjects(listener)` и `onWorktrees(projectId, listener)` работают так же. Дождитесь завершения регистрации, чтобы поймать ошибки разрешений; результат — функция отписки. Каждый сначала присылает начальный снимок, а затем изменения. `dispose()` освобождает все подписки. Хост разрешает не более 32 на фрейм и сбрасывает их при размонтировании, паузе, удалении или переключении сервера.

У снимков есть `state: "loading" | "ready" | "error"`. Состояния загрузки и ошибки могут сохранять данные; только `ready` устанавливает полный успешный результат, в том числе пустой. Снимки сессий включают `coverage` по каталогам и известные архивные сессии. Проекты отдают ID, имя и каталог; рабочие деревья — каталог, имя, ветку и доступность. Сессии включают свой проект, каталог и рабочее дерево, отметки времени, ID родителя и ID и данные прикреплённых элементов этого расширения.

`activity` сессии принимает значения `unknown`, `idle`, `running`, `retrying`, `waiting-permission` или `waiting-question`. `outcome` — наблюдавшийся ход `completed`/`failed` или `null`. Он не восстанавливается из истории и хранится в памяти не более чем для 2000 наблюдавшихся сессий. Простой после ошибки сохраняет неудачный исход до следующего запуска. Ни простой, ни завершение не помечают вашу задачу как Done. `inWork` равно `true`, когда сессия находится в блоке In work боковой панели, и всегда `false`, пока у пользователя выключен In work; старые хосты его не передают. `unread` равно `true`, когда последний ход завершился и с тех пор никто не открывал сессию, — это метка, которую показывает боковая панель; она переживает перезапуски и снимается на каждом устройстве. Для явного перехода от карточки к её чату используйте `host.openSession(sessionId)`.

`tool` — то, с чем работает сессия, пока `activity` равно `running`: вызов инструмента, который идёт сейчас, или тот, что завершился последним, пока агент думает над его результатом. Это `name`, как его называет OpenCode (`read`, `edit`, `bash`), и `target` — файл или папка, которые называет вызов, относительно `directory` сессии (для пути вне неё — только имя), либо `null`, если вызов ничего не называет. Текст shell-команды в нём никогда не появляется. `context` — насколько заполнено контекстное окно после последнего шага сессии: `tokens`, которые оно содержало, и `limit` — окно модели, или `null`, если хост его не знает. `tool` равно `null`, когда сессия не выполняется; `context` равно `null`, пока хост не видел ни одного шага, и после сжатия контекста до следующего шага, который измерит окно. Старые хосты не передают оба поля. Необязательное поле `tokens` содержит накопленное использование в сессии в той же форме, что `ready.session.tokens`; оно равно `null`, пока сессия не сообщит о ненулевом использовании.

## Фоновые shell-команды

С возможностью `shells` следите за shell-командами, выполняющимися в фоне, в пределах сессии и её субагентов, зарегистрированного проекта или всех сессий. OpenChamber отвечает из своего локального хранилища; сетевого чтения не происходит.

| Вызов | Что делает |
| --- | --- |
| `onRunningShells(scope, listener)` | подписаться на shell-команды в области: `{ kind: 'session', sessionId }` охватывает сессию и её субагентов, `{ kind: 'project', projectId }` — зарегистрированный проект, а `{ kind: 'global' }` — все сессии. Вы получаете выполняющиеся команды от старых к новым, каждую с её флагом `background`, и те, что завершились. Возвращает функцию отписки. |
| `readShellOutput(shellId, { cursor?, tailBytes? })` | одна страница вывода выполняющейся или завершённой команды. Без `cursor` она начинается на `tailBytes` (до 65536) раньше конца. Возвращает `{ output, cursor, skipped }`. |
| `stopShell(shellId)` | сначала отправить агенту заметку об остановке, затем удалить команду. |

Снимок — это `{ kind: "shells", scope, shells, ended }`, где `scope` повторяет область подписки. Каждая выполняющаяся команда — `{ id, sessionID, command, startedAt, background }`, не более 200, от старых к новым. `background` равно `true` для задачи, которую ход не ждёт.

`ended` перечисляет команды, завершение которых видел OpenChamber, от старых по времени завершения, не более 200, самые новые сохраняются. К каждой добавляются `status`, `endedAt` и `exit`, когда команда завершилась с кодом. Статус — `exited`, `timeout`, `killed` сигналом, `stopped` пользователем или `unknown`, когда завершение произошло во время переподключения. OpenChamber хранит этот список только в памяти. После перезагрузки приложения он пуст, поэтому сохраняйте то, что показывает ваша панель, в хранилище расширения.

OpenCode хранит вывод завершённой команды для последних 25 завершённых команд в каждом каталоге. Остановленная команда теряет вывод сразу. Чтение shell-команды, которую OpenChamber никогда не видел, или вывода, которого у OpenCode больше нет, — `NOT_FOUND`. Так же и остановка команды, которая не выполняется. Неподтверждённая возможность `shells` — `NOT_GRANTED`.

## Микрофон

С возможностью `microphone` вызов `openMicrophone()` даёт вашей панели микрофон пользователя как `MediaStream`. Ваш фрейм не может сам вызвать `getUserMedia`, поскольку браузер не разрешает его песочнице фрейма, поэтому OpenChamber захватывает звук и передаёт его внутрь.

```ts
button.addEventListener("click", async () => {
  const microphone = await host.openMicrophone();
  peer.addTrack(microphone.stream.getAudioTracks()[0], microphone.stream);
  microphone.onEnded((reason) => showEnded(reason));
  hangUp.onclick = () => microphone.close();
});
```

Открывайте его по клику внутри вашего фрейма: звук начинается только по жесту пользователя. Сначала проверьте `features.microphone` в `onReady`; старые хосты и скрытые фоновые фреймы отвечают `UNSUPPORTED`. На фрейм открыт один микрофон, поэтому второй вызов, пока он открыт, — `HOST_REJECTED`. Отказ пользователя или системы — `DENIED`, отсутствие устройства ввода — `NOT_FOUND`, а неподтверждённая возможность — `NOT_GRANTED`.

`close()` останавливает захват и завершает дорожку. `onEnded` сообщает, когда OpenChamber остановил его сам: `revoked`, когда пользователь отозвал возможность или поставил расширение на паузу, `device-lost`, когда устройство пропало. Перезагрузка или удаление фрейма тоже останавливает его. Поток монофонический, с включённым эхоподавлением, шумоподавлением и автоматической регулировкой усиления.

## Постоянные данные расширения

```ts
await host.storage.set("board", { columns: ["Todo", "Review"] });
const board = await host.storage.get("board");
const keys = await host.storage.keys();
await host.storage.delete("board");
```

Дополнительное разрешение не нужно. Хранилище принадлежит этому расширению на подключённом сервере, переживает перезагрузки и удаляется при удалении расширения. `get` возвращает `undefined` для отсутствующего ключа; сохранённый JSON null остаётся null. Ключи содержат от 1 до 128 символов. Каждое сериализованное значение JSON — не более 64 KiB в UTF-8, а всё пространство имён — не более 2 MiB или 2000 ключей. Для данных конкретного проекта используйте ID проекта в ключе. Записи выполняются последовательно и атомарно; при сбое существующие данные сохраняются.

## request

```ts
const user = await host.request({ method: "GET", path: "/api/v2/user" });
```

`path` начинается с `/` и не содержит схемы или хоста; OpenChamber присоединяет его к `apiOrigin` из вашего манифеста и добавляет заголовок `Authorization`. Интеграции с токеном отправляют вставленный токен как есть, как `Bearer <token>`, если манифест задаёт `token.scheme: "bearer"`, или как `Basic base64(username:token)`, если он задаёт `"basic"`. Интеграции OAuth и Linear всегда отправляют `Bearer`. Результат — `{ status, body }`. Тело приходит текстом; JSON разбирайте сами.

Интеграция с Linear также может вызвать `GET /api/linear/issues/get`, на который OpenChamber отвечает из собственного маршрута Linear.

Если ответа нет в течение 20 секунд — `HOST_TIMEOUT`.

```ts
try {
  await host.request({ method: "GET", path: "/api/v2/user" });
} catch (error) {
  if (error instanceof HostRequestError && error.code === "DISCONNECTED") {
    await host.oauthStart();
  }
}
```

## serviceRequest

Когда манифест объявляет `contributes.service`, OpenChamber запускает этот процесс, а ваша страница общается с ним через такой же вызов. Страница никогда не открывает сокет сама.

```ts
const status = await host.serviceStatus();
const result = await host.serviceRequest({ method: "GET", path: "/containers" });
```

`path` подчиняется тем же правилам, что и в `request`. Объявление сервиса добавляет `service` к возможностям, которые пользователь подтверждает при установке; до этого каждый `serviceRequest` — `NO_SERVICE`. Полный контракт — файл пакета `GUEST_SERVICES.md`.

## События сессий

Ваша страница знает о сессии, только пока она открыта. Ваш сервис может знать больше: объявите `contributes.sessionEvents` рядом с `contributes.service`, и OpenChamber будет отправлять сервису перечисленные события из всех проектов, открыто окно или нет.

```json
"service": { "entry": "service/main.js", "runtime": "host" },
"sessionEvents": { "events": ["turn-finished", "question-asked"], "content": true }
```

События: `turn-started`, `session-created`, `session-archived`, `session-deleted`, `turn-finished` (агент закончил и ничего не ждёт: нет работающих субагентов, нет открытого разрешения или вопроса, нет шага цели), `turn-failed`, `permission-asked` и `question-asked`. Ход, который остановил пользователь, ничего не отправляет. Подтверждение расширения и есть подписка; диалог перечисляет события под строкой сервиса. Без `content` сервис получает только идентификаторы: сессию, каталог её проекта, элементы, которые пользователь к ней прикрепил. С `"content": true` манифест также запрашивает разрешение, которое пользователь видит отдельной строкой — **Read what the agent says in the background**, — и каждое событие несёт финальный ответ агента, поля вопроса или подробность разрешения.

Каждое событие приходит одним `POST /session-events` с bearer-токеном сервиса. Прочитайте его через `readSessionEventRequest` и ответьте `{ "ok": true }`:

```ts
import { SESSION_EVENTS_PATH, readSessionEventRequest } from "@openchamber/sdk";

// inside your service's request handler, after the bearer check
if (url.pathname === SESSION_EVENTS_PATH) {
  const request = readSessionEventRequest(body);
  if (!request) return json(res, 400, { ok: false, error: "not a session event" });
  const { event, content } = request;
  if (event.type === "turn-finished" && event.project.directory === myProject) {
    await postComment(event.linked, content?.type === "turn-finished" ? content.reply : "");
  }
  return json(res, 200, { ok: true });
}
```

События из каждого проекта отправляются; сравните `event.project.directory` со своими настройками и на остальные ответьте `{ "ok": true }`. Доставка не более одного раза и по порядку, по одному запросу за раз; неудачный ответ отбрасывает ваши события на 30 секунд, и после простоя OpenChamber или вашего сервиса ничего не повторяется. Панель сервису для этого не нужна. Пример `session-events-log` записывает каждое событие в файл.

## Вызов OpenChamber из вашего сервиса

Сервис может действовать без открытого окна. `createServiceHost` — его способ вернуться:

```ts
import { createServiceHost } from '@openchamber/sdk';

const host = createServiceHost({ env: process.env });

const { sessionId } = await host.sessions.start({ prompt: 'Summarize the failed deploy', directory });
await host.sessions.send(sessionId, 'Now write the incident note');
await host.setInstructions(directory, 'Deploys run through the release branch.');
await host.emit('deploy-finished', { id: 42 });
```

`sessions.start`, `sessions.send`, `sessions.retry`, `sessions.status` и `sessions.stop` требуют `contributes.sessionControl`, который пользователь подтверждает отдельной строкой. `sessions.lastReply` требует `sessionControl: { content: true }`. Сообщение из `sessions.send` закрывает форму или страницу, которую агент ждёт в этой сессии, как и сообщение, набранное в чате.

Чтобы передавать запросы агента куда-то ещё, например в чат-приложение, добавьте `answers: true`. Пользователь подтверждает это ещё одной строкой, и после этого сервис может отвечать за него в любой сессии: `sessions.answerPermission(sessionId, requestId, { decision: 'allow' })` (или `'deny'` с `message`, который прочитает агент) для события `permission-asked` и `sessions.answerForm(sessionId, formId, values)` для события `question-asked`, у которого `event.question.kind` равен `form`. Содержимое события перечисляет поля формы с их `key` и вариантами. `null` вместо значений закрывает форму. Разрешение `allow` действует на один этот запрос.

`setInstructions` требует `contributes.instructions` и добавляет к тому, что читают агенты, в одной папке или, с `null`, везде.

`emit` доходит до ваших открытых фреймов через `host.onServiceEvent`, поэтому панель перестаёт опрашивать сервер. Ничего не повторяется, поэтому фрейм, который откроется позже, сначала читает текущее состояние. `readSettings` даёт сервису настройки интеграции, включая поля `secret`, а `needsConfiguration` показывает сообщение на карточке расширения.

## Работа без внешних запросов

Сервис запускается по первому запросу, а сервис роли останавливается, когда простаивает. `service.keepRunning: true` запускает его вместе с OpenChamber и возвращает к жизни, когда он останавливается. `service.schedule` будит его по часам:

```json
"service": {
  "entry": "service/main.js",
  "runtime": "host",
  "keepRunning": true,
  "schedule": [{ "id": "nightly", "cron": "0 3 * * *", "timezone": "Europe/Kyiv" }]
}
```

Один запуск — это один `POST /schedule`. Прочитайте его через `readServiceScheduleRequest` и ответьте 200. Запуск, пропущенный, пока OpenChamber был выключен, потерян. Сервис, которому нужны внешние события, держит собственное соединение или опрашивает сервер.

## Метки на строках боковой панели

`contributes.marks: true` позволяет вашему сервису ставить маленькие иконки на строки боковой панели, например красный крестик на каждой сессии ветки, у которой не проходят проверки. Пользователь подтверждает это отдельной строкой.

```ts
await host.setMark({ directory, branch: 'feature/login' }, { icon: 'close-circle', tone: 'error', text: 'Checks failed' });
await host.setMark({ sessionId }, { icon: 'robot-2', tone: 'info', text: 'Started from the desk' });
await host.setMark({ sessionId }, null);
```

| Цель | Строки |
| --- | --- |
| `{ sessionId }` | эта сессия |
| `{ directory, branch }` | все сессии на этой ветке и строка рабочего дерева этой ветки; `directory` — любая папка репозитория |
| `{ directory }` | сессии в этой папке и рабочее дерево в ней |

`icon` — имя из Remixicon, `tone` — `neutral`, `info`, `success`, `warning` или `error`, а `text` (до 200 символов) — подсказка, которая показывается после имени расширения. Клик открывает вашу панель в сессии этой строки. Расширение без панели может добавить адрес `https` как `url`, и клик откроет этот адрес. На телефоне касание открывает вкладку рабочей области вашей панели в сессии этой строки, если манифест задаёт `panel.mobile`; иначе оно показывает `text` метки и открывает её `url`, если он есть.

Повторная установка цели заменяет её метку, а `null` удаляет её. Строка рисует не более двух меток, по одной от расширения, и перечисляет их все в своей подсказке. На однострочной строке кнопки строки закрывают метки, пока указатель над ней, поэтому клик доходит до метки на двухстрочных строках и на сенсорных экранах.

Метка живёт столько же, сколько процесс вашего сервиса, поэтому объявите `service.keepRunning` и ставьте метки заново при запуске сервиса. Сервис держит до 200 меток и меняет их до 60 раз в минуту. Меткам нужен релиз OpenChamber новее 2.7.0: более старый игнорирует ключ и отклоняет вызов.

## Строки в меню @

`contributes.mentions: { label }` добавляет раздел в меню `@` поля ввода. Ваш сервис отвечает на `POST /mentions/search` объектом `{ items: [{ id, title, subtitle?, url? }] }` в течение 2 секунд и на `POST /mentions/resolve` объектом `{ text }` для строки, которую выбрал пользователь. Текст уходит агенту вместе с сообщением, а пользователь видит чип. Медленный сервис не добавляет строк и никогда не задерживает файлы; строка, которую не удалось прочитать, не оставляет чипа и сообщает об этом.

## Блоки в чате

`contributes.blocks` добавляет компоненты, которые агенты могут писать в UI-блоке. Каждый из них рисует ваша собственная страница, в той же песочнице и с теми же правами, что и ваша панель.

```json
"blocks": [{ "name": "JiraIssue", "description": "A Jira ticket", "args": ["key"], "entry": "blocks/issue.html" }]
```

Агент пишет `JiraIssue("OPE-1")`, а ваша страница читает вызов:

```ts
host.onBlock(({ args }) => draw(args.key));
```

Вызывайте `host.setHeight(px)` из `ResizeObserver` на вашем корневом элементе. Фрейм заполняет свой блок без отступов, поэтому добавьте свои. До 4 компонентов на расширение, поскольку каждую сигнатуру читает каждая сессия.

Блок может ответить агенту, как это делает кнопка в блоке. Вызовите `host.answerBlock(text)` по клику: агент получает текст и начинает следующий ход. Один ответ на блок, и `block.answered` хранит его после перезагрузки, поэтому в этом случае рисуйте блок как уже отвеченный.

```ts
host.onBlock(({ args, answered }) => draw(args.key, answered));
button.onclick = () => host.answerBlock('Close this ticket');
```

Задайте `"answers": true` у компонента, который так делает. Агентам велено спрашивать через него вместо встроенного выбора, когда подходит его описание, а страница, которая ждёт ответа, не показывает свою кнопку Send. Под таким блоком OpenChamber предлагает то же поле для заметки, что и в своих формах: агент читает заметку вместе с вашим ответом, и заметка сама по себе тоже считается ответом.

Аргументы пишет модель, поэтому текст с веб-страницы или из тикета может ими управлять. Считайте их недоверенными и не делайте ничего с побочными эффектами, пока пользователь не нажмёт.

## Каналы уведомлений

Сервис может доставлять уведомления пользователя наравне с десктопом и телефоном: объявите `provides: ["notifications"]` и опишите канал в `contributes.notifications`.

```json
"service": { "entry": "service/main.js", "runtime": "host", "provides": ["notifications"] },
"notifications": {
  "label": "Slack",
  "instances": { "kind": "fixed", "origin": "https://slack.com" },
  "token": { "header": "authorization", "scheme": "bearer", "scopes": ["chat:write"] }
}
```

По этому описанию OpenChamber рисует карточку аккаунта для канала в Settings → Integrations и хранит аккаунт: пользователь подключает его там, токен остаётся в OpenChamber, а ваш сервис его никогда не видит. Когда аккаунт подключён, каждое уведомление, которое OpenChamber отправил бы на телефон, идёт и в ваш сервис — после собственных переключателей уведомлений пользователя и только пока ни одно окно не видно, если пользователь не выбрал уведомлять всегда. Пауза расширения останавливает это.

OpenChamber пересылает три вызова на `POST /notifications`: `auth.probe` (этому ли серверу вы доставляете), `auth.verify` (кому принадлежит этот токен) и `notify` (одно уведомление). Читайте каждый через `readNotificationsProviderRequest` и обращайтесь к серверу канала только через помощник исходящих запросов, который отправляет ваш запрос в OpenChamber с handle вызова; OpenChamber добавляет токен и держит запрос на сервере аккаунта.

```ts
import { NOTIFICATIONS_PROVIDER_PATH, createNotificationsOutbound, readNotificationsProviderRequest } from "@openchamber/sdk";

const outbound = createNotificationsOutbound({ env: process.env });

// inside your service's request handler, after the bearer check
if (url.pathname === NOTIFICATIONS_PROVIDER_PATH) {
  const request = readNotificationsProviderRequest(body);
  if (!request) return json(res, 400, { ok: false, error: { message: "not a notifications call" } });
  if (request.method === "notify") {
    const { notification } = request.input as { notification: GuestNotification };
    const answer = await outbound.request(request.session.handle, {
      method: "POST", path: "/api/chat.postMessage",
      headers: { "content-type": "application/json" },
      body: JSON.stringify({ channel: "#agents", text: `${notification.title}: ${notification.body}` }),
    });
    return json(res, 200, answer.status === 200 ? { ok: true, data: { delivered: true } } : { ok: false, error: { message: `Slack answered ${answer.status}`, status: answer.status } });
  }
  // auth.probe → { ok: true, data: { supported: true } }; auth.verify → { ok: true, data: { account: { id, login } } }
}
```

В какую комнату или канал идёт проект — решает ваше расширение: уведомление несёт `directory` и `sessionName`. В корпоративном режиме оно несёт только общий заголовок, как и на телефоне. Пример `notification-webhook` — это готовый канал с получателем, на котором его можно попробовать.

## Трекеры

Сервис может быть трекером рабочих элементов наравне с Linear: объявите `provides: ["tracker"]` и опишите трекер в `contributes.tracker`. Тогда OpenChamber перечисляет его рядом с Linear везде, где появляются трекеры, уже по одному манифесту, до первого запуска сервиса.

```json
"service": { "entry": "service/main.js", "runtime": "host", "provides": ["tracker"] },
"tracker": {
  "wire": 1,
  "label": "YouTrack",
  "instances": { "kind": "user", "label": "Server address", "placeholder": "https://youtrack.example.com" },
  "auth": { "token": { "header": "authorization", "scheme": "bearer", "createPath": "/users/me?tab=account-security" } },
  "capabilities": { "stateUpdate": true, "labels": true, "priority": true, "projectMapping": true, "sessionComments": true },
  "stateFilters": ["open", "all", "todo", "in-progress", "done"],
  "identifier": "key-number",
  "urls": { "item": ["/issue/{id}", "/{segments+}/issue/{id}"] }
}
```

Пользователь подключает аккаунты на карточке трекера в Extension accounts: токен или вход через браузер, если вы объявили `auth.oauth` (OpenChamber проводит вход с client id, который вводит пользователь, и хранит токены). Ваш сервис никогда не видит учётные данные. `urls.item` — шаблоны адреса элемента, с `{id}` для идентификатора (а также как `?name={id}`, когда он передаётся в запросе); OpenChamber компилирует их, чтобы вставленные ссылки становились связанными элементами. `identifier` говорит, как выглядит ключ: `key-number` (`PROJ-42`), `number` или `short-code`.

OpenChamber пересылает девять вызовов на `POST /tracker`: `auth.probe` и `auth.verify`, чтения `items.list`, `items.get`, `items.liveSummaries`, `states.list` и `containers.list`, а также записи `items.updateState` и `comments.create`. Читайте каждый через `readTrackerProviderRequest`, отвечайте в нейтральных формах элементов и обращайтесь к серверу трекера только через помощник исходящих запросов, который отправляет ваш запрос в OpenChamber с handle вызова; OpenChamber добавляет учётные данные и держит запрос на сервере аккаунта. Handle чтения отправляет только `GET`.

```ts
import { TRACKER_PROVIDER_PATH, createTrackerOutbound, readTrackerProviderRequest } from "@openchamber/sdk";

const outbound = createTrackerOutbound({ env: process.env });

// inside your service's request handler, after the bearer check
if (url.pathname === TRACKER_PROVIDER_PATH) {
  const request = readTrackerProviderRequest(body);
  if (!request) return json(res, 400, { ok: false, error: { message: "not a tracker call" } });
  if (request.method === "items.get") {
    const answer = await outbound.request(request.session.handle, { method: "GET", path: `/api/issues/${encodeURIComponent(String(request.input.id))}` });
    if (answer.status === 404) return json(res, 200, { ok: true, data: { item: null } });
    if (answer.status !== 200) return json(res, 200, { ok: false, error: { message: `YouTrack answered ${answer.status}`, status: answer.status } });
    return json(res, 200, { ok: true, data: { item: toTrackerItem(JSON.parse(answer.body)) } });
  }
}
```

Когда пользователь включает комментарии к сессиям, OpenChamber вызывает `comments.create` с текстом «session started», «completed» или «failed» и ссылкой на сессию, по одному разу каждый; больше комментарий ничего не несёт. Пример `tracker-provider` — готовый трекер с подставным сервером, на котором его можно попробовать.

## Провайдеры использования

Сервис может сообщать об использовании наравне со встроенными провайдерами: объявите `provides: ["quota"]` и перечислите в `contributes.quota.providers` провайдеров OpenCode, чьи учётные данные ему нужны. OpenChamber называет провайдера `ext-<panel.id>`, рисует его карточку с именем и иконкой расширения и спрашивает его так же, как встроенного.

```json
"service": { "entry": "service/main.js", "runtime": "host", "provides": ["quota"] },
"quota": { "providers": ["openrouter"] }
```

Диалог подтверждения перечисляет этих провайдеров, а версия, которая меняет список, спрашивает заново. При каждом обновлении OpenChamber отправляет один вызов `usage.read` на `POST /quota`, где `input.credentials` содержит учётные данные, которые OpenCode хранит для каждого перечисленного провайдера, если они у него есть (ключ API или токены входа через браузер), и ничего больше из хранилища. Провайдер из списка, для которого у OpenCode нет учётных данных, показывается как ненастроенный, и сервис не вызывается; пустой список допустим — для провайдера, чей ключ живёт в собственных настройках расширения.

Прочитайте тело через `readQuotaProviderRequest` и ответьте `{ ok: true, data }` с результатом, который вычисляет встроенный провайдер: `ok`, `configured`, `error`, `planLabel` и `usage.windows` с ключами по именам окон, у каждого `usedPercent`, `windowSeconds`, `resetAt` (миллисекунды epoch) и необязательный `valueLabel` или `value`, плюс `usage.models` для окон по моделям. OpenChamber вычисляет оставшуюся долю, обратный отсчёт до сброса и форматированные строки, поэтому карточка совпадает со встроенной.

```ts
import { QUOTA_PROVIDER_PATH, readQuotaProviderRequest } from "@openchamber/sdk";

// inside your service's request handler, after the bearer check
if (url.pathname === QUOTA_PROVIDER_PATH) {
  const request = readQuotaProviderRequest(body);
  if (!request) return json(res, 400, { ok: false, error: { message: "not a usage call" } });
  const credential = request.input.credentials.openrouter;
  const bearer = credential.type === "api" ? credential.key : credential.access;
  const answer = await fetch("https://openrouter.ai/api/v1/key", { headers: { authorization: `Bearer ${bearer}` } });
  if (answer.status === 401) return json(res, 200, { ok: true, data: { ok: false, configured: true, error: "OpenRouter refused the key.", usage: null } });
  return json(res, 200, { ok: true, data: toUsage(await answer.json()) });
}
```

Сервис отвечает в течение 20 с и останавливается после десяти минут без вызовов; страница Usage обновляется каждые три минуты, пока открыта. Пример `quota-provider` — готовый провайдер с подставным API использования, на котором его можно попробовать.

## Файлы

Относительный путь находится внутри открытого проекта и требует возможности `files`. Путь, начинающийся с `/` или `~/`, должен соответствовать объявленному шаблону `contributes.filesystem` и требует возможности `filesystem`. Правила — в разделе [Создание расширения](/sdk/#files).

```ts
const { content } = await host.readFile("package.json");
await host.writeFile("notes/today.md", "# Today\n");
const { entries } = await host.listDir("src");
const info = await host.stat("~/.config/opencode/opencode.json");
```

Ограничения: путь до 1024 символов, содержимое до 2 000 000 символов, листинг до 2000 записей. Превышение лимита содержимого — `FILE_TOO_LARGE`.

## generate

```ts
const { text } = await host.generate({ prompt: notes, system: "Summarize in one sentence." });
```

`prompt` — от 1 до 64 000 символов после обрезки пробелов, `system` — до 8000, `maxOutputTokens` — от 1 до 4000. Ничего не попадает в сессию, и история не сохраняется; расширение никогда не выбирает модель. Вызов ждёт до 960 секунд. Нет подходящей малой модели — `NO_MODEL`; ошибка модели — `MODEL_FAILED`. См. [Генерация текста](/sdk/#generate-text).

Пользователь может закрыть вашу панель или переключиться на другой проект до того, как придёт ответ. Генерация всё равно завершится, и приложение сохранит ответ для вашей следующей панели на той же поверхности и в том же проекте, в том же окне. Зарегистрируйте `onLateGenerateResult`, чтобы получить его там:

```ts
host.onLateGenerateResult((late) => {
  if (late.ok) showSummary(late.request.prompt, late.result.text);
  else showError(late.error);
});
```

`late.request` — это то, что отправила закрытая панель, поэтому вы можете понять, на какой запрос пришёл ответ. Каждый ответ приходит один раз. Приложение хранит ответы час, не более 8 на расширение, и удаляет их, когда расширение выключают или удаляют. Перезагрузка всего приложения или другого окна начинает с пустого места. Приложения, которые не сохраняют поздние ответы, не задают `ready.features.lateGenerateResults` и никогда не вызывают слушатель.

## Коды ошибок

Неудачные вызовы выбрасывают `HostRequestError`. `code` — один из перечисленных; `message` говорит больше.

| Код | Когда |
| --- | --- |
| `HOST_UNAVAILABLE` | нет `window`, вы не внутри OpenChamber или выполнился `dispose()` |
| `HOST_TIMEOUT` | ответа нет 20 секунд |
| `HOST_REJECTED` | OpenChamber отказал или ответил кодом, которого этот SDK не знает |
| `DISCONNECTED` | для вашей интеграции нет токена или подключения Linear |
| `BAD_PATH` | `path` был некорректным или пытался выйти за разрешённый origin |
| `NO_INTEGRATION` | в манифесте нет `integration` |
| `NO_SESSION` | `prompt` или `sessionLink` без открытой сессии |
| `SESSION_BUSY` | `prompt({ send: true })`, пока сессия была занята |
| `DISABLED` | пользователь поставил расширение на паузу в Settings → Extensions |
| `NO_SERVICE` | сервис не объявлен, не подтверждён или не запущен |
| `NOT_GRANTED` | пользователь не подтвердил возможность, которая нужна этому вызову |
| `SERVICE_FAILED` | сервис упал или так и не стал готов |
| `NO_DIRECTORY` | относительный путь к файлу использован без открытого проекта, `openCommit` без открытого проекта или `openSurface` до того, как открыт любой чат или проект |
| `NOT_FOUND` | `readFile` для несуществующего файла или `openCommit` для коммита, которого нет в проекте |
| `FILE_TOO_LARGE` | содержимое файла превышает лимит при чтении или записи |
| `DENIED` | операционная система отказала в операции с файлом |
| `NO_MODEL` | `generate` без доступной малой модели |
| `MODEL_FAILED` | малая модель вернула ошибку |
| `UNSUPPORTED` | этот OpenChamber не может выполнить вызов, например `openCommit` там, где нет представления Diff, или `openSurface` для экрана, который не может открыться в этом месте |
