# Host API

Эта страница пригодится, когда нужны точные методы `connectHost`, ограничения и коды ошибок. О структуре папок, манифесте и установке читайте в разделе [Создание расширения](/ru/sdk/).

```ts
import { connectHost, HostRequestError } from "@openchamber/sdk";

const host = connectHost();
```

`connectHost` выбрасывает `HOST_UNAVAILABLE`, если нет `window`. Вне OpenChamber он возвращает клиент, в котором каждый вызов отклоняется с `HOST_UNAVAILABLE`. Вызывайте `dispose()`, когда убираете страницу; вызовы, которые ещё выполняются, отклоняются с тем же кодом.

## Что OpenChamber отправляет вам

`onReady` срабатывает с первым снимком и затем каждый раз, когда OpenChamber его обновляет.

Это не одноразовый колбэк монтирования. Смонтируйте интерфейс и зарегистрируйте подписки один раз; более поздние снимки используйте, чтобы обновлять тему и контекст, не заменяя поля ввода и черновики. Пример с защитой от повторного монтирования смотрите в разделе [UI kit](/ru/sdk/ui/). Слушатели полей, например `onConnection`, сразу передают текущее значение и могут получить его снова с обновлённым снимком. Сравнивайте поля, от которых зависят ваши данные, прежде чем запускать новый запрос, и игнорируйте ответы устаревших запросов.

| Поле | Что это |
| --- | --- |
| `theme.mode` | `light` или `dark` |
| `theme.tokens` | цвета приложения (поверхности, текст, состояния взаимодействия, primary, success/warning/error/info), `font`, `mono` и `radius`. Передайте это в `applyHostReady` перед монтированием интерфейса. |
| `locale` | тег языка приложения |
| `directory` | папка текущего проекта или `null` |
| `session` | `{ id, title, busy }` или `null`. Если заголовка нет, используется id сессии. `busy` — текущий статус. `model` и `agent` (агент OpenCode) появляются, когда они есть у сессии. |
| `surface` | `panel` на рейке, `dialog` в окне прикрепления, `page` на весь экран, `status` в панели Work Status, `file` как редактор файлов в Files, `block` в UI-блоке в чате |
| `item` | для чего открыта эта поверхность, или `null`: прикреплённый элемент, по которому нажал пользователь (те же поля, что вы передали в `attach`, включая `data`), сообщение (`kind: "message"`) или сессия (`kind: "session"`) из одного из объявленных вами действий. Смотрите [Действия](/ru/sdk/#действия-команды-и-счётчик). |
| `connection` | `{ connected, account }` для вашей интеграции |
| `settings` | значения полей, которые вы объявили в `integration.settings` |

Токены доступа здесь никогда не появляются — как и в результате `request`.

`onDirectory`, `onSession`, `onSessionLifecycle`, `onConnection`, `onSettings` и `onItem` при поздней подписке сразу отдают последнее значение, а затем продолжают срабатывать при каждом изменении.

`theme.tokens` включает `primaryText`, `successText`, `warningText`, `errorText` и `infoText`. Эти обязательные поля содержат вычисленные хостом цвета текста для нейтрального фона и тонированных элементов UI-набора, а не сплошные заливки. `applyHostReady` применяет их при каждом снимке. CSS-переменные описаны в разделе [UI kit](/ru/sdk/ui/).

## Методы

| Вызов | Что делает |
| --- | --- |
| `toast({ kind, message })` | показать тост в приложении. `kind` — `info`, `success` или `error`. |
| `openUrl(url)` | открыть URL; в десктопном приложении локальный адрес открывается в панели браузера рядом с чатом |
| `openSurface(surfaceId)` | показать этот экран, например `"git"` или вашу собственную панель `"plugin:<panel id>"`. Завершается, когда экран на виду; уже открытый экран остаётся открытым. |
| `writeClipboard(text)` | скопировать текст. От 1 до 32000 символов. |
| `compose({ text, mode? })` | вставить текст в поле чата без отправки. `mode` — `append` (по умолчанию) или `replace`. От 1 до 16000 символов после обрезки пробелов. |
| `attach({ ... })` | поставить чип на поле чата — туда же, куда попадают элементы GitHub и Linear. Только один чип за раз. |
| `startSession({ ... })` | создать сессию с прикреплённым элементом. Возвращает `{ sessionId, sent }`. Требует разрешения `sessions`. |
| `prompt({ text, send? })` | написать в текущую сессию или отправить в ней. Возвращает `{ sent }`. Для отправки нужно разрешение `prompt`. |
| `sessionLink({ ... })` | прикрепить элемент к текущей сессии, не создавая новую |
| `close()` | закрыть окно прикрепления. На рейке ничего не делает. |
| `oauthStart()` | открыть страницу авторизации провайдера или страницу Linear для интеграции с `host: { provider: "linear" }` |
| `oauthDisconnect()` | забыть сохранённый токен или подключение Linear |
| `request({ method, path, query?, body? })` | вызвать `apiOrigin` вашей интеграции с прикреплённым токеном пользователя |
| `serviceRequest({ method, path, query?, body? })` | вызвать локальный сервис вашего расширения (смотрите `GUEST_SERVICES.md`) |
| `serviceStatus()` | `stopped`, `starting`, `ready` или `failed` |
| `readFile(path)` | прочитать текстовый файл. Возвращает `{ content }`. |
| `writeFile(path, content)` | атомарно записать текстовый файл, создавая родительские папки. Возвращает `{ written: true }`. |
| `listDir(path)` | перечислить содержимое папки. Возвращает `{ entries: [{ name, kind }] }`, `kind` — `file`, `directory` или `other`. |
| `stat(path)` | `{ kind, size, mtime }`, `kind` — `file`, `directory`, `other` или `missing`. |
| `generate({ prompt, system?, maxOutputTokens? })` | одноразовый текст от Small Model пользователя. Возвращает `{ text }`. Требует разрешения `model`. |
| `onResolve(handler)` | зарегистрировать обработчик ваших слеш-команд. Он получает `{ command, args }` и возвращает элемент для прикрепления или `null`. |
| `setBadge(count)` | отметить ваш значок на рейке точкой и показать число (от 0 до 999) в его всплывающей подсказке или `null`, чтобы убрать его |
| `openCommit(sha)` | открыть представление Diff на этом коммите текущего проекта. `sha` — от 7 до 64 шестнадцатеричных символов; OpenChamber сам читает коммит. |
| `setHeight(px)` | задать высоту вашей секции Work Status. OpenChamber держит её в пределах от 24 до 320 пикселей; более высокое содержимое прокручивается внутри вашей страницы. В других местах это игнорируется. |
| `onFileOpen(listener)` | редакторы файлов: получить файл для редактирования — `{ path, name, readOnly }` плюс `encoding: "text"` с `content` или `encoding: "binary"` с `bytes`. Также включает сохранение по Cmd/Ctrl+S на вашей странице. |
| `onFileSnapshot(handler)` | редакторы файлов: вернуть `{ content, version }` (или `{ bytes, version }` для бинарного редактора) — весь отредактированный файл. OpenChamber вызывает его для сохранения и перед переключением на просмотр исходного кода или полноэкранный режим. |
| `onFileSaved(listener)` | редакторы файлов: снимок с этой `version` уже на диске. Ответьте через `reportFileChange`. |
| `reportFileChange({ dirty, edited })` | редакторы файлов: сообщить OpenChamber, есть ли несохранённые изменения и изменился ли только что документ |
| `requestFileSave()` | редакторы файлов: сохранить сейчас, как по Cmd/Ctrl+S |
| `reportFileUnsupported()` | редакторы файлов: этот файл нельзя открыть здесь, покажите вместо него исходный код |

## attach, startSession и sessionLink

Все три принимают одни и те же поля элемента:

```ts
await host.attach({
  providerId: "acme-hello",
  id: "TICKET-1",
  title: "Login is broken",
  url: "https://example.com/TICKET-1",
});

await host.attach({
  providerId: "acme-hello",
  id: "!12",
  title: "Fix login",
  url: "https://example.com/merge_requests/12",
  kind: "pull",
  author: "ada",
  branches: { head: "feature", base: "main" },
  text: "Optional notes for the model",
});

await host.startSession({
  providerId: "acme-hello",
  id: "!12",
  title: "Fix login",
  url: "https://example.com/merge_requests/12",
  kind: "pull",
  worktree: true,
  text: "Optional first message",
});
```

`providerId` — это id вашей панели; OpenChamber всё равно перезаписывает его вашим id. `id` — ваш собственный идентификатор элемента. `kind` — `issue` (по умолчанию) или `pull`. `text` — необязательный контекст для модели, от 1 до 16000 символов после обрезки пробелов. `data` — необязательный JSON на ваше усмотрение (статус, комментарии, что угодно), до 16000 символов в сериализованном виде. OpenChamber хранит его вместе с чипом и возвращает без изменений в `ctx.item`, когда пользователь нажимает на чип; в модель он никогда не попадает.

`startSession` принимает `projectId`, не переключая текущий проект. Опустите `worktree` для целевой папки, укажите `true` для созданного worktree, `{ kind: "existing", directory }` для известного worktree или `{ kind: "new", name?, baseBranch? }` для нового с именем. Имя задаёт и ветку, и worktree. `navigation` по умолчанию равно `"preserve"`; `"open"` выбирает новый чат. Модель, агент и вариант для первого сообщения фиксируются в момент начала создания.

Результат включает `sessionId`, `directory`, `sent`, `linked` и необязательный `worktree`. `sent` бывает `sent`, `no-model`, `skipped` или `failed`; `linked: false` означает, что элемент не сохранился в созданной сессии. Если после сбоя начальной настройки или создания сессии остался worktree, возвращается `sessionId: null` и `failure: "bootstrap-failed" | "session-create-failed"`, а также его папка/worktree. Проверьте этот результат, прежде чем повторять попытку. Вызов ждёт до 180 секунд; тайм-аут не означает, что создание откатили.

`sessionLink` прикрепляет элемент к сессии, которая открыта сейчас. Если нет проекта или сессии — ошибка `NO_SESSION`.

Ограничения, которые клиент применяет до отправки:

| Поле | Макс. символов |
| --- | --- |
| `id` | 128 |
| `title` | 200 |
| `url` | 2000 |
| `text` | 16000 |
| `data` (в сериализованном виде) | 16000 |
| `author` | 80 |
| имя каждой ветки | 200 |

## prompt и жизненный цикл сессии

```ts
await host.prompt({ text: "Fix the login" });
await host.prompt({ text: "Fix the login", send: true });

host.onSessionLifecycle((event) => {
  document.body.dataset.phase = event.phase;
});
```

Без `send` `prompt` заменяет текст в поле чата. С `send: true` он отправляет сообщение моделью и агентом, которые выбрал пользователь. Расширение их никогда не выбирает. Нет открытой сессии — `NO_SESSION`. Отправка, пока сессия занята, — `SESSION_BUSY`; писать в поле во время занятости можно. Результат — `{ sent }` с теми же значениями, что и у `startSession`.

`onSessionLifecycle` сообщает, что делает сессия. `phase` равен `started`, пока модель работает, `completed`, когда она переходит в простой, и `failure` при неожиданном статусе. Поздний слушатель сразу получает текущую фазу.

## Проекты, worktree и живые сессии

Эти методы используют существующее разрешение `sessions` и общие хранилища приложения. Они не запускают обход Git на каждый запрос и не раскрывают содержимое переписки.

```ts
const projects = await host.listProjects();
const projectId = projects.projects[0]?.id;
if (projectId) {
  const worktrees = await host.listWorktrees(projectId);
  const sessions = await host.listSessions(projectId);
  const stop = await host.onSessions(projectId, (snapshot) => {
    renderSessions(snapshot.sessions, snapshot.state);
  });
  // Call stop() when this view closes.
}
```

`onProjects(listener)` и `onWorktrees(projectId, listener)` работают так же. Дождитесь регистрации, чтобы поймать ошибки разрешений; результатом будет функция отписки. Каждый сначала отправляет начальный снимок, а затем изменения. `dispose()` освобождает все подписки. Хост допускает не более 32 на фрейм и очищает их при размонтировании, паузе, удалении или переключении сервера.

У снимков есть `state: "loading" | "ready" | "error"`. Состояния загрузки и ошибки могут сохранять данные; только `ready` подтверждает полный успешный результат, в том числе пустой. Снимки сессий включают `coverage` по папкам и известные архивные сессии. Проекты показывают ID, имя и папку; worktree — папку, имя, ветку и доступность. Сессии включают свой проект/папку/worktree, временные метки, ID родителя и ID/данные прикреплённых элементов этого расширения.

`activity` сессии бывает `unknown`, `idle`, `running`, `retrying`, `waiting-permission` или `waiting-question`. `outcome` — это наблюдаемый ход `completed`/`failed` или `null`. Он не восстанавливается из истории и хранится в памяти не более чем для 2 000 наблюдаемых сессий. Простой после ошибки сохраняет результат `failed` до следующего запуска. Ни `idle`, ни `completed` не помечают вашу задачу как выполненную. Используйте `host.openSession(sessionId)` для явного перехода от карточки к её чату.

## Фоновые команды оболочки

С возможностью `shells` следите за командами оболочки, которые выполняются в фоне, — в пределах сессии и её субагентов, зарегистрированного проекта или всех сессий. OpenChamber отвечает из своего локального хранилища, без чтения из сети.

| Вызов | Что делает |
| --- | --- |
| `onRunningShells(scope, listener)` | подписаться на команды оболочки в области: `{ kind: 'session', sessionId }` охватывает сессию и её субагентов, `{ kind: 'project', projectId }` — зарегистрированный проект, а `{ kind: 'global' }` — все сессии. Вы получаете выполняющиеся команды от старых к новым, каждую с флагом `background`, и те, что завершились. Возвращает функцию отписки. |
| `readShellOutput(shellId, { cursor?, tailBytes? })` | одна страница вывода выполняющейся или завершённой команды. Без `cursor` она начинается за `tailBytes` (до 65536) до конца. Возвращает `{ output, cursor, skipped }`. |
| `stopShell(shellId)` | сначала отправить агенту записку об остановке, затем удалить команду. |

Снимок — `{ kind: "shells", scope, shells, ended }`, где `scope` повторяет область подписки. Каждая выполняющаяся команда — `{ id, sessionID, command, startedAt, background }`, не более 200, от старых к новым. `background` равно `true` для задачи, которую ход не ждёт.

`ended` перечисляет команды, которые OpenChamber увидел завершёнными, от ранних к поздним, не более 200; самые новые сохраняются. К каждой добавляются `status`, `endedAt` и `exit`, если команда завершилась с кодом. Статус — `exited`, `timeout`, `killed` сигналом, `stopped` пользователем или `unknown`, если завершение пришлось на переподключение. OpenChamber держит этот список только в памяти. После перезагрузки приложения он пуст, поэтому сохраняйте то, что показывает ваша панель, в хранилище расширения.

OpenCode хранит вывод завершённой команды для последних 25 завершённых команд в каждой папке. Остановленная команда теряет вывод сразу. Чтение оболочки, которую OpenChamber никогда не видел, или вывода, которого у OpenCode больше нет, — `NOT_FOUND`. То же для остановки команды, которая не выполняется. Неодобренная возможность `shells` — `NOT_GRANTED`.

## Постоянные данные расширения

```ts
await host.storage.set("board", { columns: ["Todo", "Review"] });
const board = await host.storage.get("board");
const keys = await host.storage.keys();
await host.storage.delete("board");
```

Дополнительное разрешение не нужно. Хранилище принадлежит этому расширению на подключённом сервере, переживает перезагрузки и удаляется при удалении расширения. `get` возвращает `undefined` для отсутствующего ключа; сохранённый JSON null остаётся null. Ключи содержат от 1 до 128 символов. Каждое сериализованное значение JSON — не более 64 КиБ в UTF-8, а всё пространство имён — не более 2 МиБ или 2 000 ключей. Для данных конкретного проекта добавляйте его ID в ключ. Записи выполняются последовательно и атомарно; при сбое существующие данные сохраняются.

## request

```ts
const user = await host.request({ method: "GET", path: "/api/v2/user" });
```

`path` начинается с `/` и не содержит схемы или хоста; OpenChamber присоединяет его к `apiOrigin` из вашего манифеста и добавляет заголовок `Authorization`. Интеграции с токеном отправляют вставленный токен как есть: в виде `Bearer <token>`, если в манифесте задано `token.scheme: "bearer"`, или в виде `Basic base64(username:token)`, если задано `"basic"`. Интеграции OAuth и Linear всегда отправляют `Bearer`. Результат — `{ status, body }`. Тело приходит текстом; разбирайте JSON сами.

Интеграция с Linear также может выполнить `GET /api/linear/issues/get`, на который OpenChamber отвечает через собственный маршрут Linear.

Если ответа нет в течение 20 секунд — `HOST_TIMEOUT`.

```ts
try {
  await host.request({ method: "GET", path: "/api/v2/user" });
} catch (error) {
  if (error instanceof HostRequestError && error.code === "DISCONNECTED") {
    await host.oauthStart();
  }
}
```

## serviceRequest

Когда манифест объявляет `contributes.service`, OpenChamber запускает этот процесс, а ваша страница общается с ним через такой же вызов. Страница никогда не открывает сокет сама.

```ts
const status = await host.serviceStatus();
const result = await host.serviceRequest({ method: "GET", path: "/containers" });
```

`path` подчиняется тем же правилам, что и в `request`. Объявление сервиса добавляет `service` к разрешениям, которые пользователь подтверждает при установке; до этого каждый `serviceRequest` — `NO_SERVICE`. Полный контракт: файл пакета `GUEST_SERVICES.md`.

## События сессии

Ваша страница знает о сессии только пока она открыта. Ваш сервис может знать больше: объявите `contributes.sessionEvents` рядом с `contributes.service`, и OpenChamber будет отправлять сервису перечисленные события из всех проектов, открыто окно или нет.

```json
"service": { "entry": "service/main.js", "runtime": "host" },
"sessionEvents": { "events": ["turn-finished", "question-asked"], "content": true }
```

События — `turn-started`, `session-created`, `session-archived`, `session-deleted`, `turn-finished` (агент закончил и ничего не ждёт: ни работающего субагента, ни открытого разрешения или вопроса, ни шага Session Goals), `turn-failed`, `permission-asked` и `question-asked`. Ход, который пользователь остановил, ничего не отправляет. Одобрение расширения и есть подписка; диалог перечисляет события под строкой сервиса. Без `content` сервис получает только идентификаторы: сессию, папку её проекта, элементы, которые пользователь к ней прикрепил. С `"content": true` манифест также просит разрешение, которое пользователь видит отдельной строкой, **Читать, что агент говорит в фоне**, и каждое событие несёт финальный ответ агента, поля вопроса или подробности разрешения.

Каждое событие приходит одним `POST /session-events` с bearer-токеном сервиса. Прочитайте его через `readSessionEventRequest` и ответьте `{ "ok": true }`:

```ts
import { SESSION_EVENTS_PATH, readSessionEventRequest } from "@openchamber/sdk";

// inside your service's request handler, after the bearer check
if (url.pathname === SESSION_EVENTS_PATH) {
  const request = readSessionEventRequest(body);
  if (!request) return json(res, 400, { ok: false, error: "not a session event" });
  const { event, content } = request;
  if (event.type === "turn-finished" && event.project.directory === myProject) {
    await postComment(event.linked, content?.type === "turn-finished" ? content.reply : "");
  }
  return json(res, 200, { ok: true });
}
```

События приходят из всех проектов; сравнивайте `event.project.directory` со своими настройками и отвечайте `{ "ok": true }` на остальные. Доставка — не более одного раза и по порядку, по одному запросу за раз; неудачный ответ отбрасывает ваши события на 30 секунд, а после простоя OpenChamber или вашего сервиса ничего не повторяется. Панель сервису для этого не нужна. Пример `session-events-log` записывает каждое событие в файл.

## Вызов OpenChamber из вашего сервиса

Сервис может действовать без открытого окна. `createServiceHost` — так сервис возвращается в OpenChamber:

```ts
import { createServiceHost } from '@openchamber/sdk';

const host = createServiceHost({ env: process.env });

const { sessionId } = await host.sessions.start({ prompt: 'Summarize the failed deploy', directory });
await host.sessions.send(sessionId, 'Now write the incident note');
await host.setInstructions(directory, 'Deploys run through the release branch.');
await host.emit('deploy-finished', { id: 42 });
```

`sessions.start`, `sessions.send`, `sessions.retry`, `sessions.status` и `sessions.stop` требуют `contributes.sessionControl`, который пользователь одобряет отдельной строкой. `sessions.lastReply` требует `sessionControl: { content: true }`. Сообщение из `sessions.send` закрывает форму или страницу, которую агент ждёт в этой сессии, как и сообщение, набранное в чате.

Чтобы передавать запросы агента куда-то ещё, например в чат-приложение, добавьте `answers: true`. Пользователь одобряет это ещё одной строкой, и тогда сервис может отвечать за него в любой сессии: `sessions.answerPermission(sessionId, requestId, { decision: 'allow' })` (или `'deny'` с `message`, который прочитает агент) для события `permission-asked` и `sessions.answerForm(sessionId, formId, values)` для события `question-asked`, у которого `event.question.kind` равно `form`. Содержимое события перечисляет поля формы с их `key` и вариантами. `null` вместо значений закрывает форму. Разрешение действует на один запрос.

`setInstructions` требует `contributes.instructions` и добавляет текст к тому, что читают агенты, в одной папке или, с `null`, везде.

`emit` доходит до ваших открытых фреймов через `host.onServiceEvent`, так что панель перестаёт опрашивать сервер. Ничего не повторяется, поэтому фрейм, который откроется позже, сначала читает текущее состояние. `readSettings` отдаёт сервису настройки интеграции, включая поля `secret`, а `needsConfiguration` показывает сообщение на карточке расширения.

## Работа без участия человека

Сервис запускается по первому запросу, а сервис роли останавливается, когда простаивает. `service.keepRunning: true` запускает его вместе с OpenChamber и возвращает, если он остановился. `service.schedule` будит его по расписанию:

```json
"service": {
  "entry": "service/main.js",
  "runtime": "host",
  "keepRunning": true,
  "schedule": [{ "id": "nightly", "cron": "0 3 * * *", "timezone": "Europe/Kyiv" }]
}
```

Запуск — это один `POST /schedule`. Прочитайте его через `readServiceScheduleRequest` и ответьте 200. Запуск, который пропустили, пока OpenChamber был выключен, потерян. Сервису, которому нужны внешние события, придётся держать своё подключение или опрашивать сервер.

## Строки в меню @

`contributes.mentions: { label }` добавляет раздел в меню `@` поля ввода. Ваш сервис отвечает на `POST /mentions/search` объектом `{ items: [{ id, title, subtitle?, url? }] }` в течение 2 секунд и на `POST /mentions/resolve` объектом `{ text }` для строки, которую выбрал пользователь. Текст уходит агенту вместе с сообщением, а пользователь видит плашку. Медленный сервис не добавляет строк и не задерживает список файлов; строка, которую не удалось прочитать, не оставляет плашки и сообщает об этом.

## Блоки в чате

`contributes.blocks` добавляет компоненты, которые агенты могут писать в UI-блоке. Каждый из них рисует ваша страница — в той же песочнице и с теми же разрешениями, что и ваша панель.

```json
"blocks": [{ "name": "JiraIssue", "description": "A Jira ticket", "args": ["key"], "entry": "blocks/issue.html" }]
```

Агент пишет `JiraIssue("OPE-1")`, а ваша страница читает вызов:

```ts
host.onBlock(({ args }) => draw(args.key));
```

Вызывайте `host.setHeight(px)` из `ResizeObserver` на вашем корневом элементе. Фрейм заполняет свой блок без отступов, так что добавьте свои. До 4 компонентов на расширение, потому что каждая сигнатура — это текст, который читает каждая сессия.

Блок может ответить агенту, как это делает кнопка в блоке. Вызовите `host.answerBlock(text)` по клику: агент получит текст и начнёт свой следующий ход. Один ответ на блок; `block.answered` хранит его после перезагрузки — тогда рисуйте блок как уже отвеченный.

```ts
host.onBlock(({ args, answered }) => draw(args.key, answered));
button.onclick = () => host.answerBlock('Close this ticket');
```

Укажите `"answers": true` у компонента, который так делает. Агенты получают указание спрашивать через него вместо встроенного варианта, когда подходит его описание, а страница, которая ждёт ответа, не показывает кнопку «Отправить». Под таким блоком OpenChamber предлагает то же поле для заметки, что и в своих формах: агент читает заметку вместе с вашим ответом, и одна заметка тоже считается ответом.

Аргументы пишет модель, поэтому текст с веб-страницы или из тикета может ими управлять. Считайте их недоверенными и не делайте ничего с побочными эффектами, пока пользователь не нажмёт.

## Каналы уведомлений

Сервис может доставлять уведомления пользователя рядом с десктопом и телефоном: объявите `provides: ["notifications"]` и опишите канал в `contributes.notifications`.

```json
"service": { "entry": "service/main.js", "runtime": "host", "provides": ["notifications"] },
"notifications": {
  "label": "Slack",
  "instances": { "kind": "fixed", "origin": "https://slack.com" },
  "token": { "header": "authorization", "scheme": "bearer", "scopes": ["chat:write"] }
}
```

По этому описанию OpenChamber рисует карточку аккаунта для канала в разделе Настройки → Интеграции и хранит аккаунт: пользователь подключает его там, токен остаётся в OpenChamber, и ваш сервис его никогда не видит. После подключения аккаунта каждое уведомление, которое OpenChamber отправил бы на телефон, идёт и в ваш сервис — после собственных переключателей уведомлений пользователя и только пока не видно ни одного окна, если пользователь не выбрал уведомлять всегда. Пауза расширения прекращает доставку.

OpenChamber пересылает в `POST /notifications` три вызова: `auth.probe` (можно ли доставлять на этот сервер), `auth.verify` (кому принадлежит этот токен) и `notify` (одно уведомление). Читайте каждый через `readNotificationsProviderRequest` и обращайтесь к серверу канала только через помощник исходящих запросов: он отправляет ваш запрос в OpenChamber с идентификатором вызова, а OpenChamber добавляет токен и держит запрос на сервере аккаунта.

```ts
import { NOTIFICATIONS_PROVIDER_PATH, createNotificationsOutbound, readNotificationsProviderRequest } from "@openchamber/sdk";

const outbound = createNotificationsOutbound({ env: process.env });

// inside your service's request handler, after the bearer check
if (url.pathname === NOTIFICATIONS_PROVIDER_PATH) {
  const request = readNotificationsProviderRequest(body);
  if (!request) return json(res, 400, { ok: false, error: { message: "not a notifications call" } });
  if (request.method === "notify") {
    const { notification } = request.input as { notification: GuestNotification };
    const answer = await outbound.request(request.session.handle, {
      method: "POST", path: "/api/chat.postMessage",
      headers: { "content-type": "application/json" },
      body: JSON.stringify({ channel: "#agents", text: `${notification.title}: ${notification.body}` }),
    });
    return json(res, 200, answer.status === 200 ? { ok: true, data: { delivered: true } } : { ok: false, error: { message: `Slack answered ${answer.status}`, status: answer.status } });
  }
  // auth.probe → { ok: true, data: { supported: true } }; auth.verify → { ok: true, data: { account: { id, login } } }
}
```

В какую комнату или канал попадает проект — решает ваше расширение: уведомление несёт `directory` и `sessionName`. В корпоративном режиме оно несёт только общий заголовок, как и на телефоне. Пример `notification-webhook` — это готовый канал с получателем, на котором можно его проверить.

## Трекеры

Сервис может быть трекером рабочих задач рядом с Linear: объявите `provides: ["tracker"]` и опишите трекер в `contributes.tracker`. Тогда OpenChamber показывает его рядом с Linear везде, где появляются трекеры, — только по манифесту, ещё до первого запуска сервиса.

```json
"service": { "entry": "service/main.js", "runtime": "host", "provides": ["tracker"] },
"tracker": {
  "wire": 1,
  "label": "YouTrack",
  "instances": { "kind": "user", "label": "Server address", "placeholder": "https://youtrack.example.com" },
  "auth": { "token": { "header": "authorization", "scheme": "bearer", "createPath": "/users/me?tab=account-security" } },
  "capabilities": { "stateUpdate": true, "labels": true, "priority": true, "projectMapping": true, "sessionComments": true },
  "stateFilters": ["open", "all", "todo", "in-progress", "done"],
  "identifier": "key-number",
  "urls": { "item": ["/issue/{id}", "/{segments+}/issue/{id}"] }
}
```

Пользователь подключает аккаунты на карточке трекера в разделе «Аккаунты расширений»: токен или вход через браузер, если вы объявили `auth.oauth` (OpenChamber проводит вход с client id, который вводит пользователь, и хранит токены). Ваш сервис никогда не видит учётные данные. `urls.item` — шаблоны адреса элемента, где `{id}` — идентификатор (а также `?name={id}`, когда он идёт в запросе); OpenChamber компилирует их, чтобы вставленные ссылки становились привязанными элементами. `identifier` говорит, как выглядит ключ: `key-number` (`PROJ-42`), `number` или `short-code`.

OpenChamber пересылает в `POST /tracker` девять вызовов: `auth.probe` и `auth.verify`, чтение `items.list`, `items.get`, `items.liveSummaries`, `states.list` и `containers.list` и запись `items.updateState` и `comments.create`. Читайте каждый через `readTrackerProviderRequest`, отвечайте в нейтральных формах элементов и обращайтесь к серверу трекера только через помощник исходящих запросов: он отправляет ваш запрос в OpenChamber с идентификатором вызова, а OpenChamber добавляет учётные данные и держит запрос на сервере аккаунта. Идентификатор вызова для чтения допускает только `GET`.

```ts
import { TRACKER_PROVIDER_PATH, createTrackerOutbound, readTrackerProviderRequest } from "@openchamber/sdk";

const outbound = createTrackerOutbound({ env: process.env });

// inside your service's request handler, after the bearer check
if (url.pathname === TRACKER_PROVIDER_PATH) {
  const request = readTrackerProviderRequest(body);
  if (!request) return json(res, 400, { ok: false, error: { message: "not a tracker call" } });
  if (request.method === "items.get") {
    const answer = await outbound.request(request.session.handle, { method: "GET", path: `/api/issues/${encodeURIComponent(String(request.input.id))}` });
    if (answer.status === 404) return json(res, 200, { ok: true, data: { item: null } });
    if (answer.status !== 200) return json(res, 200, { ok: false, error: { message: `YouTrack answered ${answer.status}`, status: answer.status } });
    return json(res, 200, { ok: true, data: { item: toTrackerItem(JSON.parse(answer.body)) } });
  }
}
```

Когда пользователь включает комментарии сессий, OpenChamber вызывает `comments.create` с «сессия началась», «завершилась» или «упала» и ссылкой на сессию, по одному разу; больше комментарий ничего не несёт. Пример `tracker-provider` — это готовый трекер с поддельным сервером, на котором можно его проверить.

## Провайдеры использования

Сервис может показывать использование рядом со встроенными провайдерами: объявите `provides: ["quota"]` и перечислите в `contributes.quota.providers` провайдеров OpenCode, чьи учётные данные ему нужны. OpenChamber называет провайдера `ext-<panel.id>`, рисует его карточку с именем и значком расширения и спрашивает его так же, как встроенного.

```json
"service": { "entry": "service/main.js", "runtime": "host", "provides": ["quota"] },
"quota": { "providers": ["openrouter"] }
```

Диалог одобрения перечисляет этих провайдеров, а версия, которая меняет список, спрашивает снова. При каждом обновлении OpenChamber отправляет один вызов `usage.read` в `POST /quota`, где `input.credentials` содержит учётные данные, которые OpenCode хранит для каждого перечисленного провайдера, если они у него есть (API-ключ или токены входа через браузер), и ничего больше из хранилища. Провайдер из списка, для которого у OpenCode нет учётных данных, показывается как ненастроенный, и сервис не вызывается; пустой список допустим — для провайдера, чей ключ живёт в собственных настройках расширения.

Прочитайте тело через `readQuotaProviderRequest` и ответьте `{ ok: true, data }` результатом, который вычисляет встроенный провайдер: `ok`, `configured`, `error`, `planLabel` и `usage.windows` с ключами по имени окна, где у каждого есть `usedPercent`, `windowSeconds`, `resetAt` (миллисекунды эпохи) и необязательные `valueLabel` или `value`, плюс `usage.models` для окон по моделям. OpenChamber сам выводит оставшуюся долю, обратный отсчёт до сброса и форматированные строки, чтобы карточка совпадала со встроенной.

```ts
import { QUOTA_PROVIDER_PATH, readQuotaProviderRequest } from "@openchamber/sdk";

// inside your service's request handler, after the bearer check
if (url.pathname === QUOTA_PROVIDER_PATH) {
  const request = readQuotaProviderRequest(body);
  if (!request) return json(res, 400, { ok: false, error: { message: "not a usage call" } });
  const credential = request.input.credentials.openrouter;
  const bearer = credential.type === "api" ? credential.key : credential.access;
  const answer = await fetch("https://openrouter.ai/api/v1/key", { headers: { authorization: `Bearer ${bearer}` } });
  if (answer.status === 401) return json(res, 200, { ok: true, data: { ok: false, configured: true, error: "OpenRouter refused the key.", usage: null } });
  return json(res, 200, { ok: true, data: toUsage(await answer.json()) });
}
```

Сервис отвечает в течение 20 секунд и останавливается после десяти минут без вызова; страница «Использование» обновляется каждые три минуты, пока открыта. Пример `quota-provider` — это готовый провайдер с поддельным API использования, на котором можно его проверить.

## Файлы

Относительный путь указывает внутрь открытого проекта и требует разрешения `files`. Путь, начинающийся с `/` или `~/`, должен соответствовать объявленному шаблону `contributes.filesystem` и требует разрешения `filesystem`. Правила смотрите в разделе [Создание расширения](/ru/sdk/#файлы).

```ts
const { content } = await host.readFile("package.json");
await host.writeFile("notes/today.md", "# Today\n");
const { entries } = await host.listDir("src");
const info = await host.stat("~/.config/opencode/opencode.json");
```

Ограничения: путь до 1024 символов, содержимое до 2,000,000 символов, список до 2000 записей. Превышение лимита содержимого — `FILE_TOO_LARGE`.

## generate

```ts
const { text } = await host.generate({ prompt: notes, system: "Summarize in one sentence." });
```

`prompt` — от 1 до 64,000 символов после обрезки, `system` — до 8,000, `maxOutputTokens` — от 1 до 4,000. Ничего не попадает в сессию и история не сохраняется; расширение никогда не выбирает модель. Вызов ждёт до 960 секунд. Если подходящей Small Model нет — `NO_MODEL`; ошибка модели — `MODEL_FAILED`. Смотрите [Генерация текста](/ru/sdk/#генерация-текста).

Пользователь может закрыть вашу панель или переключиться на другой проект, пока ответ не пришёл. Генерация всё равно завершится, и приложение сохранит ответ для вашей следующей панели на той же поверхности и в том же проекте, в том же окне. Зарегистрируйте `onLateGenerateResult`, чтобы получить его там:

```ts
host.onLateGenerateResult((late) => {
  if (late.ok) showSummary(late.request.prompt, late.result.text);
  else showError(late.error);
});
```

`late.request` — это то, что отправила закрытая панель, так что вы можете понять, на какой запрос пришёл ответ. Каждый ответ приходит один раз. Приложение хранит ответы час, не более 8 на расширение, и отбрасывает их, когда расширение отключают или удаляют. Перезагрузка всего приложения или другое окно начинают с пустого места. Приложения, которые не хранят поздние ответы, не выставляют `ready.features.lateGenerateResults` и никогда не вызывают слушатель.

## Коды ошибок

Неудачные вызовы выбрасывают `HostRequestError`. `code` — один из перечисленных; `message` поясняет подробнее.

| Код | Когда |
| --- | --- |
| `HOST_UNAVAILABLE` | нет `window`, страница не внутри OpenChamber или уже выполнен `dispose()` |
| `HOST_TIMEOUT` | нет ответа 20 секунд |
| `HOST_REJECTED` | OpenChamber отказал или ответил кодом, которого этот SDK не знает |
| `DISCONNECTED` | для вашей интеграции нет токена или подключения Linear |
| `BAD_PATH` | `path` был некорректным или пытался выйти за пределы разрешённого источника |
| `NO_INTEGRATION` | в манифесте нет `integration` |
| `NO_SESSION` | `prompt` или `sessionLink` без открытой сессии |
| `SESSION_BUSY` | `prompt({ send: true })`, пока сессия была занята |
| `DISABLED` | пользователь приостановил расширение в разделе «Настройки → Расширения» |
| `NO_SERVICE` | сервис не объявлен, не подтверждён или не запущен |
| `NOT_GRANTED` | пользователь не подтвердил разрешение, которое нужно этому вызову |
| `SERVICE_FAILED` | сервис упал или так и не стал готов |
| `NO_DIRECTORY` | относительный путь к файлу использован без открытого проекта, `openCommit` без открытого проекта или `openSurface`, когда ещё не открыт ни один чат или проект |
| `NOT_FOUND` | `readFile` для несуществующего файла или `openCommit` для коммита, которого нет в проекте |
| `FILE_TOO_LARGE` | содержимое файла превышает лимит — при чтении или записи |
| `DENIED` | операционная система отказала в файловой операции |
| `NO_MODEL` | `generate` без доступной Small Model |
| `MODEL_FAILED` | Small Model вернула ошибку |
| `UNSUPPORTED` | этот OpenChamber не умеет выполнить вызов, например `openCommit` там, где нет представления Diff, или `openSurface` для экрана, который здесь не может открыться |
