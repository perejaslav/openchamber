# Удалённые экземпляры

Десктопное приложение может подключаться по SSH к OpenChamber, работающему на другой машине, — к рабочему серверу, облачной машине, домашней лаборатории, — и показывать его UI на вашем экране, будто он локальный. Настраивается это в **Settings → Remote Instances**.

> Удалённые экземпляры — функция **только для десктопа**. В вебе или в VS Code подключайтесь к удалённому серверу через переменные окружения из [Сервера OpenCode](/opencode-server/).

## Добавьте удалённый экземпляр

1. Откройте **Settings → Remote Instances** и добавьте экземпляр.
2. Укажите SSH-команду, которой вы обычно подключаетесь к машине, и псевдоним.
3. Выберите, как OpenChamber работает там:
   - **managed** — OpenChamber устанавливает и запускает себя на удалённой машине
   - **external** — подключение к уже запущенному экземпляру
4. Подключитесь.

OpenChamber проходит шаги — проверку соединения, настройку удалённой машины, запуск сервера и перенаправление порта — и на каждом этапе показывает, где он находится. Когда он достигает **ready**, удалённый UI загружается локально.

## Учётные данные

Вы решаете, сохранять ли пароли SSH и UI или вводить их каждый раз. Если соединение обрывается, OpenChamber сообщает, какой шаг не удался, чтобы вы могли его исправить, — см. [Удалённый доступ](/troubleshooting/remote-access/).

## Ссылки подключения

Если на удалённой машине уже работает OpenChamber, самый простой способ подключить десктопное приложение — ссылка для сопряжения. В UI удалённого сервера откройте **Settings → Remote Instances → Connect to this server → Add a device**, создайте ссылку и импортируйте её на десктопе в **Settings → Remote Instances → Other OpenChamber servers → Import Link**. Полный сценарий — в [Подключении устройства](/connect-devices/).

Ссылка, созданная с **Anywhere**, несёт и прямой адрес, и маршрут через [Private Relay](/private-relay/): десктоп подключается напрямую, когда может добраться до сервера (та же сеть), и переключается на релей с шифрованием от конца до конца, когда вы не дома. Статус рядом с каждым сохранённым сервером показывает, какой маршрут используется.

Ссылку можно создать и из терминала на удалённой машине:

```bash
openchamber connect-url --port 3000 --server http://your-host:3000 --qr
```

`connect-url` сначала запускает сервер, если на этом порту ничего не работает. Добавьте `--api-only` для headless-сервера, `--lan` для привязки к локальной сети при запуске, `--ui-password` для защиты браузерного доступа и `--name` для метки сохранённого подключения. Добавьте `--relay` для ссылки, которая работает и вне локальной сети: устройство предпочитает прямое подключение, когда оно доступно, и переключается на [Private Relay](/private-relay/) — экземпляр сам поднимает релей.

Созданная ссылка содержит одноразовый секрет сопряжения. После импорта устройство хранит собственный клиентский токен — отдельный от пароля браузерного UI, — который переживает перезапуски сервера, пока вы не отзовёте его на сервере, выдавшем ссылку.
